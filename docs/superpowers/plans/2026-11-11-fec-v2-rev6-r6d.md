# FEC v2 rev 6, step R6-d: blocks, repairs at close, the H.264 content/transport split, protected retransmits — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. One fresh agent per task; the orchestrator checks each task and runs the gates (including the browserless suites over 3+ seeds and the Docker e2e); one Opus review at the end. Steps use `- [ ]`.

**Goal:** with a knob on, the server groups bundles into Reed-Solomon blocks (SOURCE frames), closes them on k_max, time T, Empty or an MTU shrink, and sends REPAIR frames at close inside the admission budget. It serves REPAIR_REQUEST, handles RECOVERED and DECLINED, refuses to retransmit protected content, releases it to ARQ (tiles) or to the acked-reference manager (H.264) when a block fails, and keeps a deadline release as the backstop. The knob is a fixed `(k_max, T, r)`. **Default off**: the daemon is byte-identical to R6-c unless the knob is set. Adaptation is R6-e.

**Single PR:** a step of the rev 6 PR (branch `fec/v2-rev6`, worktree `gf-fec-r6a`; tip = R6-c done).

**Code facts** (read from the tip of `fec/v2-rev6`, 2026-11-11; `T` = `ghostframe-lib/src/transport`, `IB` = `T/io_bridge`, `RE` = `T/reliable_emitter`):

- **Protocol** (`ghostframe-protocol/src/fec/`, done in R6-a):
  - `frame.rs`: `SourceFrame{last, bundle_seq, block_id u16, idx, records}` with `encode()` and `coded_symbol()` (`len u16 | bundle_seq | records`, unpadded); `RepairFrame{bundle_seq, block_id, k, r, repair_idx, payload}`; `PlainFrame`; `source_from_symbol`, `records`, `push_record`. Constants `FEC_SOURCE_HEADER_LEN` 9, `FEC_REPAIR_HEADER_LEN` 11, `FEC_PLAIN_HEADER_LEN` 5, `FEC_SYMBOL_OVERHEAD` 6, `FEC_RECORDS_HEADROOM` 17.
  - `parse` rejects a REPAIR with `r == 0`, `k + r > 256` or `k + repair_idx > 255`.
  - `codec.rs`: `encode_repairs(sources: &[&[u8]], rows: &[u8])` pads internally and returns one payload per row, each as long as the longest source; `recover(sources, repairs)`. `coef.rs`: `coef(i, j)` is k-independent; `max_row_for(k)` = `255 - k`. **There is no incremental `update` in the protocol crate**, so R6-d encodes at close (one call, 158 us at k=200 natively, design §3.1).
  - `feedback.rs`: `RepairAsk{block_id u16, have, missing, first_new_idx}`, `RepairRequest{entries}` (at most 16). `repair_status.rs`: `StatusRecord::{Recovered(Vec<u32>), ContentRejected, Declined{block_id, reason, k, missing: Vec<u8> bitmap}}`; `DeclineReason::{Pruned, Evicted, InvalidSymbol, LengthBound, HeaderMismatch}`.
- **Client** (`ghostframe-client-core/src/fec_rx/blocks.rs`, done in R6-b):
  - `BlockStore` learns k from the LAST flag (`k = idx + 1`; `idx == 255` with LAST is a `HeaderMismatch`) or from any REPAIR. It rebuilds as soon as `held >= k`.
  - Each block's window is `close_at = first arrival + FEC_RX_DEFAULT_T_ADV_US (33 ms) + FEC_RX_ALLOWANCE_US (10 ms)`. Nothing advertises `T_adv` yet. At the window it sends one `Request{have, missing, first_new_idx = highest repair idx seen + 1}`, waits one more window, then `Decline` (reason `Pruned` by default, `missing` = bitmap of absent idx).
  - It prunes a block `FEC_RX_BLOCK_WINDOW` (1024) ids behind the newest, and holds at most 64 open blocks and 4 MiB.
  - A rebuilt source goes out as RECOVERED on the status stream and is never an ACK arrival. A REPAIR bundle's own `bundle_seq` is an arrival, so repair symbols are ACKed.
- **Server today** (R6-c):
  - `T/fec_tx/packer.rs`: `Packer{next_seq, body, records}`; `push(rec, RecordMeta, max_dg)`, `flush()`, `lone()`, `alloc_seq()`, `record_limit(max_dg)` (already reserves `FEC_RECORDS_HEADROOM`), `lone_bundle_len(rec_len)` (PLAIN header only). Every bundle is a PLAIN frame. `RecordMeta{wire_seq, content, emit_us, class: WireClass, is_pad, is_probe, len}`; a pad or a probe-tagged record is alone in its bundle.
  - `IB/bundle_tx.rs`: `send_counted_framed` (:212) pushes a record, `queue_bundles` (:311) ledgers each sealed bundle (`record_bundle` :319, one `Transmission` keyed by `bundle_seq`; empty `records` = a lone control frame, which `record_ack_bwe_samples` already samples like any other), `flush_bundles` (:342), `drive_pending_bundles` (:351), `note_bundle_enqueued` (:446, bills each record as its class and the rest of the frame as `Control`, `admission.charge(control_wire)` ungated).
  - `IB/pacing.rs`: `Stop` (:123), `admission_backlog` (:246), `pump_admission` (:266). Its tail calls `flush_bundles()` and has `stop` in scope. `IB/emit.rs`: `drain_reliable_emitter` (:28) admits each record with `admit_one(.., AdmitClass::Critical|Retransmit|.., wire, depth, d_target)`.
  - The loop turn (`io_bridge.rs` ~:2585) runs `expire_transmissions` then `poll_pto` then `refill_after_drain`. `next_wake_deadline` is at `io_bridge.rs:2153`.
  - `IB/repair_status.rs`: `on_recovered` releases content (`release_h264_content`, `apply_ack_coverage`, no RTT/BWE effect), `handle_status_record` counts DECLINED only (`declined_rx`), `dispatch_repair_request_datagram` counts only (`repair_requests_rx`). `FecInboundStats` holds the counters.
  - `T/loss_path.rs`: `detect` (calls `request_retransmit(content, record_ws, RetxCause::Loss)` per record of each lost bundle, then `take_due_deferred` as `Probe`) and `probe` (the PTO). Callers: `IB/bwe_glue.rs:504` (`expire_transmissions`) and `:553` (`poll_pto`), each followed by `note_h264_verdicts`.
  - `RE/emitter.rs`: `RetxCause` (:283) is `Loss | Probe` only. `classify_retx` (:1363) and `request_retransmit` (:1479). `RetxRequest` (:330) is matched exhaustively in `loss_path.rs`.
  - `IB/h264_tx.rs`: `release_h264_content` (:548), `note_h264_verdict_in` (:622: counts `tx_judged_lost`, then, for an unacked P fragment, `note_raised_lost` and `h264_refs_verdict`), `note_h264_verdicts` (:773). `IB/h264_refs.rs:948` `h264_refs_verdict` also purges the frame's queued fragments and drops it from the emitter cache, so a spurious call destroys the fragments still owed. Manager: `frame_suspect`, `frag_acked`, `frame_content_rejected`.
  - `T/transmission_ledger.rs`: `Transmission{emit_us, wire_bytes, records, depart_us, dep_idx}` is built with a struct literal at 33 sites. **Adding a field to it is a 33-site edit; this plan does not.**
- **Sizes.** A SOURCE frame is `9 + R`, its coded symbol `6 + R`, a REPAIR `11 + 6 + R_max`; the packer's block-mode cap is `body <= max_dg - FEC_RECORDS_HEADROOM`.

## Decisions fixed by this plan

1. **Knob.** `GHOSTFRAME_FEC_BLOCKS`, parsed in `config.rs` only (the env-read guard) into `TransportConfig::fec_blocks: Option<FecBlockParams>`.
   - Format `k_max,t_ms,r`, for example `64,5,2`. Unset, `off` or `0` is off. Off means every bundle is PLAIN, exactly as R6-c.
   - Valid: `r` in 1..=32, `k_max` in 1..=`255 - r`, `t_ms` in 1..=20. An invalid value warns once and means off, as the other knobs do.
   - `t_ms <= 20`. The client's recovery window is a fixed 33 + 10 = 43 ms from the block's first arrival until a `T_adv` advertisement exists (R6-e), and the sender's `D_target` is about 10 ms of queue. A block spanning T plus a 10 ms queue plus jitter must end well inside 43 ms, or the client requests repairs for symbols still in flight. 20 + 10 + jitter fits; 33 does not.
   - `FecBlockParams` is `Copy` and `pub` in `config.rs`, so `RunOptions` (which is `Copy`) can carry `fec_blocks: Option<FecBlockParams>`.
   - **Default stays off in R6-d** (owner item 1).
2. **Which records are protected.** Every first send is a source in a block while the knob is on: tile passes (all tiers), H.264 fragments, probe-tagged records. **Retransmissions of any kind (WireClass `NackRepair`, `LossRetransmit`) and pads and control datagrams go out in PLAIN frames (r = 0).**
   - This is rev 5's "protection is per transmission": a retransmit has no block, so a verdict on it retransmits it again and ARQ ends with delivery. A retransmit in a block would have its verdict refused and could strand.
   - Implementation: `RecordMeta` gains `protect: bool`. A bundle holds records of one kind: a change of kind seals the open bundle.
   - A probe-tagged record stays alone in its bundle but is a source. `Packer::lone_bundle_len` must then use the SOURCE header (9, not 5), or the probe cluster's byte count drifts 4 bytes per packet.
   - Pads stay PLAIN until R6-e turns padding into repair symbols.
3. **Block ids.** u16 counter, wrapping, allocated by the packer.
   - The server tracks at most `FEC_TX_MAX_BLOCKS = 1024` blocks (the client's own window) and `FEC_TX_MAX_CACHED_BYTES = 16 MiB` of source symbols. Past either, the oldest block is evicted as `HandedOff` (deadline-release semantics), counted `block_evicted`. This also makes an id collision after 65 536 blocks impossible. 60 s of `T_def` at 2 000 blocks/s would otherwise exceed the id space.
4. **Where the block state lives.** A new pure, sans-IO `T/fec_tx/block_table.rs`, **not** a field on `Transmission`.
   - `by_bundle: HashMap<bundle_seq, (block_id, Source{idx} | Repair{row})>` plus per-block state. The ledger, its 33 constructors and the ACK consumers are unchanged.
   - **`by_bundle` entries outlive the block's closing.** They stay until the ledger resolves the bundle or a tombstone ring (the size of `RecentBundles`, 4096) evicts them, each marked `handled` once its content outcome was taken. A late verdict on a closed block's source therefore finds its entry and cannot call `h264_refs_verdict` a second time.
   - Each block keeps its coded symbols (for encoding on demand) and, per source, its `(wire_seq, Content)` records (so a hand-off never depends on the ledger still holding the bundle).
5. **Block phases** (rev 5 §4.9.5, with the names kept): `Sending` (sources still going out, T armed) → `Repair` (closed; waiting) → `Deferred` (the server's ACK count says held(B) >= k; the client's RECOVERED or DECLINED is on its way) → `Closed(Accounted | Declined | HandedOff | TimedOut)`. Closed is terminal; late triggers are counted `block_closed_late_trigger`.
   - held(B) = distinct ACKed `bundle_seq`s among the block's sources and repairs. All sources accounted (ACKed or RECOVERED) closes it `Accounted` and frees its symbols.
   - **Deadline release (tiles):** at `deadline(B)` in `Repair`, every unaccounted source's content goes to ARQ as a PLAIN retransmit (`RetxCause::Handoff`, a new variant that is not loss-like, so it bypasses the 3-attempt cap), and the block closes `HandedOff`. In `Deferred` the deadline does not act; `T_def` (60 s, rev 5 §4.9.5) is an alarm that hands off and warns, and a test asserts it stays 0.
   - **Deadline release (H.264):** in `Repair`, the manager is told each unaccounted fragment is lost (decision 8) at the H.264 deadline. **In `Deferred` there is no loss verdict at the deadline**: the block waits for RECOVERED or DECLINED behind a short alarm of `2 srtt + 100 ms` after entering `Deferred` (`deferral_alarm_h264`, counted, warn-rate-limited). When it fires the manager is told the unaccounted fragments are lost and the block closes `TimedOut`. A frame whose RECOVERED is a round trip late is still repaired by the FRAME_ACK override (`suspect_overridden`), but a rebuilt frame must never reach the manager as lost at a high RTT.
   - `deadline(B)`, all as named `pub(crate)` constants plus live `srtt` and `max_ack_delay`, with a comment tying the window to `FEC_RX_DEFAULT_T_ADV_US + FEC_RX_ALLOWANCE_US` in client-core:
     - **tiles:** `last symbol sent + 2 x 43 ms + srtt + max_ack_delay`. The client's first window closes at 43 ms, its request is served one RTT later, and the second window runs another 43 ms before it declines; a deadline inside that round hands off content the request would have repaired.
     - **H.264:** `last symbol sent + 66 ms + srtt + max_ack_delay + RAF_ALLOWANCE (17 ms: the web client batches datagrams once per animation frame, rev 6 §2.2)`.
     - A block with both kinds takes the H.264 deadline for its H.264 sources and the tile one for the rest.
   - **PTO repair rows count against the `r + 4` extra-row cap** (decision 10).
   - **`T_lr`:** one timer per block at `last symbol sent + 43 ms + srtt + 2 rttvar`, cancelled by (all sources accounted | a REPAIR_REQUEST | DECLINED | Deferred). If it fires it sends one extra repair (row = next unused) and does not re-arm (rev 5 re-arms once; one is enough with a fixed r, and the deadline follows).
6. **Closing** (design §4; the Empty rule needs no change after `FINDINGS.md`).
   - **k_max:** the source that makes `idx + 1 == k_max` is sealed with LAST and closes the block.
   - **Empty:** at the tail of `pump_admission`, when `stop == Stop::Empty` **and** `!admission_backlog(now)` **and** nothing is in `pending_bundles` or `pending_repairs`, the final bundle is sealed with LAST (`Packer::flush_closing(empty)`) and the block closes. A pump that ended on `Depth`, `Tokens` or `Rejected` never closes the block, and an Empty pump with no open source does nothing. (`stop == Empty` alone is not enough: the pump loop breaks with `Empty` when a pull returned nothing under a small budget, with the scheduler still holding work.)
   - **T:** counted from the block's first sealed source; one more deadline in `next_wake_deadline`; serviced next to `poll_pto` (`service_blocks(now)`). All sources are already out, so closing is repairs only, with no LAST.
   - **MTU shrink:** when `max_dg - FEC_REPAIR_HEADER_LEN` is below the open block's longest coded symbol, the block closes at its current size. Repairs that no longer fit are dropped and counted `repairs_dropped_mtu`. **A block whose repairs were all dropped hands off at once** (tiles to ARQ, H.264 lost to the manager), as a block with `r = 0` has nothing to wait for.
   - A block with no sources is never closed. A DECLINED or hand-off for a block still in `Sending` also closes the packer's open block (`Packer::close_now`), so no later source joins a block the client has given up. A source is sealed into an open block only by the packer, so a block cannot hold a PLAIN bundle.
7. **Repairs at close.**
   - `r` rows 0..r-1, encoded with `encode_repairs` over the coded symbols, each wrapped in a `RepairFrame{bundle_seq: packer.alloc_seq(), block_id, k, r, repair_idx}`. `r` is `min(r_knob, 255 - k)`; a block that cannot have one repair row (k = 255) goes PLAIN-equivalent: counted, no repairs.
   - **Ordering.** An admitted repair is sealed at once, ledgered by `record_bundle`, and pushed to the back of `pending_bundles` like any bundle, never offered to quinn ahead of a source that quinn refused (`drive_pending_bundles` sends oldest first). A refused repair stays at the head with the rest. `unsent_bundle_bytes` counts queued repair bundles (it already sums `pending_bundles`; add a test that it does), so the depth gate sees them.
   - Each repair is queued as a `RepairJob` in a per-session `pending_repairs` queue and sent as a bundle with **no records** (so it is a ledger transmission with empty `records`, ACKed and BWE-sampled as a bundle, exactly like a lone control frame, and a verdict on it is congestion state only). `SealedBundle` gains `kind: Plain | Source | Repair`.
   - **Admission:** a job is admitted with `admit_one(.., AdmitClass::Critical, frame_len, ..)`. Three call sites, all through one `service_pending_repairs(now)`: (a) right after `queue_bundles` in `send_counted_framed` (so repairs follow their last source in the FIFO), (b) at the head of `drain_reliable_emitter` (what could not go in (a) goes first), (c) after the Empty close at the pump tail. `Depth` or `Tokens` leaves the job queued and makes `drain_reliable_emitter` return that `Stop`; `admission_backlog` counts `pending_repairs`. **After an Empty close the pump's `stop` is `Empty`, and `pump_admission` arms `admission_wake` only for `stop != Stop::Empty` (`pacing.rs:397`).** So when (c) gets `Tokens` or `Depth`, the pump sets `stop` to it before the wake logic, and its `need` for `time_until` is the repair frame's length, not `mtu` or `MIN_PULL_BYTES`. Test: an Empty close with a bucket too empty for the repair arms a wake and the repair leaves when it fires.
   - **Billing, one charge:** an admitted repair has paid `frame_len` at admission. In `note_bundle_enqueued`, for `kind == Repair` charge only `framing` ungated, not `control_wire`, or it is billed twice. A new `WireClass::Repair` (`COUNT` 7 → 8) takes the offered bytes, so `offered_total_B == quinn_bytes_enqueued` still holds.
   - **goog_cc/BWE:** a repair bundle is one packet and one sample (size = its wire bytes). Its verdict feeds `loss_window` and goog_cc, and never retransmits. R6-d does not tag repairs as probe material (R6-e).
8. **The H.264 content/transport split (rev 6 §5.3).**
   - The ledger verdict stays transport: `tx_judged_lost` and the loss window count as today.
   - **The manager hears a fragment lost only from content outcomes:** DECLINED naming its idx in `missing`, or the block's deadline with the source unaccounted. The delivered side is already in R6-c (`on_recovered` → `release_h264_content` → `frag_acked`).
   - `BlockTable::on_verdict(bundle_seq)` returns `Park` (source of a block in `Sending | Repair | Deferred`, not yet accounted: skip the manager and the retransmit), `Skip` (the entry is `handled`: the content outcome was already taken) or `Pass` (a PLAIN bundle, or a `Closed` block's source that was never handled). `note_h264_verdicts` and `loss_path` consult it.
   - `note_h264_verdict_in` is split in three: the counter half (`tx_judged_lost`) and **`note_raised_lost` stay at the verdict** (`h264_refs.rs:516` is the probe-raise congestion guard, not content state, and must not be parked); the manager half (`h264_refs_verdict`, the suspect flag, the queue purge, the cache drop) becomes `h264_content_lost(frame_seq, frag_idx, now)`, called at the content outcome and never bumping `tx_judged_lost`. The identity `tx_recorded >= tx_acked_live + tx_judged_lost + tx_forgotten` must hold (test `every_recorded_h264_transmission_has_exactly_one_outcome`, `h264_tx.rs:1171`).
   - **Does FRAME_ACK alone clear a suspect frame?** It already can (`suspect_overridden`). R6-d does not wait for RECOVERED to mark a frame decoded, but never makes a frame suspect on a parked verdict either; the deadline is the backstop (decision 5).
9. **Protected retransmit rules** (rev 5 §4.8.3, in the paths that exist).
   - `loss_path::detect` and `probe` take a `protected: impl FnMut(u32 /*bundle_seq*/) -> bool`. A protected transmission is still declared lost (congestion state) but its records get **no** `request_retransmit`. Counted `protected_timer_suppressed`. This is a predicate at the loss path, not a `RetxRequest::Protected` in `classify_retx`: `classify_retx` sees a content key, not the transmission, and rev 5 says protection is per transmission.
   - `probe` answers a protected candidate with one new repair row of its block (a transmission, ACKed) instead of a source. A block in `Deferred` is skipped.
   - `take_due_deferred` is unchanged: protected content is never parked there.
   - **TILE_NACK is honoured, and counted `nack_on_protected`.** Rev 5 refuses it. Refusing needs a content-to-bundle lookup, and a refused NACK that was right strands a tile. The retransmit is PLAIN and idempotent. Expect duplicates: the client's 50 ms NACK debounce fires inside its 43-86 ms request round, so a tile the request would have repaired is also NACKed. Client-side suppression comes later. (Decided provisionally; owner may override.)
   - H.264 IDR-fragment resends and PTO fragment resends are refused while their block is protected (rev 6 §2.3); after `HandedOff` or a decline they are as today.
10. **REPAIR_REQUEST serving.** For each `RepairAsk`: look up the block; unknown or `Closed` counts `request_unknown` / `block_closed_late_trigger`. Else serve `min(missing, rows_left)` rows starting at `max(first_new_idx, next_unused_row)`, clamped to `255 - k`, and cap a block's extra rows at `r + 4`, PTO and `T_lr` rows included (`request_over_cap`), so a hostile client cannot make the server send unbounded repairs. `have >= k` is malformed: treat as DECLINED with every unaccounted source missing. `have < k` while `Deferred` returns the block to `Repair` (`have_mismatch`). The rows are `RepairJob`s through decision 7's admission, with the block's `k` and `r` in the header.
11. **DECLINED serving.** **Hand off every source of the block that is not accounted (ACKed or RECOVERED); the bitmap is only a cross-check, counted `declined_bitmap_extra` when it names a source the server holds as accounted.** The client's bitmap covers `0..k` only when it knows k; with k unknown it uses `sources.len()` (`blocks.rs:142`, "highest source idx seen + 1"), so lost trailing sources are not named, and trusting the bitmap strands them. Tiles get a PLAIN `Handoff` retransmit per unaccounted source; H.264 gets `h264_content_lost`. Then the block closes `Declined`. `k` in the record is checked against the block's `k` (mismatch counts `declined_k_mismatch` and uses the block's own).
12. **Not in R6-d.** Adaptation (r, k_max, T from LOSS_REPORT), `T_adv` advertisement, frame-spanning interleaved blocks above ~70 Mbit/s (the knob clamps `k_max` to 255 - r), padding as repair, removal of H.264 retransmission (R6-f).

**Decided provisionally, pending the owner's override** (recorded as decisions, not questions):
1. Daemon default stays **off** until R6-e (a fixed r costs 20 % or more on a clean link).
2. TILE_NACK for protected content is honoured and counted `nack_on_protected` (decision 9). Rev 5 said refuse.
3. Retransmissions are never protected (decision 2). The alternative, protecting them, needs a second deadline cycle per retransmit.
4. **Frame dimensions stay PLAIN in R6-d** (a lone control frame, as today). Design §1 says every datagram is protected, so this is an open owner question; the datagram is re-sent on change and tiny, and protecting it needs a one-record source block that closes on Empty.

### Task D2: the packer's block mode (model: **sonnet**)

`T/fec_tx/packer.rs` (+ new `T/fec_tx/blocks.rs` for the pure block builder). **No bridge wiring.**

**Step 0, before any edit:** at the R6-c tip, record a golden of the sent frames (bytes of every datagram handed to `TestWire` over a fixed scripted scene, as a checked-in test fixture or a hash plus the scene). It is D4b's knob-off byte-identity test; capturing it after D2 would prove nothing.

- `Packer::set_blocks(Option<FecBlockParams>)`. `RecordMeta.protect` (decision 2; every existing construction site passes `protect: false`, so behaviour is unchanged until D4).
- With blocks on, a bundle of protected records seals as `SourceFrame`: `block_id`, `idx`, LAST per decision 6. Overflow rule `FEC_RECORDS_HEADROOM + body > max_dg` replaces `FEC_PLAIN_HEADER_LEN + body > max_dg` for source bundles. The sealed bundle carries `kind` and its coded symbol (`SourceFrame::coded_symbol`) goes into the open block.
- API (names are proposals): `push` and `flush_closing(empty: bool)` return the sealed bundles plus `Option<ClosedBlock{block_id, k, symbols, kinds, first_sealed_at}>`; `close_if_due(now)` (T); `close_for_mtu(max_dg)`; `reset()` clears blocks. The block id counter wraps.
- A protected-to-unprotected change of kind seals the open bundle first. A pad, a probe-tagged record and `lone` are as before.
- `lone_bundle_len(rec_len, kind)` takes the frame kind (decision 2).
- Tests (all in `packer.rs`, sans-IO):
  - k_max close sets LAST on exactly the closing source, and idx runs 0..k.
  - Empty, T and MTU closes (no LAST on T and MTU).
  - Every sealed frame parses with `fec::frame::parse`; the source's `coded_symbol` equals what the packer stored.

### Task D3: the block table (model: **sonnet**)

New `T/fec_tx/block_table.rs`, pure and sans-IO, time as `Instant` arguments, driven by unit tests. It is the whole of decisions 3, 4, 5, 7 (row allocation), 8 (`on_verdict`), 10 and 11 as a state machine that returns actions.

- Inputs: `on_closed(ClosedBlock, now, deadline_kind)`, `on_arrival(bundle_seq, now)`, `on_recovered(bundle_seq)`, `on_declined(block_id, k, missing_bitmap)`, `on_request(RepairAsk)`, `on_verdict(bundle_seq) -> Park | Skip | Pass`, `on_timer(now, srtt, rttvar)`, `next_deadline() -> Option<Instant>`, `evict_over_cap()`, `reset()`.
- Outputs (an `Action` enum): `Repair{block_id, row}` (to be encoded by the bridge from `symbols(block_id)`), `HandOffTile{records}`, `ContentLostH264{frame_seq, frag_idx}`, `Alarm(DeferralTimeout)`.
- Row allocation: planned rows `0..r`; extra rows are `max(r, highest_used + 1)` upward, never reused, never above `255 - k`; the per-block extra cap is `r + 4`.
- Tests, one per transition and per order of the cross-channel races of rev 5 §4.9.5:
  - ACKs reaching k → `Deferred`; all accounted → `Closed(Accounted)` and symbols freed.
  - DECLINED before held(B) reaches k, and after.
  - A RECOVERED before the verdict, and the verdict first.
  - A deadline in `Repair` hands off; in `Deferred` it does not (tiles), and for H.264 the `2 srtt + 100 ms` alarm acts instead of the deadline (property: at srtt 150 ms no H.264 source of a block with held >= k is reported lost before RECOVERED or the alarm).
  - DECLINED with k unknown and a bitmap that omits trailing lost sources: every unaccounted source is handed off. Break test: use the bitmap instead; this must fail.
  - A late verdict on a closed block's source returns `Skip` (the `by_bundle` entry outlived the block).
  - A block whose repairs were all dropped hands off at once.
  - `T_lr` fires once and is cancelled by each cancelling event.
  - Eviction by count and by bytes; a late trigger on a closed block is counted and does nothing.
  - REPAIR_REQUEST: rows are fresh, clamped, capped; `have >= k` is a decline; `have < k` in `Deferred` re-opens.
  - Property: no source is ever both handed off and released as delivered, and every source of a closed block ends in exactly one of delivered, handed off, lost-to-manager.
- Break tests (say which): drop the `Deferred` check; the property must fail.
