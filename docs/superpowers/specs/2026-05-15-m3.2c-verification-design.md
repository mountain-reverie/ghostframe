# M3.2c — End-to-End Verification of the WebGPU Client: Per-Milestone Design

**Date:** 2026-05-15
**Status:** Design approved
**Predecessors:**
- `docs/superpowers/specs/2026-05-13-m3.2b-webgpu-client-design.md` (the milestone whose foundation M3.2c verifies)
- `docs/superpowers/specs/2026-05-13-palrle-codec-design.md` (PalRLE wire format + palette table)
- `docs/superpowers/specs/2026-05-11-m3.1-solid-scheduler-decisions.md` (Scheduler + FEEDBACK bidi stream)
- `docs/superpowers/specs/2026-04-28-m3-codec-suite-design.md` (M3 umbrella)

This design supersedes the "M3.2c follow-up bucket" enumerated in `~/.claude/projects/-home-cedric-work-ghostframe/memory/project_m32c_deferred.md` where they conflict, and otherwise refines it. M3.3+ phase ordering is unaffected.

---

## Context

M3.2b shipped 22 commits of foundation: the WebGPU client migration, HELLO capability handshake, `indices_raw` wire variant, decode-error feedback (`0x04`), and the rAF tick orchestrator. The build chain is green (271 lib tests + 27 vitest + 15 e2e). But two verification gaps remain:

1. **Five e2e tests are `#[ignore]`'d** because the test capture path (Xorg-on-VKMS + `--text-grid` + xdaemon's modesetting-FB capture) does not yield PalRle-feasible content, plus one edge-tiles failure under odd-resolution VKMS.
2. **Seven "Not Proven" behavioural assertions** that M3.2b's design implies are not exercised by any current passing test. M3.2b's WGSL shaders (PalRLE compute, Solid render, H.264 blit) have been logic-tested at unit level but never behaviourally verified end-to-end against real wire bytes.

M3.2c is the verification milestone that closes both gaps. It is NOT a feature milestone — no new wire protocol, no new codecs, no new client features.

---

## Decision Register

| # | Decision | Rationale |
|---|---|---|
| D1 | Pure verification milestone; no new wire protocol, no new client features | M3.2b shipped foundation; correctness must land before M3.3 builds on it |
| D2 | Strategy α — verify shaders through the real production-like wire pipeline, NOT a synthetic-payload Dawn-Node / browser-smoke harness | Real end-to-end proof is the project's contract; synthetic harnesses verify shader logic but leave wire-protocol / classifier-integration gaps |
| D3 | Capture-path fix: diagnose-first, then commit to one of three concrete repairs (xdaemon source-selection fix, capture-pipeline alpha/AA fix, or DRM-direct text-rendering mode in test-pattern) | Three plausible root causes; locking in a fix before knowing which one applies risks burning the milestone on the wrong rabbit hole |
| D4 | Pixel-accuracy bar: exact-match for lossless codecs (Solid, PalRle, Raw) + SSIM ≥ 0.95 against checked-in golden PNG for H.264 (per-backend split fallback documented in the Risks table) | Catches off-by-one tile placement, channel-swizzle, OOB-pixel bugs (exact-match) AND lossy-codec quality regressions (SSIM); golden image is the high bar M3.2b's "find a red-ish pixel" assertions cannot reach |
| D5 | OOB-index error injection via a new `GHOSTFRAME_INJECT_OOB_PALRLE` env-var on the server, paralleling the existing `GHOSTFRAME_*_LOSS_*` protocol | Re-uses the established test-injection idiom; no new cfg(test) surface on the server |
| D6 | `__readPixel` correctness gets its own pre-flight test (`e2e_readpixel_correctness`) ahead of any other pixel assertion | Every pixel-assertion in M3.2c builds on `__readPixel`; if the readback is wrong the entire milestone silently lies |
| D7 | SSIM via `image-compare` crate (or hand-rolled if it doesn't fit) rather than JS-side in the page | Rust-side keeps the golden image and the threshold under `cargo test`; cleaner failure messages, no Chrome JS dependency |
| D8 | Goldens regenerated only on intentional H.264 tuning changes via a `GHOSTFRAME_BLESS_GOLDENS=1` test flag | Standard golden-image practice; protects against accidental "bless the regression" runs |
| D9 | Edge-tiles (A4) gets a hard-stop: 1-day timebox, otherwise stays `#[ignore]`'d and carries over | A4's root cause is unknown and could be tangled with resolution-change work, which is explicitly out of scope |
| D10 | Section D items (errors-readback tile-coords map, `device.lost` auto-reconnect, `indices_raw` content-class predicate) and the M3.2a parking-lot items stay deferred | Out of scope per the "no new features" framing; revisit when M3.5 bench data motivates |

## Goal & non-goals

### Goal

> Every `#[ignore = "M3.2c: …"]` in `ghostframe-lib/tests/e2e.rs` is removed, AND every "Not Proven" item B1–B7 from `project_m32c_deferred.md` is converted to a passing test exercising the real WebTransport → WebGPU pipeline.

The verification bar is the production-like flow: server classifier → wire bytes → client reassembly → CPU pre-validation → GPU dispatch → framebuffer pixels. No synthetic shader harnesses, no Dawn-Node bypass.

### Non-goals

- No new wire-protocol surface (no new codecs, no new message types, no new HELLO bits).
- No new server-side reactions to decode errors.
- No content-class predicate for `indices_raw` (M3.5).
- No `device.lost` auto-reconnect.
- No new errors-readback → tile-coords map unless B7's test design forces it.
- No M3.2b parking-lot items (GPU subset-fold against persistent-table palettes, pure-GPU RLE encode, `pulp` SIMD on inner-loop RLE, persistent-table churn cap).
- No resolution-change support (separate plan; see `docs/superpowers/plans/2026-04-27-e2e-resolution-change.md`).

## Workstreams

### W1 — Capture-path diagnosis & fix

Unblocks `#[ignore]`'d tests A1 (`e2e_palrle_5pct_loss`), A2 (`e2e_palrle_session_reset`), A3 (`e2e_text_clarity`), and prerequisite for A5 (`e2e_decode_error_thin_uncached`).

**Phase 1.1 — Diagnose** (time-boxed, ~½ day). Add temporary instrumentation to learn what the classifier sees for `--text-grid`:

- Per-frame `unique_colors_per_tile` histogram for tiles overlapping the text region, logged via `tracing` in `io_bridge::process_frame_gpu`.
- One-shot raw frame dump: save the 4-byte-BGRA pixels of one captured frame to `/tmp/frame.bin`, inspect with `od` to confirm the actual capture content (e.g., is `BG_PIXEL = 0x141414` reaching the classifier, or is it the VKMS empty scanout?).
- Confirm Xorg actually paints by capturing via `xwd` inside the test container.

Three possible root causes, mutually exclusive:

- **a) X11 paints correctly but capture reads VKMS scanout** (xdaemon's source selection wrong; writeback connector unavailable on VKMS). Fix in xdaemon's capture-source selection or VKMS connector config.
- **b) Capture reads correct bytes but introduces alpha / premultiplied / sub-pixel-AA noise** that inflates the per-tile unique-color count above the PalRle classifier threshold. Fix the channel/alpha handling — same family of bug as `feedback_canvas_alpha.md`.
- **c) Capture path is genuinely unfixable on Xorg-on-VKMS in the test container.** Add a `--text-grid --drm-direct` mode to `ghostframe-test-pattern` that paints the same glyphs into a DRM dumb buffer, migrate the ignored tests to that mode.

**Phase 1.2 — Implement** the chosen fix.

**Phase 1.3 — Verify** by un-`#[ignore]`'ing `e2e_palrle_5pct_loss` and `e2e_text_clarity`. Both must pass on local hardware and on SwiftShader fallback.

### W2 — `__readPixel` correctness pre-flight

Blocks every pixel assertion in M3.2c. Independent of W1; runs in parallel.

W2 is not in tension with D2 (no synthetic shader harness): the debug compute pipeline introduced here verifies the *readback function* `__readPixel`, not any production codec shader. Production shaders (`palrle_decode.wgsl`, `solid.wgsl`, `h264_blit.wgsl`) are still only verified through real wire bytes in W3 and W4.

- Add `window.__readGradientGolden(): Promise<{ok: bool, mismatches: Array<{x,y,got,want}>}>` to `ghostframe-web-client/src/main.ts`. Compute-shader-writes a known `(x, y, 0, 255)` gradient to the framebuffer at session-start (via a one-shot debug pipeline distinct from any production codec pipeline), reads back via `__readPixel` at 16 sample points, returns a structured diff.
- Add `e2e_readpixel_correctness` in `tests/e2e.rs`: spins up the client, calls `__readGradientGolden()`, asserts `ok === true`. Fails today if `__readPixel` has wrong channel order, off-by-one origin, or wrong stride.

### W3 — Shader correctness through real wire bytes

Sequenced after W1 + W2.

- **B1 — PalRLE compute shader.** New e2e `e2e_palrle_exact_pixels` driven by a new `palrle_exact.rs` test-pattern mode emitting a 2-color tile with predetermined palette and indices. Assert exact RGBA values at specific `(x, y)`. Palette designed so swapping even/odd nibbles would be detectable (e.g., index 0 → BGRA `0xFF0000FF`, index 1 → BGRA `0x00FF00FF`; alternating-nibble payload).
- **B2 — `indices_raw` wire round-trip.** Extend `e2e_indices_raw_handshake` (currently SwiftShader-sanity only). Add `window.__ghostframeRecordedFlags: number[]` parallel to the existing `__ghostframeRecordedCodecs`. Assert at least one tile has `(flags & 0x02) != 0`.
- **B3 — Solid WGSL pipeline.** New `e2e_solid_per_tile_pixels` driven by a new `solid_per_tile.rs` test-pattern: uniform-color tiles in known regions surrounded by motion in others, so the classifier picks `CodecState::Solid` per-tile for the static regions. Exact-pixel-match on corner tiles. Mitigation if the classifier never picks per-tile Solid in practice: design the pattern against the classifier source, verify with a quick unit test before writing the e2e.
- **B6 — Decode-error round-trip.** Re-enable `e2e_decode_error_thin_uncached`. Inject a thin PalRLE tile referencing an uncached `palette_id` (via the existing `GHOSTFRAME_OUTBOUND_LOSS_PREDICATE=palrle_bundled` knob). Assert the server receives `0x04` with `error_code=3`, the next dirty pass emits bundled (`force_rebundle` works), and the client re-renders correctly.
- **B7 — Errors-readback path.** New `e2e_palrle_oob_index`. Introduce `GHOSTFRAME_INJECT_OOB_PALRLE=tile_x,tile_y` env-var on the server that emits a malformed PalRle payload (count=1, indices=2, OOB) for one tile. Assert a `0x04` `error_code=5` arrives at the server FEEDBACK stream.

### W4 — Pixel-accuracy infrastructure

- **Exact-match infra** falls out of W3 — no extra scaffolding beyond `__readPixel`.
- **SSIM golden-image infra for H.264:**
  - Add `image-compare` dev-dep to `ghostframe-lib/Cargo.toml`.
  - Add `screenshot_canvas(page) -> image::RgbaImage` to `tests/helpers.rs`, wrapping Chrome DevTools `Page.captureScreenshot` + `image::load_from_memory`.
  - Add `assert_ssim_against_golden(captured, golden_path, threshold)` helper.
  - Add `bless_golden(captured, golden_path)` helper gated on `GHOSTFRAME_BLESS_GOLDENS=1`.
  - Generate `ghostframe-lib/tests/e2e/golden/h264_solid_red_t5s.png` once on the canonical rig (real GPU passthrough), commit to git.
  - New `e2e_h264_ssim_golden`: 5 s into `--solid-red`, capture screenshot, decode PNG, run SSIM, assert ≥ 0.95.
  - Pre-flight: run the SSIM test 5× on the canonical rig to confirm score variance < 0.01 before locking the threshold. If the threshold doesn't hold on SwiftShader, split into per-backend thresholds.

### W5 — Edge-tiles investigation

A4 — `e2e_edge_tiles` reads `r=0` at the center pixel under WebGPU + Xvfb + 700×500 VKMS. Likely separate from W1.

- Confirm via `__readPixel(0, 0)` / `(699, 499)` whether the canvas is empty everywhere or only at the read coordinates (size/scale mismatch vs full corruption).
- Check `MAX_TILES` calc and partial-tile accounting in the renderer for 22-col + 1-partial × 15-row + 1-partial layout.
- Check H.264 full-frame `importExternalTexture` scaling to non-power-of-two, non-32-aligned 700×500.
- **Hard-stop:** 1-day timebox. If unfixed, leave `#[ignore]`'d and document the deferral in `project_m32c_deferred.md`.

### Ordering

```
W1 (capture-path fix)  ─┐
                        ├─►  W3 (shader correctness through wire)  ─┐
W2 (__readPixel)        ─┘                                          │
                                                                    ├─►  done
W4 (SSIM golden, H.264-only)  ─────────────────────────────────────┤    (W4 SSIM is parallel-safe; runs any time)
                                                                    │
W5 (edge tiles, hard-stop 1d)  ────────────────────────────────────┘
```

W1 and W2 run in parallel. W3 needs both. W4's SSIM piece is independent of W1/W2/W3 and can start any time. W5 runs last; if it blows the hard-stop, the carry-over is documented and the milestone closes.

## Test-infra additions

### New test-pattern modes (`ghostframe-test-pattern/src/`)

- *(Conditional on W1 path 1.1c.)* `text_grid_drm.rs` — paints the same `GHOSTFRAME / TILE / TEST` glyphs via DRM dumb buffer instead of X11. Reuses `font.rs` and `SamplePair` constants so test-side coord math is unchanged.

- `ghostframe-lib/tests/e2e/golden/h264_solid_red_t5s.png` — checked in; regenerated only via bless.

## Risks & mitigations

| Risk | Mitigation |
|---|---|
| Capture-path root cause is harder than ½ day | Phase 1.1 is time-boxed; if no diagnosis, fall through to W1 path 1.1c (DRM-direct text mode) as the escape hatch |
| Classifier never picks per-tile Solid in practice | Design `solid_per_tile.rs` against the classifier source, not against hope; verify with a quick unit test before writing the e2e |
| SSIM threshold flaky across real GPU vs SwiftShader | Lock threshold on the canonical rig with 5-run variance < 0.01; split per-backend if needed (0.95 real, 0.90 SwiftShader) |
| Edge-tiles fix balloons into resolution-change scope | W5 hard-stop at 1 day; leave `#[ignore]`'d on miss |
| OOB-index injection requires invasive cfg(test) surgery | Implement via env-var protocol mirroring existing `GHOSTFRAME_*_LOSS_*` knobs; no new cfg surface |
| Goldens drift on intentional H.264 tuning | `GHOSTFRAME_BLESS_GOLDENS=1` bless flag; review-gate the diff in PR |

## Exit criteria

M3.2c is complete when **all** of the following hold on `cargo test -p ghostframe-lib --lib` and `cargo test -p ghostframe-lib --test e2e -- --test-threads=1`:

1. **Zero `#[ignore = "M3.2c: …"]`** in `ghostframe-lib/tests/e2e.rs`. (The unrelated resolution-change `#[ignore]` at line 1461 stays — separate blocker.) If W5 hits its hard-stop and `e2e_edge_tiles` carries over, this requirement reads "zero except `e2e_edge_tiles`, with carry-over documented."
2. **271+ lib tests, 27+ vitest, ≥ 20 e2e all green.**
3. Every WGSL shader in `ghostframe-web-client/src/webgpu/shaders/` has at least one end-to-end pixel assertion:
    - `palrle_decode.wgsl` → `e2e_palrle_exact_pixels`
    - `solid.wgsl` → `e2e_solid_per_tile_pixels`
    - `h264_blit.wgsl` → `e2e_h264_ssim_golden`
    - `present_blit.wgsl` → implicitly covered by every pixel-assertion test
4. **`__readPixel` is independently verified** by `e2e_readpixel_correctness`.
5. **At least one e2e uses a golden-image reference** (`e2e_h264_ssim_golden`, SSIM ≥ threshold locked on canonical rig, variance < 0.01 across 5 runs).
6. **At least one e2e asserts exact pixel values** at known coordinates (the `e2e_*_exact_pixels` tests).
7. **`indices_raw` wire emission is verified** end-to-end (flags bit 1 observed on the wire AND tile correctly rendered).
8. **Decode-error code 3 → `force_rebundle` round-trip** is verified end-to-end.
9. **GPU shader OOB-index error path** is verified end-to-end (code 5 observed on FEEDBACK stream).
10. **`project_m32c_deferred.md` is updated** to mark every Section A / Section B item closed, with a pointer to the verifying test for each. Any W5 carry-over is captured.

## What this design does NOT do

- No synthetic / Dawn-Node shader harness. Shader correctness is verified through real wire bytes only.
- No new wire-protocol surface, no new client features.
- No content-class predicate for `indices_raw`, no `device.lost` auto-reconnect.
- No tightening of existing `find-red-ish-pixel-anywhere` assertions in unrelated tests — those are intentionally loose for QUIC-congestion / partial-arrival tolerance.
- No multi-monitor or multi-canvas test surface.
- No client-side metrics export or WebTransport metrics stream.

## W1 diagnosis findings (recorded 2026-05-15)

Ran `cargo test -p ghostframe-lib --test e2e e2e_palrle_5pct_loss -- --ignored --test-threads=1 --nocapture` with `GHOSTFRAME_DIAGNOSE_TILES=1` and `RUST_LOG=ghostframe::diagnose=info` (commit `da1dcb6`). Test failed at the codec-recording assertion:

```
expected Codec::PalRle (2) on the wire; saw codecs: [5, 5, 5, 5, ...]   (≈400× repeated)
```

100% of 400+ classified tiles came back as `Codec::Raw (5)`. Per the classifier rule at `ghostframe-lib/src/tile/classifier.rs:165–170`:
- `unique_colors == 1` → Solid (codec 1)
- `unique_colors ≤ 16` → PalRle (codec 2)
- otherwise → Raw (codec 5)

The text-region tiles should contain exactly 2 colors (`BG_PIXEL = 0x141414`, `FG_PIXEL = 0xF5F5F5`). Their classification as Raw is only consistent with capture reading garbage / scanout (every tile > 16 unique colors), not with alpha/AA noise (which would still yield ≤ 3 unique colors per tile).

**No per-tile tracing was emitted** because the e2e test binary does not initialize a `tracing-subscriber`. The `GHOSTFRAME_DIAGNOSE_TILES` parser still works at unit-test level but its emissions are not visible at e2e runtime. This is a known limitation of the diagnostic instrumentation; not a regression. Future work could add a subscriber init in the test harness.

**Chosen fix path: 1.1c** — add a `--text-grid --drm-direct` mode to `ghostframe-test-pattern` that paints the same glyphs into a DRM dumb buffer, bypassing Xorg entirely. Migrate `e2e_palrle_5pct_loss`, `e2e_palrle_session_reset`, `e2e_text_clarity`, and `e2e_decode_error_thin_uncached` to that mode.

The deeper Xorg-on-VKMS investigation (whether 1.1a — xdaemon source-selection — or 1.1c — fundamental VKMS limit — is the true root cause) is **out of scope for M3.2c**. It would be a production-path fix that doesn't affect the verification goal; tracked separately if it becomes user-visible later.
