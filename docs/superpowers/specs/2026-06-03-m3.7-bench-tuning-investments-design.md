## Context

M3.6c shipped the bandwidth-axis bench and observed that the policy machinery works (every override pathway is reachable code), but the bench couldn't produce empirical signal to retune the 3 M3.6 constants:

- `REFINEMENT_BIAS_PER_TILE_US = 5.0` — needs PixelPerfect convergence vs mode-switch ratios.
- `HEADROOM_MIN_BYTES_PER_US = 0.25` — needs realistic QUIC `cwnd` shrinkage (our app-side cap doesn't drive cwnd).
- `LOSS_OVERRIDE_THRESHOLD = 0.10` — needs decode-error rates across a loss-axis sweep.

The bench-report's "Investments deferred" section documented 4 specific upgrades that would unlock empirical tuning. M3.7 lands 3 of them (PixelPerfect metric, tc qdisc shaping, subtle-drift pure scenes); the 4th (loss-axis sub-matrix) is the natural shape of M3.7a's loss-tuning sweep.

This milestone is bench-only. No production policy code changes; no wire-format changes. The classifier gains 3 cfg-gated env-var overrides that mirror M3.6b's `GHOSTFRAME_TEST_FORCE_BYTES_PER_US` pattern — production behavior unchanged when env vars are unset.

Tier 3 from the bench-results follow-up plan (server→client `policy_snapshot` wire + client overlay for production telemetry) splits to **M3.8**: different review surface (production wire format + UI), and the bench-side tuning in M3.7 should land first so M3.8's telemetry has tuned constants to broadcast.

## Architecture

### Two phases (a + b)

Mirrors the M3.6 cadence. Each phase reviewable as one PR with one focused concern, each ending with a constants retune commit.

**M3.7a — Tier 1: parametric tuning of 2 constants from controlled signals.**
- New harness metrics: `pixelperfect_count` (parsed from `cdf53.pixelperfect` log lines) and `decode_error_count` (parsed from existing decode-error datagrams that the server already logs).
- Subtle-drift mode for pure scenes: `ghostframe-test-pattern --subtle-drift <ms>` shifts the rendered tile pattern by 1 pixel every N ms so pure scenes generate dirty events.
- Cfg-gated env-var overrides for 2 of the 3 M3.6 constants:
  - `GHOSTFRAME_TEST_REFINEMENT_BIAS_US` overrides `REFINEMENT_BIAS_PER_TILE_US`.
  - `GHOSTFRAME_TEST_LOSS_OVERRIDE_THRESHOLD` overrides `LOSS_OVERRIDE_THRESHOLD`.
- Bench sweep modes:
  - `--bias-sweep` (4 bias values × 1 scene × 1 bandwidth point, 30 s each).
  - `--loss-axis` (6 loss rates × 1 bandwidth × 1 scene, 30 s each).
- Closes with a retune commit citing Tables 11 and 12.

**M3.7b — Tier 2: realistic-cwnd shaping unlocks HEADROOM tuning.**
- Container entrypoint adds `tc qdisc` shaping driven by new env vars (`SHAPE_BANDWIDTH_KBPS`, `SHAPE_DELAY_MS`, `SHAPE_LOSS_PCT`). `iproute2` installed in the Dockerfile.
- Harness extends the M3.6c env-var forwarding loop to include the 3 SHAPE_* vars (host → container plumbing).
- 3rd env-var override: `GHOSTFRAME_TEST_HEADROOM_MIN_BPUS` overrides `HEADROOM_MIN_BYTES_PER_US`.
- New bench modes:
  - `--shaping-matrix` (replaces `--bandwidth-matrix` for realistic cases — combined bandwidth + delay + loss per shaping point).
  - `--headroom-sweep` (4 threshold values × 3 shaping points × 30 s each).
- Closes with a retune commit for `HEADROOM_MIN_BYTES_PER_US` citing Table 14.

### App-side hooks coexist with tc

M3.6b's `BandwidthCap` module + the existing `GHOSTFRAME_INBOUND_LOSS_*` injection stay in the codebase unchanged. They run at the WebTransport layer (above QUIC) and are useful for fast lib-level unit tests that don't need cwnd realism. tc is the bench's preferred shaping for sweep-driven tuning because it's the only mechanism that causes QUIC to react realistically. Two valid mechanisms, picked per use case; no code removal.

### Why parametric sweep instead of "judge current values"

A "look at the current numbers and decide" approach is cheaper (~2 h) but produces verdicts that read as opinion. A parametric sweep produces verdicts like "REFINEMENT_BIAS_PER_TILE_US = 10.0 because Table 11 row 3 shows highest PixelPerfect/switches ratio with no latency regression." The retune commit message can cite a specific row of a specific table. Worth the extra ~4 h.

### Sweep semantics

Both sweep modes run on a single scene + single bandwidth point so the swept variable is the only thing that changes between runs. Defaults:
- `--bias-sweep`: scene = `text_drift_50ms` (the new subtle-drift mode applied to `text`), bandwidth = 10 mbps_dsl (1.25 B/µs), loss = 1 % (tc-applied if M3.7b shipped, app-side otherwise).
- `--loss-axis`: scene = `mode_switch` (the existing alternating-cycle scene), bandwidth = 30 mbps_cable (3.75 B/µs).

### tc qdisc shape

Entrypoint applies a single qdisc that combines bandwidth + delay + loss:

```bash
if [[ -n "${SHAPE_BANDWIDTH_KBPS:-}" ]]; then
    tc qdisc add dev eth0 root handle 1: netem \
        delay "${SHAPE_DELAY_MS:-0}ms" \
        loss "${SHAPE_LOSS_PCT:-0}%"
    tc qdisc add dev eth0 parent 1:1 handle 10: tbf \
        rate "${SHAPE_BANDWIDTH_KBPS}kbit" \
        burst 32kbit \
        latency 400ms
fi
```

Failure path: if `tc qdisc add` fails (missing `iproute2`, missing privilege, kernel feature absent), entrypoint logs a warning and continues without shaping. Bench detects post-hoc — the shaping-point's row in Table 13 looks like the unshaped baseline if shaping didn't apply.

## Out of scope

- **Tier 3 production telemetry** (server→client `policy_snapshot` wire + client overlay). Splits to M3.8 (different review surface — production wire format + UI). Tier 3 enables ongoing field tuning; M3.7 enables empirical bench tuning today.
- **Cross-product sweep** (bandwidth × loss × all 3 constants). 4 × 6 × 4 = 96 runs × 30 s = ~50 min plus overhead. Per-axis sweep at representative points captures the same signal for ~12 runs = ~10 min. Cross-product deferred unless per-axis verdicts conflict with each other.
- **Per-content-class constant tuning** (e.g. `text_REFINEMENT_BIAS = X`, `photo_REFINEMENT_BIAS = Y`). The classifier doesn't take content class as input today; introducing class-conditional constants is M4+ work tied to the classifier's content-typing axis (which doesn't exist yet).
- **CPU sampling resolution** improvements (M3.5b deferred item). The 100 ms `/proc` polling cadence is too coarse for steady-state CPU load attribution; M3.7's tuning targets latency + override-frequency outcomes, not CPU. CPU sampling stays at 100 ms.
- **BC1 variant removal** (M3.5b deferred item). M3.7 doesn't touch codec enums; BC1 removal can land independently.
- **Production codepath simplification** (e.g. removing `BandwidthCap` now that tc exists). Per D7, both mechanisms stay valid. Removal is a separate cleanup if ever desired.
- **Adaptive constants** (constants that change at runtime based on observed signals). The 3 constants stay compile-time. Runtime adaptation is M4 territory.

## Post-implementation drift (2026-06-05)

Captured after M3.7a + M3.7b execution. The spec above is the *intent* that drove design; this section records what actually shipped where it differs.

**Scene choice for bias_sweep:** uses `--mode-switch-cycle 12` (same scene as `e2e_progressive_refinement`), not `--subtle-drift <ms>`. The cycle-12 scene already produces predictable static-then-motion phases that exercise CDF53 refinement; the subtle-drift binary mode was implemented (`ghostframe-test-pattern/src/subtle_drift.rs`, kept for ad-hoc tooling) but the bench dispatch landed on the cycle scene because it matches the e2e regression test's signal profile and validation expectations.

**Scene duration:** empirically settled at 180 s per swept value (not 30 s). Refinement convergence + classifier hysteresis dwell windows + tc qdisc settle time combine to need a longer window to produce statistically meaningful PixelPerfect counts.

**Default scene name:** `DEFAULT_SCENE_NAME = "mode_switch_12s"`, not `"text_drift_50ms"`.

**Mid-flight fixes landed during M3.7 execution** (not in the original spec scope but resolved bugs uncovered by the bench work):
- Hysteresis hybrid (commit `da2729b`): wall-clock-only hysteresis from M3.6b (`7e3e041`) was fragile to docker scheduling preemption — spurious mode flips dropped `e2e_progressive_refinement` reliability to 40 %. Fixed with hybrid model (streak counter AND wall-clock dwell, both required). Full bisect history in `feedback_classifier_hysteresis_micros_regression.md`.
- `cdf53.pixelperfect` log target (commit `68023ac`): emission used `target: "ghostframe::cdf53"` but the bench parser filters `"ghostframe::bench"`. One-line target change.
- Env-var forwarding gap: harness `launch_scenario_stack` didn't include `GHOSTFRAME_TEST_*` or `GHOSTFRAME_ENABLE_CDF53` in its host→container forwarding loop. Extended the loop to cover 7 new env vars (commit `5d114dc`).
- Permissive wait-for-status: harness required exact `"Receiving frames"` substring, which never matched on 1 mbps_sat shaping in 30 s. Now accepts `"Connected"` OR `"Receiving frames"` to match e2e helper behavior.

**Review-fix follow-ups (2026-06-05, after `m3.7-complete` tag):**
- `tests/containers/test-server/entrypoint.sh`: rolls back netem qdisc if tbf add fails (prevents silent partial-shaping where delay+loss apply but bandwidth cap doesn't).
- `ghostframe-bench/src/bin/codec_report/main.rs`: bias_sweep and loss_axis dispatch branches converted from `?` to `if let Err` (matching shaping/headroom-sweep) so env-var cleanup always runs and a single bad sweep value doesn't kill the whole run.
- `ghostframe-bench/src/bin/codec_report/report.rs`: Section 9 `has_matrix` derives from `state.args.bandwidth_matrix` (not a `'/'`-in-key heuristic); Sections 11/12/14 sweep-axis label parse failures yield `f32::NAN` / `u32::MAX` instead of silently rendering 0.
- `ghostframe-lib/src/tile/classifier_decide_tests.rs`: 2 new regression tests for the hybrid-hysteresis preemption case (wall-clock jump without sufficient streak must NOT flip mode).
- `ghostframe-e2e/src/harness/scene.rs`: zero-traffic warning when `server_telemetry.is_empty()` to surface mis-launched runs; CRITICAL comment on the env-var forwarding loop cross-referencing the bench bin's expectations.

**Section layout in report.rs:** Sections 11-14 are inline in the writer, not pulled into helper functions. Acceptable for one-off bench tables that aren't reused; if a Section 15+ ever shares structure with 11 or 12, refactor then.

**LOSS_OVERRIDE_THRESHOLD tuning verdict** (not in original spec — added during M3.7a): kept at initial 0.05 value. The 6-value loss sweep (0.0 / 0.005 / 0.01 / 0.03 / 0.05 / 0.10) showed clean H264 fallback at thresholds at and above 0.05; below that, false-positive H264 escalations hurt PixelPerfect counts.
