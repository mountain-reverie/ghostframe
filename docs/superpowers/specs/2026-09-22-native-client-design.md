# Native client: embeddable library, C API, and showcase CLI

*Design, 2026-09-22. Supersedes the sketch in `.claude/NEXT-SESSION-native-client.md`,
which remains useful for the bug history but is not a spec.*

## 1. Purpose

Ship `libghostframe-client`: a Rust-internals, C-ABI library that other projects
link to get a ghostframe session as a dmabuf plus input push functions. The host
application owns window creation, presentation and input capture; the library owns
the tailnet, the transport, the decode and the GPU.

A showcase CLI (`ghostframe`) demonstrates the library: `login` / `logout` /
`connect`, where `connect` opens a window that displays the dmabuf directly.

### Secondary benefit, not the goal

The client currently has two CDF 5/3 decoders -- `Cdf53TileState::integrate` in
Rust and the WGSL GPU path -- and no test executes the real WGSL
(`ghostframe-client-core/tests/oracle_gpu_sparse.rs` reimplements the shader's
arithmetic in Rust and says so in its own header). This library executes the real
WGSL in-process, so it can close that gap. That is a welcome consequence. The
product decision is the embeddable library.

### Non-goals

- Replacing the browser client.
- Scaling the remote framebuffer to the window size in the showcase (1:1 only).
- Clipboard, audio, or any capability not already on the wire.
- Auto-reconnect. The library reports `DISCONNECTED`; policy belongs to the host.

## 2. Decisions and rationale

| Decision | Choice | Why |
|---|---|---|
| Primary goal | Embeddable library, C API is the product | User decision |
| Render stack | wgpu + WGSL | Hedges a possible macOS port: naga emits MSL, so the decode pipelines port for free. wgpu's translator *is* naga, so it yields the same SPIR-V as ash+naga would on Vulkan -- the choice is about future backends, not shader fidelity |
| Platform | Linux first | dmabuf is the output currency |
| H.264 | ffmpeg + VA-API hwaccel | libva does not parse H.264; it takes pre-parsed picture/slice buffers and expects the caller to manage the DPB. ffmpeg does both and still yields a `VASurfaceID` we export zero-copy. Mirrors the existing `ghostframe-lib/src/encoder/h264_vaapi.rs` in reverse |
| Drive model | Library threads + event queue + eventfd | The libinput / Wayland / PipeWire idiom; fits any host main loop, no callbacks into host code from foreign threads |
| Frame handoff | Private framebuffer + 3 export buffers, partial blits | User design. Avoids both tearing and library stalls, and the merged damage rects are reusable by the host |
| Tailnet auth | Interactive URL default, `--authkey` for headless | `logout` must actually leave the tailnet, not orphan a node |
| Showcase | Wayland and X11, runtime switch | User decision |
| Staging | Three milestones | Isolates the risky GPU/export work in M1 |

## 3. Architecture

Four new crates. Two existing components change.

### `ghostframe-client-gpu`

Pure rendering. No networking, no tsnet, no protocol beyond `TileData`.

- wgpu device construction from a hand-built `VkInstance`/`VkDevice` (see 5.1).
- The WGSL decode pipelines: solid, palrle, cdf53 integrate, cdf53 inverse l1 /
  l1_pass2 / l2 / l3, idle_skip, present_blit.
- The persistent internal framebuffer.
- The 3-buffer dmabuf export ring and its modifier negotiation.
- Dirty-tile tracking and rect coalescing.

Testable headlessly with synthetic tiles and no transport at all. This is where
the real WGSL finally executes under test.

### `ghostframe-client-native`

Orchestration and the idiomatic Rust API.

- Owns `GhostbridgeHandle`, `ClientNet`, `ClientCore`.
- Owns the net thread and the render thread (see 8.2).
- Owns the event queue and its eventfd.
- Encodes input via `ghostframe_client_core::input`.

Depends on `client-gpu`, `client-net`, `client-core`, `tsnet`.

### `ghostframe-client-capi`

`crate-type = ["cdylib", "staticlib", "rlib"]`. A thin `extern "C"` shim over
`client-native` with no logic of its own. `ghostframe_client.h` is generated by
cbindgen, as `ghostframe-lib/build.rs` already does.

### `ghostframe-cli`

The `ghostframe` binary: `login`, `logout`, `connect`. `connect` opens the
showcase window. It depends on `client-capi` **as an rlib and calls the
`extern "C"` symbols directly**, so the showcase exercises the real C surface and
proves it sufficient, without adding a C toolchain to the build.

### Modified

- `ghostbridge/main.go`: adds `gbridge_login_url` and `gbridge_logout`.
- `ghostframe-tsnet`: adds the matching safe wrappers.

### Repo-mechanical obligations

- New workspace members must be added to the test-server `Dockerfile`, which
  `COPY`s manifests per crate. Missing one fails `docker buildx` before any test
  runs.
- CI names `--test` targets individually in `.github/workflows/e2e.yml`. A new
  `tests/*.rs` does not run in CI until a workflow names it.
- GPU-gated e2e tests must be added to `ci/skip-list.txt` in the same PR.

## 4. The C API

Opaque handle, `gf_` prefix, `struct_size` on every struct for forward
compatibility, `gf_version()` for consumers to check.

```c
/* lifecycle */
gf_result gf_client_create(const gf_client_config *cfg, gf_client **out);
void      gf_client_destroy(gf_client *c);
int       gf_client_event_fd(const gf_client *c);            /* add to your poll set */
gf_result gf_client_next_event(gf_client *c, gf_event *out); /* drain until GF_AGAIN */

/* session */
gf_result gf_client_connect(gf_client *c, const char *host, uint16_t port);
gf_result gf_client_disconnect(gf_client *c);

/* frames */
gf_result gf_client_acquire_frame(gf_client *c, gf_frame *out);
void      gf_client_release_frame(gf_client *c, uint32_t frame_id);

/* input -- coordinates are REMOTE framebuffer pixels, not window pixels */
gf_result gf_client_push_pointer_motion(gf_client *c, int16_t x, int16_t y);
gf_result gf_client_push_pointer_button(gf_client *c, int16_t x, int16_t y,
                                        uint8_t button, bool down);
gf_result gf_client_push_wheel(gf_client *c, int16_t dx, int16_t dy);
gf_result gf_client_push_key(gf_client *c, uint32_t keysym, bool down);
```

### `gf_client_config`

```c
typedef struct {
  uint32_t        struct_size;
  const char     *hostname;        /* tsnet node name */
  const char     *state_dir;
  bool            supports_h264;   /* false until M3 */
  bool            indices_raw;
  uint32_t        n_export_buffers;/* default 3 */
  /* Modifier negotiation: the host passes what its consumer can import,
     most-preferred first. Empty means "library picks", which will prefer
     DRM_FORMAT_MOD_LINEAR. See 5.3. */
  uint32_t        n_preferred_modifiers;
  const uint64_t *preferred_modifiers;
} gf_client_config;
```

**Allocation timing.** The remote resolution is not known until the server sends
it, so export buffers are allocated on the first `GF_EVENT_RESIZED`, not at
`gf_client_create`. The config's `preferred_modifiers` are recorded at create and
consulted at allocation.

This imposes an ordering on the host: connect to the display server and read its
supported modifiers *first*, then `gf_client_create`. On Wayland that means
binding `zwp_linux_dmabuf_v1` and reading `DmabufFeedback` before creating the
client.

### `gf_frame`

```c
typedef struct {
  uint32_t       struct_size;
  uint32_t       frame_id;     /* pass back to gf_client_release_frame */
  uint32_t       buffer_id;    /* 0..n-1, STABLE -- cache your import against this */
  gf_handle_type handle_type;  /* GF_HANDLE_DMABUF | WIN32_NT | IOSURFACE | CPU */
  uint32_t       width, height;
  uint64_t       drm_modifier;
  uint32_t       n_planes;
  struct { int fd; uint32_t offset; uint32_t stride; } planes[4];
  int            acquire_fence_fd; /* sync_file; -1 if already signalled */
  uint32_t       n_damage;
  const gf_rect *damage;       /* merged rects; valid until release */
} gf_frame;
```

`handle_type` is tagged from day one so a Windows (`WIN32_NT`) or macOS
(`IOSURFACE`) port is an internal change rather than an API break. This costs
nothing today and is the single most important portability decision in the design.

### Frame acquisition semantics

`gf_client_acquire_frame` returns `GF_AGAIN` when no new frame is ready; it never
blocks. A `GF_EVENT_FRAME_READY` event means one is waiting.

If the host holds every export buffer, the library keeps decoding into its private
framebuffer and simply does not publish. Nothing stalls and nothing is lost -- the
next buffer the host releases is filled with the accumulated damage since that
buffer was last written. A slow host therefore drops intermediate frames rather
than throttling the session.

### Ownership rules

These are the classic way such APIs leak, so they are normative:

- **Plane fds are owned by the library.** They stay valid until the buffer set is
  torn down (resize or destroy). The host must not close them; `dup()` for a
  longer life. `buffer_id` is stable precisely so the host imports N buffers once
  and caches, rather than importing per frame.
- **`acquire_fence_fd` is owned by the host** and must be closed. It is per-frame.
- **`damage` points into library memory** and is valid only until
  `gf_client_release_frame`.

### Events

`GF_EVENT_FRAME_READY`, `GF_EVENT_RESIZED`, `GF_EVENT_CONNECTED`,
`GF_EVENT_DISCONNECTED`, `GF_EVENT_ERROR`.

### Threading contract

Any thread may call `gf_client_*`, but not concurrently. One thread drains events.

### Coordinates

Input takes remote-framebuffer coordinates. The host owns the window and therefore
owns any scaling; the library publishes the remote resolution via `GF_EVENT_RESIZED`.

## 5. GPU pipeline and dmabuf export

### 5.1 Device construction

wgpu will not enable `VK_EXT_external_memory_dma_buf`,
`VK_EXT_image_drm_format_modifier`, or `VK_KHR_external_memory_fd` on request. So
we build the `VkInstance` and `VkDevice` with ash, enabling what we need, and hand
them up:

```
wgpu::Instance::from_hal -> create_adapter_from_hal -> create_device_from_hal
```

All three are confirmed present in current wgpu. Everything above that line is
ordinary safe wgpu.

**This is the first spike in M1.** If it does not work, the stack choice is wrong
and we want to know in week one. Fallback is pure ash, which costs the macOS hedge.

### 5.2 Shader single-source-of-truth

The point of this client is to stop having two decoders. Move the WGSL from
`ghostframe-web-client/src/webgpu/shaders/` to a top-level `shaders/client/`,
referenced by vite's `?raw` imports and by `include_str!` in `client-gpu`. A
mechanical change that makes the shared-source property structural rather than a
convention someone can quietly break.

### 5.3 Export ring and modifier negotiation

Export images are built in ash:

- `VkExternalMemoryImageCreateInfo(handleTypes = DMA_BUF_BIT_EXT)`
- modifiers enumerated via `vkGetPhysicalDeviceImageFormatProperties2` with
  `VkDrmFormatModifierPropertiesListEXT`
- `VkImageDrmFormatModifierListCreateInfoEXT` narrowed to the intersection of what
  the device supports and what the host passed in `preferred_modifiers`
- `VkExportMemoryAllocateInfo`, then `vkGetMemoryFdKHR` for the fd
- `vkGetImageDrmFormatModifierPropertiesEXT` for the chosen modifier and
  `vkGetImageSubresourceLayout` per plane for offset/stride

then wrapped back through `wgpu_hal::vulkan::Device::texture_from_raw` +
`wgpu::Device::create_texture_from_hal`, so the blit is a normal wgpu copy.

If the intersection is empty, fall back to `DRM_FORMAT_MOD_LINEAR`; if that also
fails, `gf_client_create` errors rather than handing out a buffer the consumer
cannot import.

On Wayland the host obtains its list from SCTK's `DmabufFeedback`, which is why
this is real negotiation rather than a guess.

### 5.4 Internal framebuffer

A persistent `rgba8unorm` texture mirroring `Framebuffer.resize` in
`ghostframe-web-client/src/webgpu/framebuffer.ts`, **including the
preserve-on-resize copy** -- without it, tiles written before a late
sentinel-driven resize are lost.

### 5.5 Synchronisation: a deliberate v1 simplification

**Corrected 2026-09-22 against wgpu 30.0.1.** This section originally said wgpu
cannot signal a semaphore on submit. That is false: `wgpu_hal::vulkan::Queue`
exposes `add_signal_semaphore` and `add_wait_semaphore`
(`wgpu-hal-30.0.1/src/vulkan/mod.rs:1522-1560`), so an exportable binary
semaphore can be signalled on the blit submission and turned into a `sync_file`
fd with `vkGetSemaphoreFdKHR`.

M1 still ships the simple version — `device.poll(PollType::wait_indefinitely())`
after the blit, reporting `acquire_fence_fd = -1` (already signalled). It is
correct, the copy is small, and it keeps the export ring focused. The field
exists from day one so exporting a real fence later is not an API break.

The difference is that this is now a choice, not a limitation. The upgrade is a
contained change to `ExportRing::publish` plus one more device extension
(`VK_KHR_external_semaphore_fd`), and it is the first optimisation to make if
frame pacing shows the stall.

## 6. Damage tracking

A bit per tile over the 32x32 grid -- 60x34 = 2040 bits = 255 bytes at 1080p.

**Dirty is recorded by the renderer when it writes a tile, not derived from
`frame_seq`.** A CDF 5/3 refinement pass changes the framebuffer without a new
frame; deriving damage from the protocol would silently drop those updates.

- A 16-entry ring of dirty maps (4 KB total), indexed by a monotonic generation.
- Each export buffer records `filled_at_gen`.
- Filling buffer B ORs the maps in `(B.filled_at_gen, current_gen]`.
- If B is older than the ring, full blit.
- A buffer that has never been filled, or that belongs to a buffer set created
  after a resize, gets a full blit. `filled_at_gen` is unset for both.

Coalescing merges horizontal runs per tile row, then merges vertically adjacent
runs with identical x-extent. The resulting rects drive both the
`copy_texture_to_texture` calls and the `damage` array handed to the host, which
the host can pass straight to `wl_surface.damage_buffer`.

## 7. H.264

`h264_blit.wgsl` **cannot be reused.** It is built on `texture_external` and
`textureSampleBaseClampToEdge`, which are WebGPU-only types with no native
equivalent.

The native path:

ffmpeg + VA-API hwaccel decodes to `AVFrame(AV_PIX_FMT_VAAPI)`;
`vaExportSurfaceHandle(DRM_PRIME_2)` yields an NV12 dmabuf. Rather than fight
Vulkan's ycbcr sampler conversion -- which wgpu's bind-group model cannot express
anyway -- **import the same dmabuf twice**: plane 0 as `R8Unorm`, plane 1 as
`Rg8Unorm`, at their respective offsets. BT.709 limited-range YUV to RGB happens
in a new `h264_nv12_blit.wgsl`. No ycbcr extension needed, expressible in plain
wgpu.

**Consequence, stated plainly:** this one shader is native-only and has no browser
counterpart. It is the single place the two clients genuinely diverge. Everything
else -- solid, palrle, cdf53 integrate and inverse l1/l2/l3, present_blit -- is
shared source. Gate it with a test that decodes a known clip both ways and
compares, so the divergence is measured rather than assumed.

## 8. Transport and tsnet lifecycle

### 8.1 Session bring-up

`gf_client_connect(host, port)`:

1. `GhostbridgeHandle::dial_tcp(host:port)`, `GET /config.json`, parse `certHash`.
   This endpoint already exists: `ghostbridge/web_server.go` serves it and
   `ghostframe-web-client/src/bootstrap.ts` consumes it. No protocol change.
2. `dial_udp(host:port)` for the QUIC byte pump.
3. `ClientNet::new` with the pinned `server_cert_sha256`.

Every byte goes through `ghostframe-tsnet`. No socket API is added anywhere. The
standing constraint is that the protocol and public API must never permit escaping
to a direct socket connection; the module boundary that enforces this is unchanged.

### 8.2 Threads

**Net thread**: epoll over the UDP fd, a timerfd for `ClientCore::poll_timeout`,
and a wake eventfd. Owns `ClientNet`, `ClientCore`, and all ACK/NACK timing.

**Render thread**: owns the GPU, consumes a queue of `TileData`.

Two threads rather than one so that GPU stalls -- including the v1 `poll(Wait)` --
do not land inside transport timing. Much of the M3 stack is timing-sensitive.
Plain epoll rather than tokio also keeps us clear of the FFI-plus-tokio-runtime
lifecycle trap.

### 8.3 New ghostbridge exports

- `gbridge_login_url(sd, buf, len)` -- surfaces the Tailscale auth URL.
- `gbridge_logout(sd)` -- `LocalClient().Logout(ctx)`, so the node leaves the
  tailnet rather than being orphaned by a deleted state dir.

Implementation must check the exact `tsnet` API against the version pinned in
`ghostbridge/go.mod`. Interactive login is `StartLoginInteractive` plus status
polling in some versions and a blocking `Up(ctx)` with a readable `AuthURL` in
others.

## 9. CLI

State lives in `$XDG_STATE_HOME/ghostframe/tsnet` (default
`~/.local/state/ghostframe/tsnet`).

- `ghostframe login [--authkey K] [--login-server URL] [--hostname H]` --
  with no authkey, prints the auth URL and waits for the node to come up.
- `ghostframe logout` -- real logout, then removes local state.
- `ghostframe connect <host> [--port N]` -- requires seeded state; brings tsnet up,
  connects, opens the window.

## 10. Showcase

Backend chosen at runtime: `WAYLAND_DISPLAY` then `DISPLAY`, else error.

The two backends are **not symmetric in maintenance cost**, and we accept that
deliberately rather than hand-rolling both for symmetry.

### Wayland -- almost entirely third-party

`smithay-client-toolkit` 0.21 provides `dmabuf` (`DmabufState`, `DmabufParams`,
`DmabufFeedback`), `seat::keyboard` (behind the `xkbcommon` feature, with key
repeat via calloop), `shell` for xdg-shell, and registry/globals. Our code is
roughly: build a `wl_buffer` per `buffer_id` from `DmabufParams`, then
`attach` + `damage_buffer` + `commit`.

`DmabufFeedback` supplies the compositor's preferred format/modifier tranches,
which we pass into `gf_client_config.preferred_modifiers`.

Keysyms need **no translation table**: SCTK yields `xkeysym::Keysym`, and
`Keysym::raw() -> RawKeysym` (`u32`) is exactly the X11 keysym the wire carries.
This is the one place the native client is simpler than the browser, which needed
`keymap.ts`.

### X11 -- hand-written, no alternative

No DRI3/Present helper crate exists on crates.io. The floor is `x11rb` (already a
dependency of `ghostframe-xdaemon`, with `dri3` already enabled) plus the
`xkbcommon` crate's `x11` feature:

- `dri3::pixmap_from_buffers` with the modifier, one `Pixmap` cached per
  `buffer_id`.
- `present::pixmap` with a damage region.
- keycode to keysym via `xkbcommon::xkb::x11`.

Roughly 150 lines. If that proves burdensome, dropping the X11 backend is a
cheaper option than replacing it.

### Window and coordinates

The window opens at the remote resolution on the first `RESIZED` and maps 1:1.
Scaling is an explicit non-goal; it would add a coordinate-math bug class to code
whose only job is to prove the API.

### Quit chord

`Super+b` then `d`. A two-state machine. **Every key including `Super+b` is
forwarded normally; only the final `d` is swallowed.** This keeps input latency and
ordering untouched at the cost of the remote occasionally seeing a stray `b` --
the same bargain tmux makes.

`--quit-chord` allows an override, because many compositors grab Super combos
before an application ever sees them. Window close always works regardless.

## 11. Telemetry and testing

`tracing` throughout, `GHOSTFRAME_LOG` filter, stderr subscriber in the CLI. Client
telemetry becomes greppable alongside server telemetry instead of being pasted out
of a browser console -- the concrete complaint that motivated this work.

Each new crate gets a single `config.rs` as the only place that reads env, matching
the guard CI already enforces on `ghostframe-lib`.

### Tests

- **`client-gpu` framebuffer assertions.** Feed synthetic tiles, assert on the
  *exported dmabuf contents*, CPU-mapped with `DMA_BUF_SYNC` (cross-GPU PRIME
  import is known to yield stale bytes here). This is the first time the real WGSL
  executes under test.
- **Damage coalescing proptest**: the merged rect list covers exactly the union of
  dirty tiles -- no more, no less.
- **`client-native`** driven against the existing e2e harness and netsim.
- **H.264 cross-check** (M3): decode a known clip natively and in the browser,
  compare, so the one divergent shader is measured.
- **Mutation check**: mutate out a known fix and confirm the new GPU tests fail.
  A test that passes for the wrong reason is worse than no test.

## 12. Milestones

**M1 -- library, GPU, export.** `from_hal` spike first. Then `client-gpu`,
`client-native`, `client-capi` + header, headless framebuffer tests.
`supports_h264 = false`. Deliverable: a test binary that connects to a test server
and asserts pixels.

**M2 -- CLI and showcase.** ghostbridge login/logout exports, tsnet wrappers, CLI,
both window backends, quit chord. Deliverable: watch a real session.

**M3 -- H.264.** VA-API decode, NV12 dual-plane import, `h264_nv12_blit.wgsl`,
browser cross-check. Flip `supports_h264 = true`.

Each milestone is a reviewable branch.

## 13. Risks

Most likely first.

1. **The `from_hal` spike fails, or wgpu version churn breaks the escape hatch.**
   Fallback is pure ash, which costs the macOS hedge. Mitigated by spiking first.
2. **DRM modifier mismatch with the consumer.** Mitigated by real negotiation
   through `preferred_modifiers` plus a LINEAR fallback, and by failing loudly at
   create time rather than handing out an unusable buffer.
3. **NVIDIA's proprietary driver** is historically weaker than Mesa on dmabuf
   modifiers. May force LINEAR there.
4. **Compositors swallow Super combos**, making the documented quit chord
   unreachable. Mitigated by `--quit-chord`.
5. **The Metal/IOSurface wrap is unverified.** wgpu-hal documents `texture_from_raw`
   for Vulkan and GLES; a Metal equivalent was not confirmed. Only bites if macOS
   actually happens; spike before committing to it.

## 14. Spikes and open items

- **S1 (blocking, M1 first task):** `wgpu::Instance::from_hal` through
  `create_device_from_hal` with our own extension list, on RADV.
- **S2 (M2):** exact `tsnet` login/logout API in the pinned tailscale version.
- **S3 (deferred):** Metal `texture_from_raw` equivalent, only if macOS is scheduled.
- **Independent of this work:** the handoff's capture-vs-client diff
  (`GHOSTFRAME_DUMP_FRAME` against the client framebuffer). Cheap, and if the
  server's capture is already coarse it redirects the open bug hunt. Not a gate on
  the library.
