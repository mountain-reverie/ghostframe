# M3.3b — CDF 5/3 Client-Side Decode + Default Flip — Design

**Date:** 2026-05-28
**Milestone:** M3.3b — second slice of the M3.3 "CDF 5/3 + progressive refinement" pair. Lands WebGPU client decode, flips the `GHOSTFRAME_ENABLE_CDF53` default to on, and swaps the classifier's high-color default from Raw to Cdf53.
**Umbrella reference:** `docs/superpowers/specs/2026-04-28-m3-codec-suite-design.md` § Phase M3.3.
**Predecessor:** `docs/superpowers/specs/2026-05-25-m3.3a-cdf53-server-design.md` — the wire format, scheduler, and server encoder are unchanged. This spec adds nothing to the wire protocol; it consumes what M3.3a emits.

## Context

After M3.3a, the server emits `Codec::Cdf53 (6)` datagrams behind the `GHOSTFRAME_ENABLE_CDF53` env flag AND the client's HELLO `supports_cdf53` bit. The client currently advertises the capability but drops Cdf53 datagrams silently — `__ghostframeRecordedCodecs` registers them but no decode runs. The reference Rust implementation (`encoder/cdf53.rs`) provides `forward`, `inverse`, `encode_passes`, `decode_passes`, and `rle_decode` as the algorithmic source of truth for porting to WGSL + TypeScript.

The M3.3a spec's Out of Scope section explicitly defers client decode to this cycle with the direction "GPU/WebGPU client decode wherever meaningfully possible — the bulk inverse transform belongs on WebGPU compute; tiny per-pass preprocessing (RLE unpack, bit-plane reassembly) may stay CPU if compute-dispatch overhead exceeds the work. The exact split is M3.3b's brainstorm."

This spec settles that split and lays out the integration shader, the inverse-transform shader trio, the dispatch lifecycle, the default flip, and the test plan.

## Goal

Three deliverables, with the e2e lossless build-up test as the milestone's anchor:

1. **WebGPU client decode** that consumes the 14-pass Cdf53 wire stream and reconstructs lossless BGR pixels into the framebuffer texture, including progressive refinement visible across passes.
2. **Default flip** — `cdf53_enabled` defaults to on; classifier Rule 8 swaps high-color tiles from `Raw` to `Cdf53`.
3. **Safety nets preserved** — Raw stays as the wire codec for stale-client fallback (HELLO bit absent) and for CPU-mode emission (M3.1 D13); `GHOSTFRAME_ENABLE_CDF53=0` opt-out keeps working.

End state: with default settings, the server emits Cdf53 for every high-color tile and the client reconstructs them losslessly on the GPU. Stale M3.2-era clients without the HELLO bit still receive Raw and render correctly. `e2e_cdf53_lossless_buildup` proves end-to-end correctness against a Rust-computed golden.

## Architecture

### Work split — CPU vs GPU

| Step | Where | Why |
|---|---|---|
| Wire parsing (datagram header, tile header) | CPU (JS) | Tiny, serial, already runs in `main.ts` for every codec. |
| RLE unpack (per-channel bit-plane bytes → 128 bytes) | **CPU (JS)** | Serial state machine; per-pass payload ≤ ~280 bytes typically < 50; JS handles in microseconds; compute-shader port would need single-invocation kernel or prefix-scan rewrite. |
| Generation-bump detection + per-tile state clear | GPU (compute) | One atomic load per tile per batch + conditional clear; cheap. Keeps state authority on the GPU. |
| Bit-plane integration (OR into coefficient buffer) | GPU (compute) | Embarrassingly parallel — 3072 ORs per pass. Perfect for GPU. |
| Inverse CDF 5/3 lifting (3 levels) | GPU (compute) | 10K invocations per tile per refinement. The original target for the GPU-first principle. |
| Pixel write into framebuffer | GPU (compute) | Same compute pass as the L1 inverse; `textureStore` to the shared `rgba8unorm` framebuffer. |

### State that survives across frames

Three GPU buffers, allocated once at `Cdf53Pipeline.resize(maxTiles, …)` and cleared on session reset:

- **`coefficientBuffer: GPUBuffer`** — `max_tiles × 3 channels × 1024 × i16`, packed as two i16 lanes per `u32`. At `max_tiles = 1024` that's 6 MB. DEVICE_LOCAL.
- **`signBuffer: GPUBuffer`** — `max_tiles × 3 × 1024` sign bits, packed as `u32` words; `max_tiles × 384 bytes` total. DEVICE_LOCAL.
- **`tileGenBuffer: GPUBuffer`** — `max_tiles × u32`, most-recently-seen generation per tile.

Coefficient encoding mirrors the server's i16-backed-by-i32 storage layout (WGSL has no native `i16` storage type). Both forward (server, M3.3a) and inverse (client, this milestone) shaders share the same packing — same per-channel layout `[LL3 4×4][HL3 4×4][LH3 4×4][HH3 4×4 | HL2 8×8 LH2 8×8 HH2 8×8 | HL1 16×16 LH1 16×16 HH1 16×16]` documented in `cdf53.rs:35–101`.

### Per-frame data flow

Inserted into `WebGpuRenderer.encodeAndPresentFrame` between the existing PalRle compute pass (Step 7) and the Solid/H264 render pass (Step 8):

```
rAF tick
  Step 0 (existing): drain palRleQueue, prevalidate, etc.
  ...
  Step 6 (existing): encoder = device.createCommandEncoder()
  Step 7 (existing): palrlePipeline.encodeDispatch(encoder, palRleCount)
  Step 7.5 (new): cdf53Pipeline.uploadBatch(cdf53Queue)
                  – writeBuffer tileWork + concatenated bit-planes
                  – writeBuffer dirtyTilesCount := 0 (atomic counter reset)
  Step 7.6 (new): cdf53Pipeline.encodeIntegrate(encoder, batchSize)
                  – one compute pass, dispatchWorkgroups(batchSize)
                  – per-workgroup: detect gen bump → clear if needed
                                   → OR bit-planes into coefficient/sign buffers
                                   → atomicAdd into dirtyTiles list
  Step 7.7 (new): cdf53Pipeline.encodeInverse(encoder)
                  – three compute passes: L3 inverse → L2 inverse → L1 inverse
                  – indirect dispatch driven by dirtyTilesCount (no CPU readback)
                  – L1's final invocation textureStore's pixels into framebuffer
  Step 8 (existing): Solid + H264 render pass
  Step 9 (existing): present-blit
  ...
```

The indirect-dispatch buffer holding `dirtyTilesCount` is updated via `copyBufferToBuffer` from the integration shader's atomic counter — keeps the dispatch driven entirely by GPU state, no CPU stall.

## Components

### 1. `prevalidate_cdf53.ts`

```ts
export interface PrevalidatedCdf53 {
  tileX: number;
  tileY: number;
  gen: number;     // 0..15
  passIdx: number; // 0..13
  bitPlanes: Uint8Array; // 384 bytes = [B 128][G 128][R 128]
}

export interface Cdf53Result {
  ok: true;
  entry: PrevalidatedCdf53;
} | {
  ok: false;
  errorCode: number; // ERR_CDF53_* enum
}

export function prevalidateCdf53(
  payload: Uint8Array,
  gen: number,
  passIdx: number,
): Cdf53Result;

export function rleDecode(rle: Uint8Array): Uint8Array;
```

**Steps inside `prevalidateCdf53`:**

1. Validate `passIdx < 14`. Reject with `ERR_CDF53_BAD_PASS` otherwise.
2. Walk three `[u16 BE len][len bytes RLE]` triples in B, G, R order.
3. For each triple: validate `offset + 2 + len ≤ payload.length`. Reject with `ERR_CDF53_TRUNCATED` if not.
4. Call `rleDecode(rle)` for the channel; reject with `ERR_CDF53_RLE_LENGTH` if result is not exactly 128 bytes.
5. Pack the three decoded planes into `bitPlanes: Uint8Array(384)` and return.

**`rleDecode` semantics** (port of `cdf53.rs:rle_decode`):
- Token `0x80..=0xFF`: zero run of `(token & 0x7F) + 1` bytes (1..=128 zeros).
- Token `0x7F`: two-byte literal escape — next byte is the actual literal value (used when literal would collide with the zero-run prefix).
- Token `0x00..=0x7E`: literal byte.

### 2. `webgpu/cdf53.ts` — `Cdf53Pipeline` class

Mirrors `PalRlePipeline` in API shape:

```ts
export class Cdf53Pipeline {
  constructor(device: GPUDevice, presentFormat: GPUTextureFormat);

  /** Allocate per-tile buffers + rebuild bind groups. Called from
   *  WebGpuRenderer.resize. */
  resize(maxTiles: number, framebufferView: GPUTextureView): void;

  /** Pack tileWork + bit-planes for a batch of prevalidated passes. */
  uploadBatch(entries: readonly PrevalidatedCdf53[]): number; // returns batchSize

  /** Encode the integration compute pass (bit-plane OR + gen-bump clear). */
  encodeIntegrate(encoder: GPUCommandEncoder, batchSize: number): void;

  /** Encode the three inverse-level compute passes; L1 writes to framebuffer. */
  encodeInverse(encoder: GPUCommandEncoder): void;

  /** Zero all per-tile state. Called from WebGpuRenderer.onSessionReset. */
  clearAllState(): void;
}
```

### 3. `cdf53_integrate.wgsl` — integration shader

**Bindings:**
- `@binding(0)` `tileWork: array<TileWorkEntry>` (read) — `(tileX, tileY, gen, passIdx, bitPlanesOffset)` per pass entry.
- `@binding(1)` `bitPlanes: array<u32>` (read) — concatenated 96-u32 slots per pass.
- `@binding(2)` `coefficientBuffer: array<atomic<u32>>` (read_write) — per-tile coefficients (two i16 per u32).
- `@binding(3)` `signBuffer: array<atomic<u32>>` (read_write) — per-tile sign bits.
- `@binding(4)` `tileGen: array<atomic<u32>>` (read_write) — per-tile current generation.
- `@binding(5)` `dirtyTiles: array<u32>` (read_write) — output tile indices.
- `@binding(6)` `dirtyTilesCount: atomic<u32>` (read_write) — output count.

**Workgroup geometry:** `@workgroup_size(64)`, dispatch `(batchSize, 1, 1)`. One workgroup per queued pass entry.

**Per-workgroup logic:**

1. Read `entry` for this workgroup; compute `tile_idx = entry.tileY * cols + entry.tileX`.
2. **Generation-bump detection** — invocation 0 atomically loads `tileGen[tile_idx]`. If `prev_gen != entry.gen`, atomicStore the new gen, set workgroup-shared `should_clear = 1u`. workgroupBarrier.
3. **Conditional clear** — if `should_clear`, all 64 invocations strided-clear the tile's coefficient and sign buffer slots. workgroupBarrier.
4. **Bit-plane integration** — strided across the 1024 coefficients per channel × 3 channels:
   - Load bit from `bitPlanes[entry.bitPlanesOffset + ch*32 + i/32] >> (i % 32) & 1`.
   - If `pass_idx == 0`: atomicOr into `signBuffer[tile_idx * 96 + ch * 32 + i / 32]` at bit `(i % 32)`.
   - Else: compute `bit_pos = 13 - pass_idx`; atomicOr `(1u << bit_pos)` (or `<<16` if `i` is odd, packing low/high i16 lane) into `coefficientBuffer[tile_idx * 1536 + ch * 512 + i / 2]`.
5. Invocation 0 appends `tile_idx` to `dirtyTiles` via `atomicAdd(&dirtyTilesCount, 1u)`.

The `dirtyTiles` list may contain duplicates if multiple passes for the same tile arrive in the same batch. The inverse pipeline reads from `coefficientBuffer` + `signBuffer` and writes only to the framebuffer texture (intermediate level results live in workgroup-shared memory or a scratch buffer that's overwritten per run, never back into `coefficientBuffer`). That makes repeated processing of the same tile in one frame idempotent — running the inverse N times produces the same pixels. Wasted GPU work is bounded by `passes_in_batch` and is small in practice (typical batches have 10–20 passes spread across that many distinct tiles); GPU-side dedup is a future optimization gated on profiling.

### 4. `cdf53_inverse_l{1,2,3}.wgsl` — inverse-transform shaders

Three shaders, one per decomposition level, running in the order **L3 → L2 → L1**. Each is the inverse of the corresponding server-side forward shader (`cdf53_forward_l{1,2,3}.comp`).

**Bindings (shared across all three):**
- `@binding(0)` `coefficientBuffer: array<u32>` (read) — input coefficients.
- `@binding(1)` `signBuffer: array<u32>` (read) — input signs.
- `@binding(2)` `dirtyTiles: array<u32>` (read) — list of tiles to process.
- `@binding(3)` `framebuffer: texture_storage_2d<rgba8unorm, write>` — L1 only; L3/L2 omit.
- For L1, an additional read_write `workArea: array<u32>` storage to hold intermediate per-tile results across level boundaries (alternative: store level-N inverse outputs back into a scratch slice of `coefficientBuffer`; chosen approach in plan).

**Workgroup geometry:**

| Shader | workgroup_size | Dispatches |
|---|---|---|
| `cdf53_inverse_l3.wgsl` | `(8, 8, 1)` = 64 | `(dirtyTilesCount, 1, 1)` |
| `cdf53_inverse_l2.wgsl` | `(16, 16, 1)` = 256 | `(dirtyTilesCount, 1, 1)` |
| `cdf53_inverse_l1.wgsl` | `(16, 16, 1)` = 256 | `(4 × dirtyTilesCount, 1, 1)` (4 workgroups per tile, one per quadrant) |

All three stay at or below the 256-invocation portability cap that bit M3.2c. Workgroup_size 256 is the largest safe value across Mesa Vulkan and the SwiftShader fallback path (which we still want to keep compatible even though it's no longer the test client).

**Per-invocation logic** (L1 sketch — the others are size-shrunk versions of the same inverse-lifting steps):

```wgsl
@compute @workgroup_size(16, 16, 1)
fn inverse_l1(@builtin(workgroup_id) wg: vec3u,
              @builtin(local_invocation_id) lid: vec3u) {
    let tile_slot = wg.x / 4u;
    let quadrant  = wg.x % 4u;
    let tile_idx  = dirtyTiles[tile_slot];

    // For each of B, G, R:
    //   1. Reassemble sign + magnitude into signed coefficient (i32).
    //   2. Unpack channel layout into work[16][16] for this quadrant.
    //   3. Inverse vertical pass: reinterleave + inverse update + inverse predict.
    //   4. Inverse horizontal pass: same on rows.
    //   5. Write reconstructed pixel via textureStore.

    let fb_x = wg.x_tile * 32u + quadrant_x * 16u + lid.x;
    let fb_y = wg.y_tile * 32u + quadrant_y * 16u + lid.y;
    textureStore(framebuffer, vec2u(fb_x, fb_y), vec4f(r, g, b, 1.0));
}
```

The inverse lifting formulas port verbatim from `cdf53.rs:row_inverse` lines 194–215. Mirror-boundary handling at `i == 0` and `i + 1 >= n` ports verbatim too — small `select()` branches.

**Why three shaders, not one:** the natural problem decomposition has each level read its predecessor's output as input. WebGPU's storage-buffer happens-before is guaranteed across compute passes (not within a single pass), so we use three back-to-back passes. Workgroup-size pressure also benefits — fitting all three levels into one workgroup would push past 256 invocations on the outermost level.

## Lifecycle

### Generation handling

The server bumps a tile's generation when its content changes substantially (`bump_generation`); all in-flight passes for the prior gen are superseded and the new gen's passes start fresh. On the client, the integration shader's first action per pass is to compare the incoming gen against `tileGenBuffer[tile_idx]` and clear the tile's coefficient + sign state on mismatch. This is the only state-clearing trigger during normal operation — it covers both server-driven content changes and out-of-order pass arrival within a gen (clears are idempotent if `prev_gen == new_gen`).

### Session reset

`renderer.onSessionReset` calls `cdf53Pipeline.clearAllState()` which writeBuffer-zeros all three persistent buffers. This handles transport disconnect/reconnect — server's `fire_session_reset` already clears its side, so both ends start the new session with empty coefficient state. Matches the existing PalRle palette atlas clear in `WebGpuRenderer.onSessionReset`.

### Resize / resolution change

`Cdf53Pipeline.resize(maxTiles, framebufferView)` follows the existing PalRle resize discipline: destroy old buffers if `maxTiles` grew, allocate new ones, rebuild bind groups. The framebuffer view binding for the inverse shader's `textureStore` is rebuilt every resize since the texture handle itself is recreated.

The pre-existing `e2e_resolution_change` test (currently `#[ignore]`'d for encoder lazy-init reasons documented in `project_resolution_change_blockers.md`) stays ignored; M3.3b doesn't unblock it.

## Testing

### TypeScript vitest unit tests

1. **`prevalidate_cdf53.test.ts` — happy-path roundtrip.** Load `cdf53_fixture.json`, call `prevalidateCdf53` on each of the 14 encoded passes, assert the unpacked `bitPlanes` match the fixture's `expected_bit_planes`.
2. **Malformed-input rejections.** Three test cases, one per error code: `passIdx >= 14` (`ERR_CDF53_BAD_PASS`), truncated payload (`ERR_CDF53_TRUNCATED`), RLE that decodes to ≠ 128 bytes (`ERR_CDF53_RLE_LENGTH`).
3. **All-zero bit-plane.** `rleDecode(Uint8Array.from([0xFF]))` → 128 zero bytes (single zero-run token of length 128).
4. **`rleDecode` direct roundtrip.** Encode random byte sequences via a JS-side `rleEncode` helper (parallel to `cdf53.rs:rle_encode`), feed through `rleDecode`, assert byte-equal.

### Rust unit tests

5. **Fixture generator** (`#[cfg(test)] fn write_fixture()`). One-shot helper that runs `make_test_tile(0xCDF5_3B)` → `forward` → `encode_passes`, plus computes each pass's pre-RLE bit-plane bytes, and serializes everything to `ghostframe-e2e/tests/fixtures/cdf53_fixture.json`. Gated behind a `GHOSTFRAME_REGENERATE_CDF53_FIXTURE=1` env var so it doesn't run by default but can be regenerated when the algorithm changes.

### WGSL shader correctness tests

6. **Integration shader vs CPU reference.** TS test: instantiate `Cdf53Pipeline`, upload all 14 fixture passes for tile (0,0), run `encodeIntegrate`, read back the coefficient buffer slot via `copyBufferToBuffer` + `mapAsync`. Assert exact match against the fixture's `expected_coefficients`.
7. **Inverse shader vs CPU reference.** Pre-fill the coefficient buffer slot with `expected_coefficients`, run `encodeInverse` with `dirtyTiles = [0]`, read back framebuffer pixels for tile (0,0) via `__readPixelRect`. Assert per-pixel BGR match within ±1 LSB (rounding tolerance per the clamp-to-`[0,255]` in `cdf53::inverse`).
8. **Generation-bump clears state.** Upload passes 0..6 with `gen=1`, then pass 0 of `gen=2`. Read back coefficient buffer for the tile. Assert the slot contains only the gen-2 sign-plane contribution (no residual magnitude from gen 1).
9. **Truncated-pass monotonicity.** Loop K = 1..14: upload only passes 0..K-1, run inverse, read back pixels, compute sum-of-squared-error vs the fixture's `pixels`. Assert SSE decreases monotonically as K increases (mirrors `cdf53.rs:truncated_pass_error_monotone`).

### E2E tests

10. **`e2e_cdf53_lossless_buildup`** — the milestone's anchor test. Setup: `--gradient --drm-direct`, no env override (relying on the M3.3b default flip). Wait 8 s for the H264 burst + handoff + Cdf53 full 14-pass build-up. Sample 16 pixels via `__readPixel` from the gradient region. Compute the Rust golden by running `forward` + `inverse` on the same gradient pattern. Assert per-pixel BGR within ±1 LSB.
11. **`e2e_cdf53_progressive_visible`** — same setup. Sample pixels at t = 200ms, 600ms, 1.5s, 4s. Compute SSIM-vs-final at each sample point. Assert SSIM monotonically increases.
12. **`e2e_cdf53_default_on`** — `--gradient --drm-direct`, no env override. Assert `__ghostframeRecordedCodecs` contains `6` (Cdf53). Regression check for the flag flip.
13. **`e2e_cdf53_opt_out`** — same setup with `GHOSTFRAME_ENABLE_CDF53=0` (explicit opt-out). Assert no Cdf53 on wire; assert Raw (5) is present. Verifies the opt-out path.
14. **`e2e_cdf53_stale_client_fallback`** — synthesize a HELLO without the `supports_cdf53` bit via a test-only client hook (a `window.__ghostframeSuppressCdf53Cap = true` global checked in `feedback.ts` before HELLO encode). Assert server emits Raw for high-color tiles.
15. **Retire `e2e_cdf53_flag_off`** — replaced by `e2e_cdf53_opt_out`. The semantics are the same (env var off → no Cdf53), but the test name now reflects the post-flip world where "off" means "explicit opt-out" rather than "default".

### Diagnostic tracing

The existing server-side `cdf53.emit` tracing line stays. No new tracing added on the client side beyond what `DecodeErrorBatcher` already routes through.

## Out of scope

- **C6 proptest re-enable.** Classifier invariant requiring H.264 → idle transition via lossy intermediate codec. Was deferred from M3.3a; this milestone could enable it but needs a careful look at what "lossless within content" means once Cdf53 is the high-color default.
- **GPU bit-plane extraction on the server.** Server-side optimization — moving M3.3a's Phase B work to Vulkan compute. Only if M3.5 bench data motivates.

### Deferred to M3.5

- **`BenchEncoder` impl** for CDF 5/3 — `ghostframe-bench/benches/codec_latency.rs`.
- **Variable pass count per tile** (P3 from the original brainstorm).
- **Threshold tuning** based on bench data.

### Deferred indefinitely

- **Removing `Codec::Raw` from the wire enum.** Raw stays as wire codec for stale-client fallback (HELLO bit absent) and CPU-mode emission (M3.1 D13). The codec is de-emphasized in the classifier, not removed from the protocol.
- **Resolution-change support.** Pre-existing M3.2c blocker tracked in `project_resolution_change_blockers.md`. Cdf53 buffer resize on resolution change is included in this plan, but the underlying `e2e_resolution_change` test stays `#[ignore]`'d.

## Decision register

| # | Decision | Rationale |
|---|---|---|
| D1 | CPU does RLE unpack; GPU does bit-plane integration + inverse transform | Hybrid (B) from the brainstorm. RLE is serial state-machine, tiny per-pass payload. Integration + inverse are embarrassingly parallel. Matches PalRle's CPU-prevalidate + GPU-decode split. |
| D2 | Render after every received pass (progressive) | (A) from the brainstorm. Compute work is small (~10K invocations per tile per pass); the truncated-pass monotonicity test was designed to verify this; user sees the codec's whole value proposition (blurry → sharp build-up). |
| D3 | Three compute shaders for the inverse transform, one per decomposition level | Matches the server's M3.3a forward shader trio. Keeps each workgroup_size ≤ 256 (M3.2c portability lesson). Storage-buffer happens-before across compute passes gives us the level-to-level barrier for free. |
| D4 | Coefficient buffer packs two i16 per `u32` | WGSL has no native `i16` storage. Same packing the server uses; integration + inverse shaders share an unpack helper. |
| D5 | Sign and magnitude tracked in separate buffers | Mirrors the Rust `decode_passes` algorithm (signs accumulated separately, applied at final assembly). Lets pass 0 (sign plane) and passes 1..13 (magnitude) write to disjoint regions, avoiding cross-pass atomic contention. |
| D6 | Generation tracked per tile in a GPU buffer; bump detection inside the integration shader | Keeps state authority on the GPU; no CPU readback in the hot path. Atomic load + conditional clear is cheap. |
| D7 | Indirect dispatch for the inverse pass via `copyBufferToBuffer` of `dirtyTilesCount` | Same energy-efficient pattern as M3.3a's server-side `cdf53_indirect_args`. Idle tiles cost zero GPU cycles. |
| D8 | `GHOSTFRAME_ENABLE_CDF53` default flips from off → on; env var stays as opt-out | User direction. Production rollout enabled by default; opt-out preserved for ops staged rollback. |
| D9 | Classifier Rule 8 swaps from `Raw` to `Cdf53` for high-color tiles | User direction. Raw stays as the wire codec for stale-client fallback (HELLO bit absent) and CPU-mode emission. |
| D10 | Cross-language reference fixture (JSON file generated by Rust, consumed by both TS and WGSL tests) | Single source of truth for correctness. Encoded fixtures committed; regenerable behind a one-shot env var. |
| D11 | Three new decode-error codes (`ERR_CDF53_BAD_PASS`, `_TRUNCATED`, `_RLE_LENGTH`), reuses existing `DecodeErrorBatcher` | No new server-side feedback logic needed — existing `dispatch_feedback_bytes` already logs unknown codes via tracing. |
| D12 | Algorithmic source of truth = Rust `cdf53.rs` (already established in M3.3a) | This milestone ports the inverse to WGSL but adds no new algorithmic ground-truth. |
