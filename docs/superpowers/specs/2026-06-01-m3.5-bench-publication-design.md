## Context

M3.0–M3.3 shipped: frame-mode classifier, Solid/PalRle/Cdf53 codecs, scheduler with per-pass ACK, GPU compute forward + WebGPU inverse for Cdf53, progressive refinement to PixelPerfect. All four M3.3 sub-milestones merged to master on 2026-06-01 (commit `f5f96cb`); 29/29 e2e tests pass; 323/323 lib tests pass.

The umbrella M3.5 phase (defined in `2026-04-28-m3-codec-suite-design.md` lines 512–558) was scoped as a small "run the bench harness on real hardware → publish results → retune classifier constants → decide BC1's fate" milestone. This design **reshapes that scope** in response to the goals surfaced during 2026-06-01 brainstorming:

1. **End-to-end measurement, not micro-bench-only.** Per-codec encode µs in isolation misses scheduler/fragmenter/ACK/MTU/decoder overhead. The bench must run the real production pipeline against representative scenes and measure capture-to-paint latency plus server CPU/RSS/bandwidth.
2. **No BC1 implementation at all in M3.5.** The umbrella anticipated building "BC1 encoder behind the bench harness only" so M3.5 could measure BC1. This design drops that — BC1 stays absent in M3.5 and the "would BC1 help?" question is answered analytically from CDF53 measurements vs published BC1 operating points.
3. **Lossless-escalation strategy tuning is a first-class M3.5 output.** The umbrella treated M3.5 as pure constants tuning; this design adds an explicit strategy lever — pruning the escalation source-codec set (`{Bc1, PalRle, Solid}` → `{Bc1}`) — based on the bench finding that escalating already-lossless tiles is wasted compute.

## Architecture

### Two phases (a + b)

Mirrors the M3.3a/b/c/d cadence: each phase reviewable as one PR with one focused concern.

**M3.5a — Harness foundation.** Lands the plumbing. Extracts `ghostframe-e2e` test helpers into a public `harness` library, adds the missing `BenchEncoder` impls to the criterion micro-bench, builds the `codec_report` binary skeleton, instruments server + client telemetry. No classifier changes. No conclusions reached. Results doc is a stub with `TODO` cells.

**M3.5b — Run, interpret, tune.** Runs the bench, fills the results doc with real numbers, lands three surgical classifier commits (cost-model constants retune, escalation-set prune, per-class LZ4 default), runs the regression sweep. BC1 fate decided in the document.

### Two measurement layers

**Layer A — per-codec micro-bench** (existing `ghostframe-bench/benches/codec_latency.rs`, extended). Single tile in → bytes out, criterion measures encode µs, side channels record compressed bytes + SSIM. Feeds the classifier's `CostModel` placeholders with measured µs per codec.

**Layer B — e2e bench** (new `ghostframe-bench/src/bin/codec_report.rs`). Drives the real `ghostframe-xdaemon` + headless Chromium against scenes for a wall-clock window; measures capture→paint latency (two intervals, no clock sync needed), wire bandwidth, server CPU/RSS. Catches protocol-layer behavior the micro-bench can't see.

Both layers contribute to the same results document.

### Decision rule for BC1

The umbrella's "BC1 lands iff lower encode time AND smaller compressed size at equivalent SSIM for any content class" framing is replaced by a **class × SSIM-threshold matrix**. For each content class and each candidate SSIM threshold in `{0.85, 0.90, 0.95, 0.98}`, the matrix asks: would BC1 reach this threshold in fewer round-trips × bytes than CDF53's pass-K to hit the same threshold? BC1's operating point is its published GPU encode latency range + its fixed 512 bytes/tile. CDF53's operating point is measured from M3.5's bench.

BC1 lands iff ≥ 1 cell is unambiguously "yes" at both ends of BC1's published cost band. Otherwise BC1 is dropped from the `Codec` enum in M3.5b.

### Lossless-escalation strategy levers

Three levers, each tuned from bench data:

- **L1 — source-codec set.** Current code: `tile.codec_state ∈ {Bc1, PalRle, Solid}` triggers CDF53 escalation. Real answer: only codecs that leave a *lossy snapshot* on the canvas should escalate. PalRle and Solid are already lossless within feasibility. Pruned to `{Bc1}` (or `{}` if BC1 dropped) in M3.5b. Post-M3.4 if BC1 lands the set becomes `{H264-leftover, Bc1}` — the only lossy sources possible.
- **L2 — idle threshold.** Current code: `idle_frames > 30` (~0.5 s at 60 fps). M3.5b retunes to a single value driven by the time-to-PixelPerfect requirement.
- **L3 — refinement bandwidth fraction.** Current code: `refinement_bandwidth_fraction = 0.2`, static. M3.5b retunes from the CDF53 SSIM-vs-passes curve + measured bandwidth. Adaptive variants (RTT/loss-aware) are M4 work tied to the §6.5 estimator.

### Telemetry instrumentation

Two new server-side `tracing::info!` events, two extensions to the client-side diagnostics FIFO, plus external `/proc` sampling in the bench binary.

#### Server side

**Existing infrastructure:** `tracing::info!` macros scattered through `io_bridge.rs` (~10 per frame at 60 fps in current builds). Today they emit via the default `tracing-subscriber` text formatter. The bench switches the formatter to JSON via an env var (`GHOSTFRAME_LOG_FORMAT=json`) that `ghostframe-xdaemon::main` already could honor or trivially can; log level stays at the production default. The bench then captures xdaemon's stderr and parses JSON lines.

**Additions — two new events:**

1. **`frame.captured`** — emitted once per `frame_seq` after `drm_capture.rs::capture_via_modesetting_fb_cpu` completes the `DMA_BUF_IOCTL_SYNC` + memcpy and the classifier picks a mode. Fields: `frame_seq: u64`, `capture_done_ns: u64` (monotonic clock), `mode: "h264" | "tile"`.
2. **`frame.last_send`** — emitted once per `frame_seq` after the last fragment of that frame is handed to QUIC. Fields: `frame_seq: u64`, `last_send_ns: u64`, `total_wire_bytes: u32`, `tile_count: u16`, `codec_histogram: {solid: u16, palrle: u16, cdf53: u16, raw: u16, h264: u8}`.

No new sink abstraction. Both events use existing `tracing::info!`; gated by the existing `RUST_LOG` filter. Production overhead is two extra log lines per frame, dominated by the existing ~10 lines.

#### Client side

**Existing infrastructure:** `diagnostics.ts::recordTile(params)` captures per-tile metadata into a 32768-cap FIFO exposed on `window.__ghostframe_recordedTiles`. Bench reads via Chromium DevTools polling.

**Additions:**

1. **Extend `recordTile`** with two optional fields: `firstRecvNsClient?: number` (`performance.now()` at first fragment arrival), `lastPaintNsClient?: number` (`performance.now()` after `putImageData` / `drawSolidTile` returns). Optional → existing tests that don't care emit `undefined` and are unchanged.
2. **New `recordFramePainted({seq, rafNsClient})`** called from the first `requestAnimationFrame` callback after a frame's last tile has been painted. The "last tile" determination reuses `FragmentCoverageMap` (or its main.ts-side equivalent that tracks per-frame expected fragment count). New global `window.__ghostframe_framePaints` exposes the FIFO of paint records.

No new wire-protocol fields. Overhead: two `performance.now()` calls per tile + one per frame, below 50 µs/frame at 60 fps.

#### External `/proc` sampling

Implemented in the bench binary, not production. Per-scene tokio task polls `/proc/<xdaemon_pid>/status` and `/proc/<xdaemon_pid>/stat` every 100 ms. Records `ProcSample { wall_ns, utime, stime, rss_kb, vmhwm_kb }` into `SceneResult.proc_samples`. `utime`/`stime` in clock-ticks → seconds via `libc::sysconf(_SC_CLK_TCK)`. Pure-Rust `std::fs::read_to_string` parsing; no `procfs` crate dependency unless parsing complexity warrants it at implementation time.

#### Correlation

Bench joins server records (by `frame_seq` from `frame.captured` / `frame.last_send`) with client records (by `frame_seq` from `recordTile` / `recordFramePainted`). No cross-clock alignment: per-frame the bench computes **server interval** `(last_send_ns - capture_done_ns)` from server timestamps and **client interval** `(raf_ns - first_recv_ns)` from client timestamps, reports both separately and as a sum.

### Layer A criterion micro-bench additions

File touched: `ghostframe-bench/benches/codec_latency.rs` (existing 194 lines). Three new `BenchEncoder` impls + three new side channels.

**New `BenchEncoder` impls:**

1. **`SolidEncoder`** — wraps `ghostframe_lib::encoder::solid::encode_solid`. Returns empty Vec for non-feasible tiles.
2. **`Cdf53Encoder`** — wraps `cdf53::forward(tile) → encode_passes(coeffs)`; bench payload is the length-prefixed concatenation of all passes. Measures CPU forward + all bit-plane extraction. Used as the classifier's `cdf53_us` source.
3. **`Cdf53PerPassEncoder`** — same forward, emits only the first K passes (K parameterized via `BenchmarkId`). K ∈ 1..9. Used to populate the SSIM-vs-passes curve.

**Side channels** (separate from criterion's timing path; written to `target/criterion/m3-codec-side-channel.json`):

1. **`compressed_bytes`** per (codec, class, lz4_on_off).
2. **`ssim_per_class`** per (codec, class). For lossless codecs at feasible inputs: 1.0. For `Cdf53PerPassEncoder`: one row per K with reconstructed SSIM. Backed by `dssim-core`.
3. **`bytes_to_lossless`** for CDF53 only, per class. Sum of all 9 passes' compressed bytes.

SSIM and bytes-to-lossless work happens *outside* the criterion timing loop so it doesn't inflate latency numbers.

**Dependency add:** `dssim-core` to `ghostframe-bench/Cargo.toml` dev-dependencies. Pure Rust, no system deps.

**Acceptance:**
- `cargo bench -p ghostframe-bench --bench codec_latency -- --test` completes in CI mode.
- `cargo bench -p ghostframe-bench --bench codec_latency --features gpu-bench,m3` produces a criterion HTML report covering Solid/PalRle/Cdf53 × 6 classes × `+lz4` variants, plus a populated side-channel JSON file.
- New proptest in `ghostframe-lib::encoder::cdf53::tests` asserts the bench's "concatenate-passes → length-prefix-split → `decode_passes` → `inverse` → byte-exact original" round-trip.

### Layer B `codec_report` binary skeleton

File: `ghostframe-bench/src/bin/codec_report.rs` (~400 LoC). Depends on `ghostframe-e2e::harness` + `serde`/`serde_json` (side-channel ingest) + `clap` (CLI).

**CLI:**

```
codec_report \
  --output docs/specs/m3-codec-bench-results.md \
  --scene-duration 10s \
  --scenes solid,flat_ui,text,gradient,photo,motion,mode_switch \
  --gpu-name "AMD Radeon RX 7800 XT" \
  --reuse-criterion-json target/criterion/m3-codec-side-channel.json
```

All flags default; zero-arg invocation works. `--scenes` lets a single scene re-run. `--reuse-criterion-json` lets the binary stitch Layer A numbers into the report without re-running criterion.

**Scene set — 6 pure + 1 mixed:**

| Scene | Source | Frame contents | Frame mode |
|---|---|---|---|
| `solid` | `--tile-pattern solid` | full 1920×1080 of `ContentClass::Solid` | TileCodec |
| `flat_ui` | `--tile-pattern flat_ui` | full screen of `ContentClass::FlatUi` | TileCodec |
| `text` | `--tile-pattern text` | full screen of `ContentClass::Text` | TileCodec |
| `gradient` | `--tile-pattern gradient` | full screen of `ContentClass::Gradient` | TileCodec |
| `photo` | `--tile-pattern photo` | full screen of `ContentClass::Photo` | TileCodec |
| `motion` | `--tile-pattern motion` | full screen of `ContentClass::Motion` (cycling) | H264 (classifier choice) |
| `mode_switch` | existing `--mode-switch-cycle 2s` | three-stripe mixed-codec static half + motion half | both, alternating |

Pure scenes are produced by a new `--tile-pattern <class-name>` flag on `ghostframe-test-pattern` that fills the full frame with one tile pattern from `ghostframe_bench::fixtures::ContentClass::tile()`. Same fixture source as Layer A — no new fixture authoring. The flag addition is an M3.5a deliverable; `ghostframe-test-pattern`'s `Cargo.toml` gains a path dependency on `ghostframe-bench` (or the fixture module is hoisted to a shared crate at implementation time — implementation-plan call).

**Aggregation per scene:**

- Server interval (capture→last-send): min, p10, median across all frames.
- Client interval (first-recv→rAF-after-paint): min, p10, median.
- Sum interval = p10_server + p10_client (headline).
- Wire bandwidth = total bytes / duration (Mbps).
- Server CPU = `(Δutime + Δstime) / Δwall` → % of one core. Mean + peak.
- Server RSS = max `VmRSS` + max `VmHWM` (high-water).
- Per-codec wire bytes per scene from `codec_histogram` × `total_wire_bytes` + exact per-tile attribution via `recordTile.payloadLen`.

**Report shape — `m3-codec-bench-results.md`:**

1. Preamble: date, git rev, GPU name, kernel, machine class, `dssim-core` version, `RUST_LOG` filter used.
2. Per-scene end-to-end latency table — rows: scenes; columns: server-p10, client-p10, sum-p10, min, median, frame-count, drop-rate.
3. Per-scene wire bandwidth + server CPU/RSS table.
4. Per-codec micro-bench table (from criterion JSON) — codecs × classes × {without LZ4, with LZ4}, units µs.
5. Per-codec compressed-size table — same shape, units bytes/tile, with LZ4 break-even verdict per cell.
6. CDF53 SSIM-vs-passes curve — classes × K∈1..9 → (SSIM, cumulative bytes).
7. BC1 gap matrix — classes × SSIM thresholds {0.85, 0.90, 0.95, 0.98} → "yes/no/depends" + supporting numbers.
8. Lossless-strategy recommendation — narrative + proposed L1/L2/L3 values.

**M3.5a deliverable:** all 8 sections present as headers + table skeletons with `TODO(M3.5b)` cells. Binary runs end-to-end; produces a parseable markdown file.

**Acceptance:**
- `cargo run -p ghostframe-bench --bin codec_report --release -- --scenes solid --scene-duration 2s` completes on the dev machine; produces a 1-scene report.
- `--scenes solid,text,mode_switch --scene-duration 5s` completes under 60 s wall-clock.
- Smoke test in `ghostframe-bench/tests/codec_report_smoke.rs` runs `--scenes solid --scene-duration 1s --output /tmp/test.md` and asserts the output parses as markdown with tables 1 + 8 populated.

## Phase M3.5b — Run, Interpret, Tune

### Step 1 — Run the bench

On the dev machine (AMD card1, VKMS host config matching the e2e suite):

```bash
cargo bench -p ghostframe-bench --bench codec_latency --features gpu-bench,m3 --release
cargo run  -p ghostframe-bench --bin codec_report --release -- \
  --output docs/specs/m3-codec-bench-results.md \
  --scene-duration 10s \
  --reuse-criterion-json target/criterion/m3-codec-side-channel.json
```

`mode_switch` may need `--scene-duration 30s` to surface enough hysteresis flips. Per-scene durations recorded in report preamble.

**Sample-size guard.** Each scene must produce ≥ 600 joined frames (10 s × 60 fps after 2 s warmup ramp). Below that: re-run, investigate. Bench logs per-scene count as a quality signal.

### Step 2 — Populate the report

Sections 2–6 auto-populated by the binary. Manual M3.5b work in those sections:

- **LZ4 break-even verdicts (table 5):** auto-classify per cell as "wins / loses / tie (within 5 %)". Tie threshold documented.
- **BC1 gap matrix (table 7):** auto-populated using BC1's published GPU encode cost range (citation block in preamble; URLs included). Matrix cell tests both ends of the band; reports "yes / no / depends". "Depends" cells get analyst commentary.

Narrative sections require human judgment:

- **Header preamble + reproducibility notes** — human-written.
- **BC1 fate decision** — applied rule: BC1 lands iff ≥ 1 (class, threshold) cell is unambiguously "yes" at both ends of the published BC1 cost band. Decision + evidence chain documented in report. If "drop": follow-up commits listed (remove `Codec::Bc1` variant or leave reserved — decided here). If "land": named content classes feed the future M3.4 brainstorm.
- **Lossless-strategy recommendation (report section 8)** — three values from data:
  - **L1 prune:** narrative argument quantifying the bandwidth savings of removing PalRle/Solid from the escalation set (cite table 3 bandwidth column).
  - **L2 (`idle_frames`):** derived from `mode_switch` scene's time-to-PixelPerfect curve. Target: "PixelPerfect within 1 s of motion stopping on text/UI content".
  - **L3 (`refinement_bandwidth_fraction`):** derived from CDF53 SSIM-vs-passes curve combined with measured bandwidth. Target: "all 9 passes delivered for idle text region within 500 ms of escalation start without starving newly-dirty tiles".

### Step 3 — Three surgical code commits

Each in its own commit, each citing the report.

1. **`fix(classifier): retune CostModel from M3.5 bench data`** — `ghostframe-lib/src/tile/classifier.rs::CostModel`. Replaces the six µs placeholders (`solid_us`, `palrle_us`, `bc1_us`, `cdf53_us`, `raw_us`, `h264_frame_us`) with measured p10 values from report table 4. `bc1_us` keeps the placeholder if BC1 lands later, or is removed in commit 4 if BC1 dropped.
2. **`fix(classifier): remove PalRle/Solid from refinement escalation set`** — `ghostframe-lib/src/transport/io_bridge.rs` (escalation predicate) and `ghostframe-lib/src/tile/escalation.rs::detect_escalation_candidates`. Updates source-codec match arm `{Bc1, PalRle, Solid}` → `{Bc1}` (or `{}` if BC1 dropped). L2 (`idle_frames`) and L3 (`refinement_bandwidth_fraction`) constants updated in same commit; module-of-record per current code is `transport/scheduler.rs` for L3 and `tile/escalation.rs` for L2.
3. **`fix(codec): per-class LZ4 default per M3.5 bench`** — whichever site picks LZ4 on/off per codec emit. If break-even is consistent per codec across classes: a constant flip. If per-class differentiation needed: also adds a per-class field to the classifier output (small change, called out in report).

**Optional 4th commit** if BC1 dropped: **`refactor(codec): remove Codec::Bc1 variant and dead BC1 references`**. Touches `Codec` enum, `CodecState` enum, every match arm. Decision deferred to post-report review.

### Step 4 — Regression sweep

After commit 3 (or 4), all of:

- `e2e_mode_switch` — umbrella's specifically-called-out regression. Asserts *behavioral* boundaries ("100 % solid stays tile-codec", "100 % motion drives H264 within hysteresis") that hold across constants tuning even if exact thresholds shift.
- `e2e_progressive_refinement` — refinement still reaches PixelPerfect after L2/L3 tune.
- `e2e_lossless_buildup` — CDF53 SSIM convergence unaffected by classifier constants.
- `e2e_solid_color`, `e2e_h264_motion`, `e2e_codec_transition`, `e2e_multi_tile_grid` — broader sanity sweep matching M3.3 close-out cadence.
- `e2e_ack_telemetry_no_waste` — recent regression guard. New telemetry fields must not add unacked datagrams.
- `cargo test -p ghostframe-lib --lib` — 323/323 baseline must hold.

### Step 5 — Commit the populated report

Two-phase commit pattern inside M3.5b to keep the report honest about which build it describes:

1. **Pre-tune report commit.** After Step 1's run, the report committed by Step 2 describes the *pre-tune* binary (placeholder constants, old escalation set). Tables in the report cite "constants version: pre-M3.5b" in the preamble. This commit lets Step 3's commits cite the report as their evidence chain.
2. **Post-tune report commit.** After Step 3's commits land and Step 4's regression sweep passes, the bench is re-run once more (full 7 scenes + criterion). The report is regenerated; tables update; preamble flips to "constants version: post-M3.5b". Commit message names which numbers shifted vs the pre-tune report and by how much. If any number shifted in a way that contradicts the BC1 fate decision or the L2/L3 tune from the pre-tune report, the iteration loop reopens (re-do Step 3 with the new data).

The post-tune report is the final shipped artifact. The pre-tune report stays in git history as the decision-time snapshot.

## Wire protocol additions

**None.** All telemetry rides existing channels:
- Server: existing `tracing::info!` macros with new event names (`frame.captured`, `frame.last_send`). JSON output enabled via `RUST_LOG` + subscriber config the bench passes; no new sink, no new datagram type.
- Client: existing `diagnostics.ts` FIFO with extended `recordTile` fields and a new `recordFramePainted` entry point. No new global beyond the new FIFO name.
- External: `/proc/<pid>/status` and `/proc/<pid>/stat` polled by the bench binary; not a wire protocol.

No new datagram discriminators. No `Codec` enum changes in M3.5a; possible removal of `Codec::Bc1` in M3.5b commit 4 if BC1 dropped.

## Out of scope

- **BC1 implementation.** Encoder, shader, decoder all absent. "Drop BC1" verdict closes the question; "land BC1" verdict triggers a separate M3.4 brainstorm.
- **Adaptive bandwidth fraction.** L3 stays static tuned. RTT/loss-aware refinement budgeting is M4 work tied to the §6.5 estimator.
- **Cross-hardware bench matrix.** Single dev machine. Validation on Intel iGPU / second AMD card is future work.
- **CI integration for the bench.** Runs locally, by hand, once per milestone. Constants live in the repo; bench-results doc is the audit trail.
- **Codegen of constants.** Manual edit per M3.5b Step 3 commit 1. Codegen has its own maintenance cost and the structured-JSON intermediate adds a moving part.
- **`tests/e2e.rs` refactor.** Its 3567 lines stay as-is; only the harness helpers extract to the library. Internal-test refactor is a separate cleanup if desired.
- **Per-metric-pattern classifier rules.** L1 prune is the only escalation-rule change. Metric-conditional rules (e.g. "edge_density > 0.5 → faster escalation") deferred until cross-class data warrants them.
- **`Codec::Bc1` removal commit before the report exists.** Removal (if it happens) lands in M3.5b after the report names it as the verdict.

## Decision Register

| # | Decision | Rationale |
|---|---|---|
| D1 | M3.5 split into M3.5a (harness foundation) + M3.5b (run + interpret + tune) | Mirrors M3.3a/b/c/d cadence; isolates harness-refactor review from data-interpretation review; risk-isolates surgical classifier commits. |
| D2 | No BC1 implementation in M3.5 (even bench-only) | User goal is "see if BC1 *would* help" — answerable analytically from CDF53 measurements + published BC1 operating points. Avoids building code that may be discarded. |
| D3 | Two measurement layers: Layer A criterion micro-bench + Layer B e2e bench | Cost-model constants need per-tile encode µs (Layer A); end-to-end protocol behavior needs whole-pipeline measurement (Layer B). Cross-validation between the two surfaces protocol quirks. |
| D4 | Codecs benched: Solid + PalRle + Cdf53 only | Only the three production codecs exist; BC1 is excluded per D2. |
| D5 | BC1 gap predicate: class × SSIM-threshold matrix | Surfaces *where* BC1 might be useful (speed-to-acceptable-quality on specific content) rather than the umbrella's bytes-to-lossless framing that pre-determines a "drop BC1" answer. Allows content-class-specific decisions. |
| D6 | Scene model: 6 pure scenes + 1 mixed (`mode_switch`) | Pure scenes give clean per-codec attribution for the matrix and SSIM curves; mixed scene catches scheduler-fairness quirks pure scenes miss. |
| D7 | Latency endpoints: DRM-capture → first rAF after paint, measured as two intervals | Truest "frame-to-photon-equivalent" measurement. Two-interval reporting avoids cross-clock alignment and exposes whether latency lives server- or client-side — the protocol-quirk signal cited as the bench's purpose. |
| D8 | Lossless-strategy levers in M3.5b: L1 prune + L2 tune + L3 tune | L1 prune is the highest-value insight from the data (PalRle/Solid escalation is wasted compute). L2 and L3 single-value tunes are within bench data's discriminative power. New per-metric rules deferred. |
| D9 | Harness location: extract `ghostframe-e2e::harness` library + new binary in `ghostframe-bench` | Bench is a tool that emits a document, not a pass/fail test; `cargo test` semantics fight the long-running shape. Library extraction also benefits future tests wanting programmatic harness control. |
| D10 | SSIM source: `dssim-core` crate, not hand-rolled | Pure-Rust, no system deps, well-validated. Hand-rolling Gaussian-windowed SSIM is error-prone for marginal benefit. |
| D11 | "Best case" stat: report min + p10 + median; headline = p10 | p10 is robust to occasional GC pauses while still reflecting "what good looks like". Reporting all three is a small marginal cost. |
| D12 | Telemetry source: combined in-band server telemetry + external `/proc` polling | Server-side bytes-per-frame_seq is authoritative for bandwidth (knows codec emission vs ACKs vs control). External `/proc` polling avoids self-sampling skew for CPU/RSS. |
| D13 | Constants update path: manual PR per M3.5b Step 3 | Constants change once per milestone; codegen has its own maintenance cost; the structured-JSON intermediate adds a moving part. |
| D14 | No new wire-protocol fields | Telemetry rides existing tracing infrastructure (server) and existing diagnostics FIFO (client). Existing protocol stays stable. |
| D15 | No new server-side telemetry sink abstraction; reuse `tracing::info!` | Two extra `tracing::info!` per frame is below the existing per-frame noise. JSON output via `tracing-subscriber` configuration. Avoids inventing infrastructure for a once-per-milestone use case. |
| D16 | M3.5 reorders the M3 phase plan: M3.5 must run before M3.4 | Per umbrella D10: M3.4 is conditional on M3.5's BC1 fate decision. M3.5 closes the loop on whether M3.4 happens at all. |
| D17 | L1 escalation set in production today (`{Bc1, PalRle, Solid}`) is incorrect; M3.5b prunes to `{Bc1}` (or `{}` if BC1 dropped) | PalRle and Solid are already lossless within feasibility. Escalating them runs the CDF53 forward transform + scheduler queueing for zero perceptual improvement. Bench quantifies the wasted compute in M3.5b. |
