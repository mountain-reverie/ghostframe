# M3.2b — WebGPU Client Migration: Per-Milestone Design

**Date:** 2026-05-13
**Status:** Design approved
**Predecessors:**
- `docs/superpowers/specs/2026-04-28-m3-codec-suite-design.md` (M3 umbrella)
- `docs/superpowers/specs/2026-05-13-palrle-codec-design.md` (M3.2 server pipeline + "M3.2b parking lot")
- `docs/superpowers/specs/2026-05-11-m3.1-solid-scheduler-decisions.md` (Scheduler + ACK + FEEDBACK bidi stream)

This design supersedes the parking lot enumerated in §"M3.2b parking lot" of the PalRLE codec design where they conflict. The M3 umbrella's broader phase ordering (M3.3+) is unaffected.

---

## Context

M3.2a shipped the server-side PalRLE pipeline end-to-end on the wire (`Codec::PalRle = 2`) with a pure-TypeScript Canvas 2D client. The client touches GPU only indirectly via the browser compositor; every pixel passes through CPU `putImageData`, BGRA→RGBA byte-swap loops, and a JS `Map`-backed `PaletteCache`.

M3.2b migrates the client onto WebGPU as foundation work for M3.3 (CDF 5/3) and M3.4 (BC1), both of which need GPU compute on the client side and have no Canvas 2D analogue. While re-homing every codec onto GPU, M3.2b also ships the previously-reserved PalRLE wire variant (`indices_raw`, `flags` bit 1) along with the capability handshake required to negotiate it, and adds client→server decode-error feedback so the server can react to client-side decode failures.

WebGPU is hard-required: no Canvas 2D fallback path remains after this milestone.

## Decision Register

| # | Decision | Rationale |
|---|---|---|
| D1 | Full M3.2a parking-lot scope: WebGPU renderer + palette atlas + `indices_raw` + HELLO capability handshake + decode-error feedback; no WASM ever | Foundation for M3.3/M3.4; deferring sub-items would leave the wire-protocol surface half-built |
| D2 | Hard-require WebGPU; delete Canvas 2D paths entirely | Target browser is Chrome; M3.3/M3.4 have no Canvas analogue; dual codepaths double test surface for no covered user base |
| D3 | GPU compute decode for all PalRLE variants; CPU pre-validation expands RLE→indices, GPU does palette lookup only | Workgroup-per-tile + thread-per-pixel can't parallelize an RLE state machine; pre-expanding to 512 B 4-bit indices on CPU is cheap (~50 µs/rAF) and yields a uniform GPU shader. `indices_raw`'s win (skip CPU expansion) is preserved |
| D4 | New `HELLO_MSG_TYPE = 0x03` on the existing reliable bidi FEEDBACK stream, fixed 2 bytes `[0x03][caps:u8]` | Conventional capability-negotiation shape; out of feedback hot path; extensible by adding bits or by future HELLO_V2 message type |
| D5 | Offscreen persistent framebuffer texture + present blit | Only model that preserves dirty-tile-only semantics; canvas swapchain textures are reclaimed per present |
| D6 | Per-codec batched dispatches driven by `requestAnimationFrame` ticks, never by frame-seq completion | No-stall property: a lost packet for one tile must not block rendering of any other tile |
| D7 | `importExternalTexture` for both H.264 paths (tile and full-frame) | Zero-copy from WebCodecs `VideoFrame`; ephemeral lifetime matches the rAF-submit model |
| D8 | Decode-error message `DECODE_ERROR_MSG_TYPE = 0x04`, fixed 5 bytes `[0x04][codec:1][tile_x:1][tile_y:1][error_code:1]` | Per-error granularity gives the server enough signal for targeted reactions (force-rebundle on uncached-palette); rate-limited at the client to bound feedback bandwidth |
| D9 | Match each codec to its strongest GPU primitive (Solid=render, Raw=writeTexture, PalRLE=compute, H.264=render+importExternalTexture) | Aligns each codec with its lowest-overhead WebGPU API; uniform-under-compute or uniform-under-render would force codecs through awkward primitives |
| D10 | Hybrid decode-error detection — CPU pre-validates structural errors (codes 1–4); GPU shader writes in-shader errors (codes 5–7) into a tagged error buffer; CPU drains on the next rAF tick | Structural errors are free during CPU batch-packing; in-shader errors need GPU detection. Same B2 emission format from either layer |
| D11 | Palette atlas as a single storage buffer `array<u32, 4096>`, indexed `palette_id * 16 + color_idx` | 16 KB total; storage-buffer indexed lookup is one-line WGSL with no sampler/view/format ceremony; perf is wash vs sampled texture at this size |
| D12 | Canvas / framebuffer pixel format `rgba8unorm`; BGRA→RGBA channel reorder via free `.zyxw` swizzle in shader | Standard WebGPU canvas format; channel reorder costs nothing in hardware |
| D13 | E2E uses real GPU passthrough when `/dev/dri/renderD128` is host-available; falls back to SwiftShader (`--enable-unsafe-swiftshader`) otherwise | Fast tests locally, robust CI on hosts without GPU; no test-architecture change for the rest of the suite |
| D14 | Server-side reaction to decode-error code 3 (thin→uncached): `PaletteTable::force_rebundle(palette_id)` on next dirty pass; codes 5–7 logged and counted only in M3.2b | Force-rebundle is a one-line existing-infrastructure change; deeper reactions await M3.5 bench data |
| D15 | No backwards-compatibility with M3.2a Canvas 2D client; clean replacement | WebTransport reconnect always starts fresh; mid-session upgrade is not a concern |

## Architecture

### What changes on the client

- `ghostframe-web-client/src/renderer.ts` (Canvas 2D `TileRenderer`) — **replaced** by a new `WebGpuRenderer` class.
- `ghostframe-web-client/src/palette.ts` (`PaletteCache` Map) — **replaced** by a CPU `palette_shadow` array (used by pre-validation only) and a 16 KB GPU storage buffer `palette_atlas`.
- `ghostframe-web-client/src/decoder.ts::decodePalRle` — **replaced** by `prevalidate_pal_rle` returning either a `TileWorkEntry` (with 512 B indices materialized) or a `DecodeError`.
- `ghostframe-web-client/src/main.ts` — switches from per-tile draw at decode-time to per-rAF batched flush; gains HELLO emission, `DecodeErrorBatcher`, and the rAF tick loop.
- `ghostframe-web-client/src/feedback.ts` — extended with HELLO emission and decode-error message serializers.
- New unit-test scaffolding (Vitest) with three test families.

### GPU resources

| Resource | Type | Size | Lifetime |
|---|---|---|---|
| Framebuffer texture | `GPUTexture` `rgba8unorm` `STORAGE_BINDING \| TEXTURE_BINDING \| RENDER_ATTACHMENT \| COPY_DST` | canvas_w × canvas_h × 4 B | Session; reallocated on resize |
| Palette atlas buffer | `GPUBuffer` `STORAGE \| COPY_DST` | 16 KB (256 × 16 × 4 B) | Session |
| Tile-work buffer | `GPUBuffer` `STORAGE \| COPY_DST` | `MAX_TILES × 32 B` | Session; reallocated on resize |
| Indices buffer | `GPUBuffer` `STORAGE \| COPY_DST` | `MAX_TILES × 512 B` | Session; reallocated on resize |
| Solid instance buffer | `GPUBuffer` `VERTEX \| COPY_DST` | `MAX_TILES × 12 B` | Session; reallocated on resize |
| Errors buffer | `GPUBuffer` `STORAGE \| COPY_SRC \| COPY_DST` | `MAX_TILES × 4 B` | Session; reallocated on resize |
| Errors staging buffer | `GPUBuffer` `MAP_READ \| COPY_DST` | matches errors buffer | Session; reallocated on resize |
| Quad vertex buffer | `GPUBuffer` `VERTEX` | 24 B (unit quad, 6 vertices) | Device |
| Compute pipeline (PalRLE) | `GPUComputePipeline` | — | Device |
| Render pipeline (Solid) | `GPURenderPipeline` | — | Device |
| Render pipeline (H.264 textured quad) | `GPURenderPipeline` | — | Device |
| Render pipeline (present blit) | `GPURenderPipeline` | — | Device |
| Bind groups | `GPUBindGroup` ×4 | — | Session; rebuilt on resize |

`MAX_TILES = ceil(canvas_w / 32) * ceil(canvas_h / 32)` — recomputed at session start and on resize. At 1920×1080 this is 2040 (≈64 KB tile-work, ≈1 MB indices, ≈24 KB instances, ≈8 KB errors); at 3840×2160 it is 8160 (256 KB / 4 MB / 96 KB / 32 KB). Resize triggers reallocation of every per-tile-sized buffer plus the framebuffer.

### No-stall property

Each codec queue is drained independently per rAF tick. A lost packet for one PalRLE tile delays only that tile; the rest of the tick proceeds. The missing tile's region on the framebuffer keeps its previous contents until the server's scheduler retransmits or a new dirty pass paints over it. The render pipeline never blocks on a missing tile.

### Generation-aware queueing

Tile fragments carry `(generation, pass)` in the existing `TileHeader`. On enqueue, if a fresher `(gen, pass)` for the same `(tile_x, tile_y)` is already pending, the older entry is dropped — last-write-wins by generation, not by arrival order.

## Wire-protocol additions

Both new messages travel client→server on the existing reliable bidi FEEDBACK stream. Server reads them in the same byte-stream loop that already reads `FEEDBACK_MSG_TYPE = 0x01` (`ReceiverFeedback`). No change to the unreliable datagram fast path, no change to tile or frame headers.

### HELLO — `MSG_TYPE = 0x03`, 2 bytes fixed

```
[0]  msg_type = 0x03
[1]  capabilities : u8
       bit 0 = supports indices_raw (PalRLE flags bit 1)
       bits 1..7 reserved (must be 0 in M3.2b; deserializer ignores)
```

**Client:** emits exactly one HELLO immediately after `await transport.ready`, before initiating any other reads/writes. Always sets bit 0 (WebGPU is hard-required).

**Server side state** (new):
- Per-session `ClientCapabilities { indices_raw_enabled: bool }`, default all-`false`.
- Encoder Phase A reads this flag to choose between bundled / thin / `indices_raw` variants when emitting PalRLE tiles.

**Back-compat:** purely additive. Older clients never send `0x03`; the server defaults safely to bundled-only emission.

### DECODE_ERROR — `MSG_TYPE = 0x04`, 5 bytes fixed

```
[0]  msg_type = 0x04
[1]  codec       : u8     Codec enum discriminant (typically PalRle=2)
[2]  tile_x      : u8
[3]  tile_y      : u8
[4]  error_code  : u8     taxonomy below
```

| Code | Meaning | Detection layer |
|---|---|---|
| 1 | payload too short | CPU pre-validation |
| 2 | count out of range (not 1..16) | CPU pre-validation |
| 3 | thin payload references uncached `palette_id` | CPU pre-validation |
| 4 | bundled payload truncated mid-palette | CPU pre-validation |
| 5 | palette index ≥ count | GPU shader → error-buffer readback |
| 6 | RLE expansion overshot 1024 pixels | GPU shader → error-buffer readback |
| 7 | RLE expansion undershot 1024 pixels | GPU shader → error-buffer readback |

**Client-side rate-limit** (`DecodeErrorBatcher`, modeled on existing `AckBatcher`):
- Per-key `(codec, tile_x, tile_y)`: ≤ 1 emission per 1000 ms.
- Global: ≤ 32 emissions per 1000 ms.
- Sliding window via `performance.now()`. Entries above either cap dropped silently. No batching delay — emit ASAP once cap permits.

**Server-side reactions in M3.2b:**
- Code 3 — `PaletteTable::force_rebundle(palette_id)` clears the `delivered` bit so the next dirty tile carrying this palette emits bundled. Single-line addition to existing `pal_rle.rs`.
- Codes 5–7 — log `warn!`, increment `MetricsTracker.decode_errors{code, codec}`. No behavioral response in M3.2b; hooks for M3.5 to ratchet down `indices_raw` per palette if needed.
- Codes 1, 2, 4 — log `warn!`, increment counters. No mitigation (these indicate a client-side parsing bug, not a recoverable state).

## PalRLE compute decode

### Palette atlas

```wgsl
@group(0) @binding(0) var<storage, read> palette_atlas: array<u32, 4096>;
// Indexed as palette_id * 16u + color_idx.
// Each u32 packs BGRA in little-endian byte order (matches wire format).
```

CPU update when a bundled PalRLE tile arrives:

```ts
device.queue.writeBuffer(
  palette_atlas,
  palette_id * 64,
  paletteBytes,    // count * 4 bytes BGRA
  0,
  count * 4
);
palette_shadow[palette_id] = { count, present: true };
```

Slots `[count..16]` are stale/undefined; the shader never reads them because count is enforced via error code 5.

### Tile-work buffer

```wgsl
struct TileWork {
  tile_x      : u32,
  tile_y      : u32,
  palette_id  : u32,
  count       : u32,     // 1..16 for index-OOB detection
  payload_off : u32,     // byte offset into indices_buf
  _pad0       : u32,
  _pad1       : u32,
  _pad2       : u32,
};  // 32 B aligned
@group(0) @binding(1) var<storage, read> tile_work: array<TileWork>;
```

Written via `queue.writeBuffer` once per rAF tick. Worst case: 2040 entries × 32 B = 64 KB.

### Indices buffer

```wgsl
@group(0) @binding(2) var<storage, read> indices_buf: array<u32>;
```

Each tile contributes 512 B (1024 pixels × 4-bit indices) at offset `tile_work[wg].payload_off`. Concatenated across all tiles, reused across rAFs at worst-case 1 MB.

### Framebuffer (storage texture)

```wgsl
@group(0) @binding(3) var framebuffer: texture_storage_2d<rgba8unorm, write>;
```

### Error buffer

```wgsl
@group(0) @binding(4) var<storage, read_write> errors: array<atomic<u32>>;
// One u32 per workgroup. 0 = OK; non-zero = error_code.
```

### Compute shader

```wgsl
@compute @workgroup_size(32, 32, 1)
fn pal_rle_decode(
    @builtin(workgroup_id) wg: vec3<u32>,
    @builtin(local_invocation_id) lid: vec3<u32>,
) {
  let work = tile_work[wg.x];
  let pixel_in_tile = lid.y * 32u + lid.x;       // 0..1023
  let nibble_idx = pixel_in_tile;
  let byte_idx = nibble_idx >> 1u;
  let word_idx = byte_idx >> 2u;
  let byte_in_word = byte_idx & 3u;
  let word = indices_buf[(work.payload_off >> 2u) + word_idx];
  let packed_byte = (word >> (byte_in_word * 8u)) & 0xFFu;
  let color_idx = select(packed_byte >> 4u, packed_byte & 0x0Fu, (nibble_idx & 1u) == 1u);

  if (color_idx >= work.count) {
    atomicStore(&errors[wg.x], 5u);              // index OOB
    return;
  }
  let bgra_packed = palette_atlas[work.palette_id * 16u + color_idx];
  // unpack4x8unorm returns vec4<f32> in LSB-byte-first order: (B, G, R, A) for our packing.
  let bgra = unpack4x8unorm(bgra_packed);
  textureStore(
      framebuffer,
      vec2<i32>(i32(work.tile_x * 32u + lid.x), i32(work.tile_y * 32u + lid.y)),
      bgra.zyxw                                   // BGRA → RGBA swizzle (free)
  );
}
```

Dispatch: `pass.dispatchWorkgroups(num_pal_rle_tiles_this_raf, 1, 1)`. One workgroup per tile, 1024 threads per workgroup.

### CPU pre-validation step (per tile, before batch packing)

For each PalRLE tile reassembled and ready to render:

1. **Structural validation** (error codes 1–4):
   - payload length ≥ 2
   - if bundled: count ∈ 1..16, `cursor + count*4 ≤ payload.length`
   - if thin: `palette_shadow[palette_id].present === true`
2. **If bundled:** stage the palette into the per-rAF pending-atlas-writes queue (drained at rAF step 1).
3. **Materialize 512 B indices** into the staging buffer at `current_indices_off`:
   - `indices_raw` (flags bit 1 set): copy 512 B verbatim from payload.
   - bundled / thin: walk RLE nibbles, expand into a 1024-entry scratch, re-pack to 4-bit indices (512 B).
4. **Append `TileWork`** to tile_work staging with `payload_off = current_indices_off`; advance `current_indices_off += 512`.
5. **On any structural error:** enqueue a B2 decode-error (rate-limited) and skip this tile — do NOT add to tile_work. The tile's framebuffer region keeps its prior contents.

### Error buffer readback

After `submit()`, encode a `copyBufferToBuffer(errors → errors_staging)`. On the *next* rAF tick (one frame of latency, acceptable), `errors_staging.mapAsync(GPUMapMode.READ)`, drain non-zero entries, emit B2 decode-errors per the rate-limit, unmap, zero the errors buffer for reuse.

## Render-pass codecs + unified rAF tick

### Solid (instanced quad render-pass)

- Pipeline: vertex shader emits a unit-quad's 6 vertices; per-instance attributes `(tile_x:u32, tile_y:u32, color_packed:u32)` in instance buffer.
- One `draw(6, num_solid_tiles, 0, 0)` per rAF — N quads in one draw.
- Vertex shader transforms `(tile_x*32, tile_y*32)` to NDC; fragment shader emits `unpack4x8unorm(color_packed).zyxw`.
- Instance buffer reused across rAFs, worst-case 24 KB.

### Raw (`queue.writeTexture`)

- Per Raw tile, one `queue.writeTexture` call targeting framebuffer's 32×32 region at `(tile_x*32, tile_y*32)`.
- Source needs JS-side BGRA→RGBA byte-swap before upload (~10 µs per 4096 B tile via Uint32Array byte rotate; alternatively a small compute shader can do it, but `writeTexture` is simpler in scope).
- No pipeline involvement; happens before encoder begin.

### H.264 tile (`importExternalTexture` + textured quad)

- Per VideoFrame in queue: `const ext = device.importExternalTexture({ source: videoFrame })`.
- Inside the unified render pass: switch to H.264 pipeline, rebind bind-group containing `ext`, `setViewport(tile_x*32, tile_y*32, 32, 32, 0, 1)`, `draw(6)`.
- After submit: `videoFrame.close()`.

**`H264TileDecoder` ownership change.** The current implementation auto-closes the previous `VideoFrame` whenever a new one arrives (`decoder.ts:82-86`). With per-rAF queueing, the queued frame could be auto-closed mid-tick before its draw runs. Migration removes the auto-close from the decoder; the rAF tick step 14 is now the sole closer of consumed VideoFrames. If a new VideoFrame for the same tile coordinate arrives before the previous is consumed, the queue replaces (and closes) the older one via the generation-aware queueing path.

### H.264 full-frame

- Same shape as H.264 tile but `setViewport(0, 0, canvas_w, canvas_h, 0, 1)`. Same H.264 pipeline.

### Unified rAF tick lifecycle

```
1.  Drain palette updates (CPU → GPU)
       for each bundled palette pending:
           queue.writeBuffer(palette_atlas, palette_id*64, paletteBytes)
       (also updates palette_shadow used by thin-payload validation)

2.  Pre-validate + pack PalRLE batch (CPU)
       for each PalRLE tile pending:
           - structural checks (errors 1-4) → emit B2 if fail, drop tile
           - materialize 512 B indices (RLE expand OR indices_raw copy)
           - append to tile_work_staging + indices_buf_staging

3.  Pack Solid instance buffer (CPU)
       for each Solid tile pending:
           append (tile_x, tile_y, color) to solid_instances_staging

4.  Direct Raw uploads (CPU → GPU, pre-encoder)
       for each Raw tile pending:
           queue.writeTexture(framebuffer, region, bgra_swapped_payload)

5.  Buffer uploads (CPU → GPU, pre-encoder)
       queue.writeBuffer(tile_work_buf, 0, tile_work_staging)
       queue.writeBuffer(indices_buf, 0, indices_buf_staging)
       queue.writeBuffer(solid_instance_buf, 0, solid_instances_staging)

6.  encoder = device.createCommandEncoder()

7.  Compute pass — PalRLE
       pass = encoder.beginComputePass()
       pass.setPipeline(palrle_pipeline)
       pass.setBindGroup(0, palrle_bind_group)
       pass.dispatchWorkgroups(num_palrle_tiles, 1, 1)
       pass.end()

8.  Render pass — Solid + H.264 (loadOp='load' to preserve framebuffer)
       pass = encoder.beginRenderPass({
         colorAttachments: [{ view: framebuffer_view, loadOp: 'load', storeOp: 'store' }]
       })
       (a) Solid:
           pass.setPipeline(solid_pipeline)
           pass.setVertexBuffer(0, quad_vb)
           pass.setVertexBuffer(1, solid_instance_buf)
           pass.draw(6, num_solid_tiles, 0, 0)
       (b) H.264 tiles + full-frame:
           pass.setPipeline(h264_pipeline)
           pass.setVertexBuffer(0, quad_vb)
           for each h264_tile: rebind ext-texture BG, setViewport(tile rect), draw(6)
           if full-frame h264: rebind ext-texture BG, setViewport(0,0,W,H), draw(6)
       pass.end()

9.  Present pass — blit framebuffer to swapchain
       swap_tex = context.getCurrentTexture()
       pass = encoder.beginRenderPass({
         colorAttachments: [{ view: swap_tex.createView(),
                              loadOp: 'clear', clearValue: [0,0,0,1],
                              storeOp: 'store' }]
       })
       pass.setPipeline(blit_pipeline)
       pass.setBindGroup(0, blit_bind_group)   // samples framebuffer_view
       pass.draw(6)
       pass.end()

10. encoder.copyBufferToBuffer(errors_buf, 0, errors_staging, 0, errors_buf.size)

11. queue.submit([encoder.finish()])

12. queue.writeBuffer(errors_buf, 0, zeros)            // zero for next tick
    (zeros is a session-cached Uint8Array of errors_buf.size; non-error workgroups
     never write their slot, so explicit zeroing is required to avoid stale codes.)

13. Async: errors_staging.mapAsync(GPUMapMode.READ) — drain non-zero entries on completion
    (Promise resolution happens before the next rAF, so one rAF of latency on B2 emission.)

14. Cleanup: close all consumed VideoFrames
```

### Why the order matters

- **Step 1 before step 2** — palette atlas must reflect bundled-palette deliveries before validation reads `palette_shadow`. A bundled-and-thin pair carrying the same `palette_id` in the same rAF tick must see the bundled palette as already present.
- **Step 4 before step 6 (encoder)** — `queue.writeTexture` is queue-level, not encoder-level. Submitting it before encoder commands ensures it lands before encoder writes overlap the same framebuffer regions.
- **Step 7 before step 8** — compute writes to framebuffer via storage texture; render pass loads framebuffer's previous contents. WebGPU's implicit pass-boundary barrier ensures compute writes are visible to the render pass.
- **Step 8 before step 9** — present blit samples the framebuffer; must run after all writes complete.
- **Step 11 decoupled from B2 emission** — error readback can't block the rAF tick (would stall the next frame waiting on GPU→CPU map). One rAF of latency on decode-error reporting is acceptable.

## Classifier / encoder integration on the server

### Phase A `indices_raw` selection

In `ghostframe-lib/src/transport/io_bridge.rs::phase_a_palette_allocation` (and `phase_b_encode_payloads`), after selecting bundled vs thin per the existing M3.2a logic, an additional branch chooses `indices_raw` when:

1. `client_caps.indices_raw_enabled == true`
2. The selected variant would otherwise be **thin** (no palette block needed)
3. *(Tuning lever)* future M3.5 may add a content-class predicate; in M3.2b, all-thin-becomes-indices_raw.

`indices_raw` is the same byte budget as thin for entropy-light content (long runs compress in RLE) and a savings for entropy-heavy content (no nibble framing overhead). The bench in M3.5 will quantify; M3.2b ships the unconditional swap from thin → indices_raw.

### `force_rebundle` implementation

In `ghostframe-lib/src/encoder/pal_rle.rs::PaletteTable`:

```rust
impl PaletteTable {
    /// Mark a palette as needing rebundling on its next emission.
    /// Called when the client reports a thin payload referenced an
    /// uncached palette_id (decode-error code 3).
    pub fn force_rebundle(&mut self, palette_id: u8) {
        self.delivered.clear(palette_id);
        // Any in_flight_carrying entries remain; subsequent emission paths
        // will see delivered=false and emit bundled instead of thin.
    }
}
```

Called from `io_bridge.rs` when a `0x04` decode-error with `error_code=3` is parsed.

## Error handling

| Class | Detected | Handled |
|---|---|---|
| CPU structural (codes 1–4) | rAF step 2 pre-validation | Drop tile from batch; emit B2 (rate-limited); framebuffer region keeps prior contents |
| GPU in-shader (codes 5–7) | Compute shader writes to errors buffer | Async readback on next rAF tick; emit B2 (rate-limited); tile already has whatever the shader wrote (typically garbled — acceptable) |
| Lifecycle | Adapter request / `device.lost` / `transport.closed` | Surface UI error; abort or refuse connect |

### Lifecycle specifics

- **`navigator.gpu` missing OR `requestAdapter()` returns null:** UI error pre-connect, do not initiate WebTransport. Status text reads `WebGPU not available in this browser.`
- **`device.lost` mid-session:** UI error; call `transport.close()`. No auto-reconnect in M3.2b.
- **`transport.closed`:** existing M3.2a behavior preserved — `paletteCache.clear()` becomes "zero palette atlas via `queue.writeBuffer(atlas, 0, new Uint8Array(16384))` + clear `palette_shadow`." Framebuffer texture is left in place (next session paints over).
- **Resize (dimensions sentinel datagram):** reallocate framebuffer texture; rebuild render-pass bind groups (palette_atlas, tile_work, indices_buf bind groups are not affected since they reference buffers, not framebuffer); drop any in-flight tiles for the old dimensions.

## Testing

### Unit tests (Vitest, new infrastructure)

The client currently has no test infrastructure. M3.2b adds Vitest as a devDep. Three test families:

1. **CPU pre-validation correctness** — golden-input tests for `prevalidate_pal_rle(payload, palette_shadow) → TileWorkEntry | DecodeError`. Covers:
   - bundled valid (count=1, 8, 16; varied palette content)
   - bundled too short (cursor + count*4 > length)
   - bundled count out of range (0, 17)
   - thin valid against pre-populated shadow
   - thin against empty shadow (uncached palette_id)
   - `indices_raw` valid (512 B exact)
   - `indices_raw` short / long

2. **Indices-buffer materialization** — for each variant, assert 512 B output matches a known-good reference computed independently from the wire bytes. Includes adversarial RLE: max-run sequences (`0xFF` repeated), pixel-count-exact sequences, alternating-index sequences.

3. **`DecodeErrorBatcher` rate-limit** — fixed-clock harness (mock `performance.now()`), emit > caps, assert dropped count matches expectations across both per-key and global windows.

### E2E (existing `ghostframe-lib/tests/e2e.rs`)

GPU adapter availability is the gating concern. Strategy is real GPU when host-available, SwiftShader otherwise:

```rust
// New helper alongside setup_e2e_gpu in tests/e2e/mod.rs
fn setup_e2e_webgpu(test_pattern_args: &str) -> ContainerHandle {
    let mut container = setup_e2e_gpu(test_pattern_args);  // existing VKMS-passthrough helper
    if Path::new("/dev/dri/renderD128").exists() {
        // Real GPU: bind-mount renderD128, native WebGPU
        container = container
            .with_dev_dri_render()
            .with_chrome_flag("--enable-features=Vulkan,WebGPU");
    } else {
        // Headless CI: SwiftShader CPU fallback
        container = container
            .with_chrome_flag("--enable-unsafe-swiftshader")
            .with_chrome_flag("--use-angle=swiftshader");
    }
    container
}
```

**Existing M3.2a E2E tests are migrated** by rerouting through `setup_e2e_webgpu`. Pixel readback assertions continue working via canvas `toDataURL()` / Chrome DevTools `Page.captureScreenshot`.

**New E2E tests:**

| Test | Verifies |
|---|---|
| `e2e_indices_raw_handshake` | Capture HELLO byte on FEEDBACK stream; verify server emits `flags & 0x02` PalRLE tiles after handshake; verify pre-HELLO frames only emit bundled/thin |
| `e2e_decode_error_thin_uncached` | Inject a thin PalRLE tile referencing an unknown palette_id; assert `0x04` B2 message arrives at server with `error_code=3`; assert server's next dirty pass for that palette emits bundled (`force_rebundle` works) |
| `e2e_webgpu_fallback_swiftshader` | Run with `/dev/dri/renderD128` masked off; assert SwiftShader path completes a frame; pixel sample matches expected red |

### No proptest on the client

TS test surface is small enough that hand-written goldens cover the variant space; fast-check is overkill at this scope.

### Bench (out of scope)

WebGPU client-decode timing belongs in M3.5 bench publication. No client bench infrastructure in M3.2b.

## What this design does NOT do

- **No texture-cache eviction.** The 16 KB palette atlas is small enough to keep all 256 slots resident always. Server-side `PaletteTable` already handles slot reuse; the client just mirrors.
- **No client-side scheduler equivalent.** Tile retransmits stay server-driven (M3.1 infrastructure).
- **No backwards-compatibility with M3.2a Canvas 2D client.** Build replaced entirely.
- **No multi-monitor / multi-canvas support.** M4 territory.
- **No auto-reconnect on `device.lost`.** Future milestone.
- **No content-class predicate for `indices_raw` selection.** M3.2b unconditionally promotes thin → `indices_raw` whenever client supports it; M3.5 may add a heuristic.
- **No client-side metrics export.** Existing `decoder.ts` counters are local-only; no WebTransport metrics stream in scope.

## Phase ordering after M3.2b

```
M3.2a (shipped 2026-05-13)  ─►  server GPU encode + CPU Canvas 2D client
        ↓
M3.2b (this spec)            ─►  client WebGPU migration (every codec)
        ↓
M3.3                         ─►  CDF 5/3 + multi-pass refinement
        ↓
M3.4                         ─►  BC1 (conditional per M3.5 dominance check)
        ↓
M3.5                         ─►  bench publication + threshold tuning + BC1 fate
```

M3.3 builds directly on the M3.2b framebuffer + compute-decode infrastructure. The CDF 5/3 inverse transform compute shader writes into the same framebuffer texture as the PalRLE shader; bit-plane refinement passes append to the same per-rAF compute dispatch shape.
