# M3.3a — CDF 5/3 Server-Side Encoder + Multi-Pass Scheduling — Design

**Date:** 2026-05-25
**Milestone:** M3.3a (first slice of the M3.3 "CDF 5/3 + progressive refinement" milestone). Ships the server-side encoder, wire format, and scheduler integration behind a feature flag. Client decode + visible rendering land in M3.3b.
**Umbrella reference:** `docs/superpowers/specs/2026-04-28-m3-codec-suite-design.md` § Phase M3.3 + Decision D11 (per-codec brainstorm required before writing-plans).
**Predecessor:** `docs/superpowers/specs/2026-05-25-h264-tilecodec-handoff-design.md` (the H264→TileCodec mode-flip handoff is the substrate this codec builds on — once the handoff fires, classifier picks Cdf53 for high-color tiles).

## Context

After M3.2 + the H264→TileCodec handoff, the GPU classifier picks:
- **Solid** for `unique_colors ≤ 1` (lossless within content)
- **PalRle** for `unique_colors ≤ 16` (lossless within content)
- **Raw** for `unique_colors > 16` (one-shot 4 KB lossless)

M3.3 introduces **CDF 5/3** as the lossless codec for high-color tiles (>16 unique colors), displacing Raw. The wavelet codec delivers lossless via multi-pass progressive bit-planes — ~14 passes × ~140 bytes ≈ ~2 KB total per tile vs Raw's 4 KB. Bandwidth halved at equivalent quality.

The work splits into two cycles:

- **M3.3a (this spec)**: server-side encoder + scheduler + wire format + classifier rule, feature-flagged off by default. No client decode. Lets the encoder/wire format mature and be tested in isolation before client decode lands.
- **M3.3b (next cycle)**: WebGPU client decode + e2e SSIM lossless build-up gate + flag default flip + Raw retirement in classifier.

The umbrella spec's M3.3 envelope had Cdf53 *refining on top of* a lossy snapshot (Bc1/PalRle/Solid). That interpretation is obsolete in M3.2+: PalRle/Solid are already lossless within their content classes, and Bc1 is deferred to M3.4 (conditional on M3.5 bench). The new model is **Cdf53 = the lossless codec for high-color tiles** — a sibling of Solid/PalRle, not a refinement layer.

## Goal

Land **all server-side and wire-protocol changes** needed for CDF 5/3 — encoder, wire format, classifier rule, multi-pass scheduler integration with bandwidth-fraction partition, HELLO capability negotiation. After M3.3a, the server picture for Cdf53 is feature-complete; M3.3b is a focused client-decode + flag-flip cycle.

Tests verify wire emission + GPU/CPU forward-transform equivalence + round-trip property + scheduler behavior + capability gating. End state:

- With `GHOSTFRAME_ENABLE_CDF53=1` AND client advertising `supports_cdf53: true`, the GPU classifier picks `CodecState::Cdf53` for high-color tiles, the GPU pipeline runs forward CDF 5/3 in a new Stage 4 (indirect-args dispatch), Phase B extracts 14 bit-planes per tile, the scheduler enqueues all passes, the refinement bandwidth fraction partitions tick() output between new dirty tiles and refinement passes, and `Codec::Cdf53 (6)` datagrams flow to the client.
- Without either gate, no behavioral change (classifier picks Raw, current behavior preserved).
- The `decode_cdf53_passes` Rust function in `encoder/cdf53.rs` serves as the algorithmic reference for both M3.3a's GPU=CPU equivalence test and M3.3b's WGSL inverse compute shader (porting source, not WASM-deployed).

## Architecture

### Data flow

```
GPU pipeline (Stage 4, new)
  Input: BGRA tile from imported DMA-BUF (same source PalRle uses)
  Forward CDF 5/3 lifting, 3 levels, in-place integer transform
  Output: cdf53_coefficients_buffer (HOST_VISIBLE | HOST_COHERENT)
          1024 i16 per channel × 3 channels (BGR — alpha dropped) per dirty tile slot

CPU Phase B (alongside existing PalRle Phase B)
  For each tile classified Cdf53:
    Read 3 × 1024 i16 coefficients from GPU buffer
    Extract bit-planes MSB → LSB (sign-bit-plane first, then 13 magnitude bit-planes)
    RLE-encode each bit-plane per channel
    Optionally LZ4 (per-tile lz4 flag per existing protocol)
    Build 14 per-pass payloads (~140 bytes typical, all-zero passes ~1-2 bytes)

CPU Phase C (Scheduler)
  scheduler.enqueue_refinement(tile_x, tile_y, gen, 14_passes)
  Adds 14 TileWork entries (pass_idx 0..=13) for one tile
  Round-robin in pass-major order — every tile pass 0 → every tile pass 1 → ...
  bump_generation cancels in-flight passes across all pass_idx
```

### Wire format

`Codec::Cdf53 = 6` (already in the protocol enum since M2). Existing TileHeader bytes already accommodate:
- `[2]` codec discriminator (codec << 1 | lz4)
- `[3]` `(gen << 4) | pass_idx` — 4 bits each, supports pass_idx 0..=15 (we use 0..=13)

Per-pass payload structure:
```
[u16 BE len_B]   [len_B bytes RLE-encoded bit-plane B for pass i]
[u16 BE len_G]   [len_G bytes RLE-encoded bit-plane G for pass i]
[u16 BE len_R]   [len_R bytes RLE-encoded bit-plane R for pass i]
```

**Each pass carries all three channels' bit-plane for that pass-index** (channel-grouped within a pass). Visual implication: after pass `i` lands, client has bit-plane `i` for all of B, G, R — the tile fades up uniformly in quality across channels. No "channel-finished-ahead-of-others" artifacts.

**RLE scheme:** one byte per encoding token — high bit clear means literal byte (7-bit data), high bit set means zero-run (1..=128 bits of zero). Same shape as PalRle's nibble-RLE for symmetry, applied to bit-plane bytes.

**LZ4:** per-tile flag in TileHeader byte [2] bit 0. Encoder compresses the RLE-packed payload with LZ4 and emits with `lz4=1` if the result is strictly smaller; otherwise `lz4=0` with the raw RLE bytes.

### Channel handling — BGR only, drop alpha

Alpha is always 0xFF for screen content (the existing protocol's TILE_DATAGRAM_FLAG uses the high bit of `frame_seq`, not alpha). Encoder skips alpha; client decoder fills alpha = 0xFF post-decode. Saves 25% bandwidth + encode/decode time. Same simplification used by JPEG and most video codecs for opaque content.

### Pass count — fixed 14

P2 from the brainstorm: every Cdf53 tile emits exactly 14 passes (1 sign-bit-plane + 13 magnitude bit-planes, covering worst-case 14-bit signed coefficients). All-zero bit-planes RLE-encode to ~1-2 bytes. The client always processes 14 passes per tile — simplest state machine, robust to per-tile content variance.

Variable-pass-count protocol (umbrella's implicit P3) is deferred to M3.5 if bench data motivates it. The estimated ~10% bandwidth savings doesn't justify the protocol complexity for M3.3a.

## Components

### 1. Vulkan compute shader — `capture/shaders/cdf53_forward.comp`

**Algorithm:** integer CDF 5/3 lifting, 3 levels of 2D decomposition. Per level:
1. Horizontal pass: split rows into even/odd indices; high-pass `H_i = c_{2i+1} - floor((c_{2i} + c_{2i+2}) / 2)`; low-pass `L_i = c_{2i} + floor((H_{i-1} + H_i + 2) / 4)`.
2. Vertical pass: same transform applied to columns of the horizontal result.
3. Next level operates on the LL subband only (top-left quadrant of the previous output).

Output layout per channel (1024 coefficients):
```
[LL3:16][LH3:16][HL3:16][HH3:16]       — level 3 (4×4 quadrants packed)
[LH2:64][HL2:64][HH2:64]                — level 2 detail
[LH1:256][HL1:256][HH1:256]             — level 1 detail
```

**Dispatch geometry — multi-dispatch for portability margin:**

Three Vulkan dispatches per frame, one per decomposition level. Each dispatch keeps workgroup_size ≤ 256 invocations (portability ceiling; protects against limits like Mesa's 256 cap that bit M3.2c). `vkCmdPipelineBarrier` (compute → compute, shader-write → shader-read) between dispatches. Coefficient buffer is updated in-place across levels.

- **Level 1**: 4 workgroups per tile, workgroup_size = (16, 16, 1) = 256 invocations each, covering 32×32 in four 16×16 quadrants. Total invocations per tile = 1024.
- **Level 2**: 1 workgroup per tile, workgroup_size = (16, 16, 1) = 256 invocations, covering the 16×16 LL1 input.
- **Level 3**: 1 workgroup per tile, workgroup_size = (8, 8, 1) = 64 invocations, covering the 8×8 LL2 input.

Dispatch count `(tile_count_x * tile_count_y, 1, 1)` for each level (tiles indexed by workgroup_id.x).

### 2. GPU pipeline integration — Stage 4 (indirect-args dispatch)

Three sub-stages in `gpu_pipeline/frame.rs`, runs after Stage 1 (SAD dirty detection) + tile_analysis and independent of Stages 1.5-3 (PalRle pipeline). Energy-efficient: only Cdf53-classified tiles get the forward transform. Mirrors the existing `palrle_compact` + `palrle_indirect_args` + downstream-shader pattern.

**Stage 4a — `cdf53_compact.comp`:** reads `tile_analysis` output (per-tile `unique_colors`), writes a compact list of Cdf53-eligible tile indices to `cdf53_compact_list: vk::Buffer` along with `cdf53_compact_count: u32` (atomic counter). Predicate: `unique_colors > 16 AND unique_colors != UNIQUE_COLORS_UNKNOWN_SENTINEL`. Dispatch geometry: 1 workgroup per tile (small workgroup_size, e.g., 32×1×1 with one invocation handling several tiles).

**Stage 4b — `cdf53_indirect_args.comp`:** reads `cdf53_compact_count`, writes Vulkan indirect-dispatch args `(num_workgroups_x, 1, 1)` to `cdf53_dispatch_args: vk::Buffer`. Identical shape to existing `palrle_indirect_args.comp`. Trivial 1-invocation shader.

**Stage 4c — `cdf53_forward.comp`:** three Vulkan dispatches via `vkCmdDispatchIndirect` reading `cdf53_dispatch_args`, one per decomposition level. Each invocation reads its tile index from `cdf53_compact_list[workgroup_id.x]` and operates on the corresponding tile's coefficients. Idle tiles classified as Solid/PalRle/Raw are SKIPPED — no GPU cycles wasted.

**Allocation:**
- `cdf53_compact_list: vk::Buffer` (DEVICE_LOCAL, GPU-only): `max_tiles × 4 bytes (u32)` ≈ 4 KB for max_tiles=1024.
- `cdf53_compact_count: vk::Buffer` (DEVICE_LOCAL): 4 bytes.
- `cdf53_dispatch_args: vk::Buffer` (DEVICE_LOCAL, `INDIRECT_BUFFER` usage): 16 bytes (3 u32 + padding).
- `cdf53_coefficients_buffer: vk::Buffer` (HOST_VISIBLE | HOST_COHERENT, persistently mapped). Size = `max_tiles × 3 channels × 1024 coefficients × 2 bytes (i16)` ≈ 6 MB for max_tiles=1024. Sized at processor construction time; same `max_tiles` constructor parameter that bounds the other buffers.

**Coefficient encoding:** signed 16-bit integers (`i16`). Worst-case 14-bit signed values; the extra 2 bits give us room without saturation concerns.

**Read access:** Phase B reads via a stable raw pointer (`cdf53_coefficients_ptr: *const i16`) and a `cdf53_compact_count_ptr: *const u32` (HOST_VISIBLE copy of the atomic counter) telling Phase B how many tiles were classified Cdf53 this frame. Same pattern as `palrle_compact_list_ptr`, `palrle_compact_count_ptr`, etc. Pointer validity spans the lifetime of the GpuFrameProcessor (until resolution change re-allocates).

**First-frame path:** Stage 4 runs in the first-frame path including `run_first_frame_passes`. No dependency on `prev_image`. Same as the existing `tile_analysis` stage. Mirrors the M3.2c first-frame fix for PalRle stages.

### 3. Bit-plane extraction (CPU) — `encoder/cdf53.rs`

New module. Two functions:

```rust
/// Encode a tile's coefficients into 14 progressive bit-plane passes.
pub fn encode_cdf53_passes(coefficients: &[i16]) -> Vec<Vec<u8>>;

/// Reference inverse: reassemble coefficients from N bit-plane passes,
/// run inverse CDF 5/3 lifting, return BGR pixels (3 channels × 1024 = 3072 bytes).
/// Used by unit tests and as the porting source for M3.3b's WGSL inverse
/// compute shader. NOT compiled to WASM for deployment.
pub fn decode_cdf53_passes(passes: &[&[u8]]) -> Vec<u8>;
```

`encode_cdf53_passes` produces exactly 14 payloads:
- Pass 0: sign-bit-plane (one bit per coefficient: 1 if negative, 0 otherwise)
- Pass 1..13: magnitude bit-plane from bit 12 down to bit 0

Each pass: 3 channels (B, G, R), each channel 1024 bits = 128 bytes raw, RLE-encoded.

**RLE codec** as a private helper in the same module:
- Input: `&[u8]` (128 bytes per channel per pass)
- Output: `Vec<u8>` (typically 1-50 bytes after RLE for high-frequency bit-planes which have many zeros)
- Round-trip property tested

### 4. Multi-pass scheduler with refinement bandwidth fraction — `transport/scheduler.rs`

New public methods + state:

```rust
pub struct Scheduler {
    // ... existing fields ...

    // Two work queues partition tick() output by priority.
    priority_queue: SchedulerQueue,    // existing single-pass codec emissions (was `queue`)
    refinement_queue: SchedulerQueue,  // multi-pass Cdf53 emissions

    // Bandwidth fraction allocated to refinement_queue per tick.
    // Default 0.2 (20% refinement, 80% new dirty tiles).
    // Adaptive: halves on sustained ACK loss <0.5 over 10 rounds (min 0.05).
    // Restores doubles on recovery >0.8 over 10 rounds (max 0.2).
    refinement_bandwidth_fraction: f32,

    // Sliding-window ACK delivery rate tracking for adaptive logic.
    delivery_window_emitted: u32,
    delivery_window_acked: u32,
    low_delivery_rounds: u32,
    high_delivery_rounds: u32,
}

impl Scheduler {
    pub fn enqueue_refinement(
        &mut self,
        tile_x: u8,
        tile_y: u8,
        gen: u8,
        all_passes: Vec<Vec<u8>>,    // exactly CDF53_PASS_COUNT = 14 payloads
    );

    pub fn tick(&mut self, budget_bytes: usize) -> Vec<ResolvedTileWork>;

    pub fn on_ack(&mut self, tile_x: u8, tile_y: u8, gen: u8, pass: u8) -> Vec<ResolvedTileWork>;

    /// Test/diagnostic accessor. Returns current adaptive fraction in [0.05, 0.2].
    pub fn current_refinement_fraction(&self) -> f32;
}
```

`enqueue_refinement` enqueues 14 `TileWork` entries sharing `(tile_x, tile_y, gen)`, distinguished by `pass_idx = 0..=13`, with `total_passes = 14`, into `refinement_queue`.

**Ordering within each queue:** pass-major round-robin — every tile sends pass 0 before any tile sends pass 1. Implementation: existing cursor advanced in pass-major order. For `priority_queue` this is trivially pass-major (all entries are pass 0); for `refinement_queue` it sorts-by-pass-then-cursor.

**Budget partition in `tick(budget_bytes)`:**
1. Compute `refinement_budget = (budget_bytes as f32 * current_refinement_fraction()) as usize`.
2. Compute `priority_budget = budget_bytes - refinement_budget`.
3. Drain `priority_queue` up to `priority_budget` (existing behavior).
4. Drain `refinement_queue` up to `refinement_budget`.
5. If either queue is empty and the other has spare work, the spare half is repurposed (no wasted bandwidth — if there's nothing to refine, all budget goes to priority and vice versa).
6. Record `delivery_window_emitted += work_emitted_this_tick` for adaptive logic.

**Adaptive fraction logic** (called at the end of each `tick`):
- Compute `rate = delivery_window_acked / delivery_window_emitted` (clamped to 1.0 if no work emitted).
- If `rate < 0.5`: increment `low_delivery_rounds`; if it reaches 10, halve `refinement_bandwidth_fraction` (floor 0.05), reset the counter.
- If `rate >= 0.8`: increment `high_delivery_rounds`; if it reaches 10, double `refinement_bandwidth_fraction` (ceiling 0.2), reset the counter.
- Otherwise (0.5 ≤ rate < 0.8): keep fraction stable, decay both streak counters toward 0.
- Reset both window counters each round (sliding window of 1 round; can be widened later if M3.5 motivates).

`on_ack` increments `delivery_window_acked` in addition to its existing supersession-handling.

**Cancellation:** existing `bump_generation` logic already iterates all in-flight work for a tile across both queues and marks stale-gen entries as `Superseded`. The two-queue split is internal; existing public API behavior is preserved.

### 5. Classifier rule update — `tile/classifier.rs`

Current state: Rule 8 (`tile/classifier.rs:164`) routes high-color tiles to `CodecState::Cdf53 { passes_sent: 0, max_passes: N }` where N was a placeholder. M3.3a:

- `CDF53_PASS_COUNT` becomes a public constant (= 14) in `encoder/cdf53.rs` or `tile/mod.rs`.
- Rule 8 sets `max_passes: CDF53_PASS_COUNT`.
- Rule fires only when `cdf53_enabled` (Section 6 flag); otherwise classifier returns `CodecState::Raw` (current M3.0 fallback behavior preserved verbatim).

The "Cdf53-feasible" predicate is just `unique_colors > 16 AND classifier.cdf53_enabled` — no `idle_frames > 30` gate. The umbrella spec's idle gate was for refinement-on-top-of-lossy-snapshot; with Cdf53 as the lossless codec, it fires immediately on classification.

### 6. Two-layer gating — env var + HELLO capability bit

M3.3a emits Cdf53 only when **both** conditions hold:

1. **Server operator intent**: `GHOSTFRAME_ENABLE_CDF53=1` env var set at xdaemon start.
2. **Client capability**: HELLO message carries `supports_cdf53: true`.

```rust
// io_bridge per-tile emission decision (pseudocode):
if self.cdf53_enabled && session_caps.supports_cdf53 {
    // emit Cdf53
} else {
    // fall back to Raw (preserves M3.0 behavior)
}
```

#### Server-side env flag — `GHOSTFRAME_ENABLE_CDF53`

```rust
// IoBridge::new (or equivalent construction site)
let cdf53_enabled = std::env::var("GHOSTFRAME_ENABLE_CDF53")
    .map(|v| v == "1" || v.eq_ignore_ascii_case("true"))
    .unwrap_or(false);
```

Cached in `IoBridge::cdf53_enabled: bool` (set once at construction). **Default: off** in M3.3a; M3.3b flips the default to on alongside client decode.

#### Wire protocol — HELLO `supports_cdf53` field

Existing HELLO message format (per M3.2b) already carries client capabilities like `indices_raw_enabled`. M3.3a adds a `supports_cdf53: bool` field. Wire encoding details (bit position in the caps byte, byte ordering) deferred to the implementation plan; precedent: M3.2b `indices_raw_enabled` parsing in `transport/io_bridge.rs` at the `HELLO received, client capabilities updated` log line.

**Per-session storage:** add `supports_cdf53: bool` to whatever per-session capability struct holds `indices_raw_enabled` today. Defaults to `false` (backward-compatible with M3.2 clients that don't include the field).

#### Client-side advertisement — M3.3a

The web client TS code that builds the HELLO message gains one line: emit `supports_cdf53: true` in the capability set. This is a **forward-looking advertisement** — in M3.3a the client cannot actually decode Cdf53 yet (decode lands M3.3b), but the wire protocol allows datagrams that the client may drop. Since the server env flag is **off by default in M3.3a production**, the only place Cdf53 actually emits is in tests where the env flag is explicitly set; in those tests the client must advertise capability for the gate to pass.

Production safety: M3.3a deployed alongside an M3.3a-or-newer client → env flag off → no Cdf53 ever emits, regardless of the client's advertised capability. The advertisement is harmless until M3.3b ships actual decode.

Production safety with **stale M3.2-era client** (no `supports_cdf53` field): defaults to `false` → Cdf53 never emits even if env flag is on. Safe.

**Why two layers (env + HELLO capability):**
- Env flag = operator intent. Lets staged rollout / dev/debug toggle without redeploying the client.
- HELLO bit = client capability declaration. Prevents emission to a client that can't decode (M3.2 stale clients, future incompatible-version mismatches).
- Both gates required → safety in depth. Either one defaulting to false prevents emission.

Env-var precedent in the codebase: `GHOSTFRAME_SKIP_PALETTE_SESSION_RESET`, `GHOSTFRAME_DUMP_NV12_ON_IDR`, `GHOSTFRAME_INJECT_OOB_PALRLE`.

### 7. io_bridge wire-up

In `process_frame_gpu` (or its Phase B helper), after the existing PalRle Phase B block:

```rust
if self.cdf53_enabled && session_caps.supports_cdf53 {
    for tile_xy in dirty_tiles_classified_as_cdf53 {
        let coeffs = read_cdf53_coefficients_from_gpu(tile_xy);
        let passes = cdf53::encode_cdf53_passes(&coeffs);
        let gen = self.scheduler.bump_generation(tile_xy.0, tile_xy.1);
        self.scheduler.enqueue_refinement(tile_xy.0, tile_xy.1, gen, passes);
    }
}
```

The per-session `session_caps.supports_cdf53` is read from the HELLO message stored per-session.

Each enqueued pass goes through `dispatch_dirty_tiles_via_scheduler`'s tick → fragment_tile → datagram flow. The existing `SchedulerEmissionPolicy::GpuClassifierDriven` policy already handles Cdf53 since the codec discriminator is read from the TileWork.

## Testing

### Unit tests

1. **Forward + inverse roundtrip (Rust, no GPU).** Property test in `encoder/cdf53.rs`'s test module: random tile pixels → `encode_cdf53_passes` then `decode_cdf53_passes` (with all 14 passes) → assert exact reconstruction. Verifies the algorithm + bit-plane extraction + RLE roundtrip.

2. **Truncated-pass SSIM monotonicity.** Property test: drop bottom K bit-planes from the encoded passes, decode → SSIM strictly non-decreasing as K decreases. Verifies the lossless build-up invariant.

3. **GPU = CPU forward.** Vulkan-soft-skip pattern (matches existing `gpu_pipeline::tests` skip-on-no-Vulkan style). Construct `GpuFrameProcessor`, feed a known BGRA tile, dispatch only Stage 4 (or full pipeline), read coefficients via `cdf53_coefficients_ptr`, compare to CPU `cdf53::reference_forward(pixels)` — assert exact match across all 1024 × 3 coefficients.

4. **GPU indirect-args dispatch.** Vulkan-soft-skip pattern. Construct `GpuFrameProcessor`, feed a frame where some tiles classify Cdf53 (>16 colors) and others classify Solid/PalRle. Run full pipeline. Read `cdf53_compact_count_ptr` and `cdf53_compact_list`. Assert the compact list contains exactly the Cdf53-eligible tile indices, and the coefficient buffer entries for non-Cdf53 tiles are untouched (zero or stale — implementer's choice, tested either way).

5. **Scheduler pass-major round-robin.** Existing `transport/scheduler` unit-test module: enqueue 2 tiles × 14 passes via `enqueue_refinement`, drain `tick()` calls one-at-a-time, assert order is `(t0, p0), (t1, p0), (t0, p1), (t1, p1), ..., (t0, p13), (t1, p13)`.

6. **`bump_generation` cancels multi-pass work.** Extension of an existing scheduler test: enqueue 14 passes for tile T, call `bump_generation(T)`, assert all 14 in-flight entries marked `Superseded` regardless of `pass_idx`.

7. **Refinement bandwidth fraction respects budget.** Unit test: enqueue 10 priority tiles + 100 refinement passes, call `tick(budget=large)`. Assert ratio of refinement work to total work emitted ≈ `current_refinement_fraction()` (default 0.2), within tolerance for budget-rounding boundary effects.

8. **Refinement bandwidth fraction adaptive halving.** Unit test: simulate 10 ticks with low ACK delivery (work emitted but no `on_ack` calls). Assert `current_refinement_fraction()` halves to 0.1, then 0.05 floor. Then simulate 10 ticks with high ACK delivery (every emission gets `on_ack`). Assert fraction restores toward 0.2.

9. **Refinement bandwidth fraction respects empty-queue repurposing.** Unit test: enqueue 100 refinement passes only (no priority work). Call `tick(budget=large)`. Assert refinement queue gets the full budget (not just 20%), because priority queue is empty and unused budget is repurposed.

10. **HELLO `supports_cdf53` parsing.** Unit test in `transport/protocol.rs` (or wherever HELLO parsing lives): synthesize a HELLO byte stream with `supports_cdf53` bit set, parse, assert capability struct reflects it. Then parse a M3.2-era HELLO (no `supports_cdf53` field): assert defaults to false. Backward-compat check.

11. **Gating logic — env + capability.** Unit test on the per-tile emission decision: combinations of `(cdf53_enabled, supports_cdf53)` ∈ {(F,F), (F,T), (T,F), (T,T)}. Assert only the (T,T) case allows Cdf53 emission; all others fall back to Raw.

### E2E tests

Three new e2e tests cover the wire-emission path: a focused Cdf53-only test, a codec-mixing test, and a flag-off regression check.

**Test pattern dependency:** M3.3a adds a new `--gradient` test pattern mode in `ghostframe-test-pattern` (full-screen smooth gradient — diagonal blue-to-red is the simplest implementation that puts >16 unique colors in every tile). The existing `--mixed` pattern provides codec-mixing content (solid + text + gradient + spinner regions).

**`e2e_cdf53_gradient_emission` (new).** Pure-Cdf53 assertion using the new `--gradient` pattern:

```rust
#[tokio::test(flavor = "multi_thread")]
async fn e2e_cdf53_gradient_emission() -> Result<()> {
    let setup = setup_e2e_webgpu_gpu_with_env(
        "--gradient --drm-direct",
        &[("GHOSTFRAME_ENABLE_CDF53", "1")],
    ).await?;
    // Let the H264 burst + handoff fire + Cdf53 emissions accumulate.
    tokio::time::sleep(Duration::from_secs(5)).await;

    // Every tile in the gradient is high-color → all tile-codec emissions
    // post-handoff should be Cdf53.
    let codec_list: Vec<u8> = setup.page.evaluate("window.__ghostframeRecordedCodecs || []")
        .await?.into_value()?;
    let cdf53_count = codec_list.iter().filter(|&&c| c == 6).count();
    let non_cdf53_tile_count = codec_list.iter()
        .filter(|&&c| c != 6 && c != 0 /* Skip not counted */).count();
    assert!(cdf53_count > 0, "expected Codec::Cdf53 (6) on wire; saw: {codec_list:?}");
    assert!(cdf53_count > non_cdf53_tile_count * 5,
        "expected gradient to be dominated by Cdf53 emissions, but saw \
         cdf53_count={cdf53_count} vs non_cdf53_tile_count={non_cdf53_tile_count}");

    // Server log: at least one tile's full 14-pass sequence emitted.
    let logs = read_server_logs_stripped(&docker, "ghostframe::cdf53").await?;
    assert!(logs.lines().filter(|l| l.contains("cdf53.emit")).count() >= 14,
        "expected ≥ 14 cdf53.emit log lines; got:\n{}", logs);
    Ok(())
}
```

```rust
        .await?.into_value()?;

    // Mixed content should yield at least three distinct codecs:
    // - Solid (4): the solid-red region
    // - PalRle (2): the text region (≤16 colors per tile)
    // - Cdf53 (6): the gradient region (>16 colors per tile)
    assert!(codec_list.contains(&4u8),
        "expected Codec::Solid (4); saw: {codec_list:?}");
    assert!(codec_list.contains(&2u8),
        "expected Codec::PalRle (2); saw: {codec_list:?}");
    assert!(codec_list.contains(&6u8),
        "expected Codec::Cdf53 (6); saw: {codec_list:?}");
    Ok(())
}
```

**`e2e_cdf53_flag_off` (new, regression check).** Without the env flag, classifier falls back to Raw for high-color tiles (preserves current M3.2 behavior):

## Out of scope

### Deferred to M3.3b

- **Client decode.** WebGPU compute shader inverse transform + coefficient accumulator. Per the user's clarification during the brainstorm, M3.3b targets **GPU/WebGPU client decode wherever meaningfully possible** — the bulk inverse transform belongs on WebGPU compute; tiny per-pass preprocessing (RLE unpack, bit-plane reassembly) may stay CPU if compute-dispatch overhead exceeds the work. The exact split is M3.3b's brainstorm.
- **Visible rendering of Cdf53 tiles on the client canvas.**
- **E2E SSIM lossless build-up gate (`e2e_progressive_refinement`).** Requires client decode.
- **Default flag flip (Cdf53 becomes production high-color path).** Conditioned on M3.3b's client decode landing.
- **Raw codec retirement in classifier.** Rule swap from `Raw` → `Cdf53` as the default high-color path. Wire-protocol `Codec::Raw = 5` discriminant stays for CPU-fallback emission (per M3.1 D13 — CPU path is always Raw).
- **C6 proptest re-enable.** Umbrella spec's classifier invariant requiring H.264 → idle transition via lossy intermediate codec. Needs end-to-end refinement to verify; M3.3b's e2e covers this transitively.

### Deferred to M3.3c (optional)

- **GPU bit-plane extraction.** Move Phase B's bit-plane work to Vulkan compute if M3.5 bench motivates. Server-side perf optimization only.

### Deferred to M3.4 (conditional)

- **Bc1.** Conditional on M3.5 bench dominance check.

### Deferred to M3.5

- **`BenchEncoder` impl** for CDF 5/3 (`ghostframe-bench/benches/codec_latency.rs`).
- **Threshold tuning** based on bench data.
- **Raw-vs-Cdf53 bandwidth dominance check.** May lead to Cdf53 displacing Raw not just for high-color but for all tiles where the wavelet representation beats one-shot lossless.
- **Variable pass count per tile (P3-style adaptive).** Bandwidth-optimal but more complex protocol; gated on bench data showing meaningful improvement.

## Decision register

| # | Decision | Rationale |
|---|---|---|
| D1 | CDF 5/3 displaces Raw as the lossless codec for high-color tiles, NOT a refinement layer on top of a lossy snapshot | Umbrella spec's refinement-on-lossy model assumed Bc1 (M3.4, conditional). With the H264→TileCodec handoff already delivering lossless content, refinement-as-a-codec is the simpler architecture. |
| D2 | Two-cycle slice: M3.3a (server, flag-off) → M3.3b (client decode, flag-on) | Decouples server-side encoder maturity from client-side rendering. Server can be tested in isolation; client decode lands as a swap-and-flip. Avoids a regression window from "server emits Cdf53, client drops" (which would hide high-color tiles). |
| D3 | Fixed 14-pass count (P2 from brainstorm) | Simplest client state machine; all-zero bit-planes RLE to 1-2 bytes (negligible overhead); robust to per-tile content variance. Variable pass count (P3) deferred to M3.5 if bench motivates. |
| D4 | GPU-first encoder (Vulkan compute Stage 4), not CPU | Matches the project's GPU-first principle. Cost is acceptable: ~0.4 ms per frame on CPU was possible, but the Vulkan compute path keeps the architecture consistent and runs faster on real workloads. |
| D5 | Multi-dispatch (3 dispatches, one per decomposition level), workgroup_size ≤ 256 | Portability margin — the M3.2c W3/B1 root cause was a 1024-invocation workgroup that silently failed validation on Mesa Vulkan. ≤ 256 keeps us safe across server-side Vulkan implementations. |
| D6 | Bit-plane extraction on CPU (Phase B), not GPU | RLE is inherently serial; per-tile work is small (~0.1 ms per tile); GPU compute would add complexity for marginal gain. M3.3c may move to GPU if M3.5 bench motivates. |
| D7 | Each pass carries all 3 BGR channels' bit-plane (uniform build-up across channels) | Avoids "first R goes lossless then G then B" artifact. Channel-grouped within a pass (B then G then R) for RLE efficiency; per-pass payload spans all channels for uniform visual progression. |
| D8 | Skip alpha channel (BGR only, fill 0xFF on client) | Alpha is always opaque for screen content. 25% bandwidth + encode/decode savings. Same simplification used by JPEG and most video codecs. |
| D9 | Pass-major round-robin scheduler ordering (every tile pass 0 → every tile pass 1 → …) | Maximizes "every tile improves together" — user sees uniform progressive refinement across the whole screen rather than one tile finishing fully before the next starts. Matches umbrella spec § M3.3 scheduling. |
| D10 | Refinement bandwidth fraction **included in M3.3a** (revised from initial brainstorm) | Per user direction during brainstorm: "all server changes for Cdf53 land in this round" — bandwidth fraction is a server-side concern that belongs with the rest of the server work. Adaptive halving + restoration logic spans [0.05, 0.2]. See D17 for detail. |
| D11 | Feature flag = env var (`GHOSTFRAME_ENABLE_CDF53`) **plus** HELLO capability bit (revised) | Initially server-side env var only; revised to two-layer gating per user direction. Both gates required (defense in depth). See D16 for detail. |
| D12 | Algorithmic source of truth = Rust `cdf53.rs` | Single canonical implementation for: (a) unit tests, (b) M3.3a GPU/CPU equivalence check, (c) M3.3b WGSL inverse shader porting source. Not WASM-deployed to the client — M3.3b uses WebGPU compute. |
| D13 | i16 coefficient storage (not i14 packed) | Worst case 14-bit signed; extra 2 bits give safety against saturation. CPU and GPU agree on i16 layout. Buffer size 6 MB worst case (max_tiles=1024) is acceptable. |
| D14 | Stage 4 uses indirect-args dispatch (compact list → indirect args → forward) — only Cdf53-classified tiles get the forward transform | Energy-efficient: idle tiles classified Solid/PalRle/Raw skip the GPU forward pass entirely. Mirrors the existing palrle_compact + palrle_indirect_args pattern. |
| D15 | Two e2e test patterns: new `--gradient` (pure Cdf53) + existing `--mixed` (codec-mixing verification) | `--gradient` is unambiguous for Cdf53-only assertions; `--mixed` ensures classifier still routes content classes correctly when Cdf53 is in the mix. |
| D16 | Two-layer gating: env flag (`GHOSTFRAME_ENABLE_CDF53`) AND HELLO capability bit (`supports_cdf53`) | Defense in depth. Env flag = operator intent (default off in M3.3a). HELLO bit = client capability declaration. Either gate defaulting to false prevents emission. Stale M3.2-era clients without the field default to false → safe. |
| D17 | Refinement bandwidth fraction lands in M3.3a (not deferred) | Server-side completeness. M3.3a is "all server changes for Cdf53". Adaptive halving on sustained ACK loss (<0.5 over 10 rounds) and restoration on recovery (>0.8 over 10 rounds). Bounded [0.05, 0.2]. |
| D18 | Empty-queue budget repurposing in `tick()` | If priority queue is empty, refinement queue gets the full budget (not just 20%). Avoids wasted bandwidth in pure-refinement or pure-priority scenarios. |
