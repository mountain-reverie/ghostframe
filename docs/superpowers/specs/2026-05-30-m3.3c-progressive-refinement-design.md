# M3.3c — Progressive Refinement to PixelPerfect (Idle-Escalation + Acceptance Tests)

**Date:** 2026-05-30
**Phase:** M3.3c (final M3.3 piece; closes the umbrella's M3.3 acceptance gates from `2026-04-28-m3-codec-suite-design.md`).
**Prereqs landed:** M3.3a (server CDF 5/3 forward + scheduler refinement queue), M3.3b (client integrate + inverse).

## 1. Motivation

M3.3a and M3.3b ship a working CDF 5/3 forward + inverse: dirty high-color tiles classified as `Cdf53` emit 14 progressive bit-plane passes and the client integrates them into a lossless reconstruction. The umbrella M3.3 spec calls out two acceptance gates that aren't covered yet:

1. `e2e_progressive_refinement` — SSIM on an idle region monotonically increases over time and converges to 1.0 (lossless).
2. `e2e_refinement_cancel` — a tile content change during refinement cancels remaining passes for the old generation.

And the spec's "refinement entry trigger" — tiles displayed via a lossy snapshot become eligible for CDF 5/3 refinement once they've been idle long enough — is not implemented. Today the only path into `CodecState::Cdf53` is the per-frame dirty classification (Rule 8). Tiles that were classified as `H264`/`Bc1`/`PalRle`/`Solid` then went idle stay at their lossy-snapshot quality forever.

This work fills both gaps:
- Implements the idle-escalation trigger so any tile that's been static long enough and is currently displayed at less-than-lossless quality gets refined to lossless.
- Adds the two acceptance e2e tests.
- Tightens `e2e_mode_switch` per the existing `project_m33_static_refinement.md` note (refinement-emission during static halves should be observable as Frame→Tile dominance flips, not inferred from absence-of-H264).

## 2. Scope

### In scope
- `CodecState::PixelPerfect` lifecycle wired end-to-end (entry via "all 14 ACKed", exit via `bump_generation`).
- Per-frame CPU sweep in `io_bridge` that identifies escalation candidates and dispatches a second cdf53-forward pass on the GPU for them.
- Reuse of existing `cdf53_forward_l{1,2,3}` shaders with a parallel descriptor-set/buffer chain dedicated to escalation.
- New CPU module `tile/escalation.rs` with the pure escalation-candidate-detection predicate, unit-testable in isolation.
- `--mode-switch-cycle` test pattern extension: replace single-color static half with a three-stripe mixed-codec layout (solid + ≤16-color stripe + high-color gradient).
- Two new e2e tests: `e2e_progressive_refinement`, `e2e_refinement_cancel`.
- Tighten `e2e_mode_switch` to assert explicit Frame→Tile / Tile→Frame dominance flips and enable `GHOSTFRAME_ENABLE_CDF53`.

### Out of scope (deferred)
- BC1 codec implementation. The escalation trigger's source set includes `Bc1` for spec completeness, but no test exercises it because `Bc1` never emits in CDF53-on operation (Rule 5 only falls through to Bc1 when GPU metrics are sentinel-unknown).
- Bandwidth-budget tuning. Refinement still uses the existing `Scheduler::refinement_bandwidth_fraction = 0.2` with the adaptive halve/double on ACK delivery ratio.
- M3.5 (acceptance tests for the full M3 suite).
- Adaptive K (per-frame escalation cap). K is a fixed compile-time constant in this milestone.

## 3. Codec-state lifecycle

```
   ┌─────────────┐
   │ initial /   │
   │ Skip        │
   └──────┬──────┘
          │ dirty + classifier rule
          ▼
   ┌─────────────────────────────────────────────────┐
   │  H264 / Bc1 / PalRle / Solid / Cdf53            │ ◄── classifier sets per dirty frame
   └──────────────────┬──────────────────────────────┘
                      │ idle_frames > 30 AND
                      │ codec_state ∈ {H264, Bc1, PalRle, Solid}
                      │ AND !already_escalated_this_gen
                      ▼
              ┌──────────────────┐
              │ Cdf53 refinement │  (GPU forward → encode_passes → enqueue 14 passes)
              │ enqueued         │
              └────────┬─────────┘
                       │ scheduler tick budget drains passes
                       │ ACKs arrive (tracked, NOT gated)
                       ▼
              ┌──────────────────┐         dirty/content change:
              │ all 14 ACKed     │ ────► bump_generation → cancel
              │ → PixelPerfect   │       remaining passes for old gen
              └────────┬─────────┘       → tile re-enters classifier rules
                       │ tile remains static
                       ▼
              ┌──────────────────┐
              │ PixelPerfect     │  emits Skip every frame
              │ steady state     │  (escalation check fast-paths past)
              └──────────────────┘
```

### Invariants
- `already_escalated_this_gen` lives on `TileMetrics` next to `codec_state`. Reset by `Scheduler::bump_generation()` (or by the caller of `bump_generation`, whichever ends up cleaner during impl). Prevents the per-frame sweep from re-enqueueing the same tile every frame after escalation.
- Tiles entering `Cdf53` via the existing **dirty Cdf53 path** (Rule 8) reach PixelPerfect through the SAME ACK-tracking mechanism — no per-source plumbing.
- The escalation set includes `H264` (the highest-loss source in the system) even though the umbrella spec listed only `{Bc1, PalRle, Solid}`. H264 is the headline win: post-motion-cooldown tiles transition from H264-lossy to refined-lossless within ~hundreds of ms.
- Passes flow via the scheduler's tick budget, **NOT gated on per-pass ACKs**. ACK tracking has one purpose: signaling PixelPerfect transition. Loss recovery uses the existing datagram-level FEC + scheduler's per-pass ACK-timeout retry as fallback.

## 4. Server-side implementation

### 4.1 Layering

| Concern | Module |
|---|---|
| Pure escalation-candidate predicate (testable in isolation) | new `ghostframe-lib/src/tile/escalation.rs` |
| Per-frame orchestration: sweep, GPU buffer write, dispatch invocation, post-fence Phase B | `ghostframe-lib/src/transport/io_bridge.rs` |
| Vulkan buffer allocation + descriptor sets | `ghostframe-lib/src/capture/gpu_pipeline/setup.rs` + `mod.rs` |
| Command-buffer recording for the escalation forward dispatch chain | `ghostframe-lib/src/capture/gpu_pipeline/frame.rs` (new `run_cdf53_forward_escalation_stages`) |

This mirrors the existing layering for the dirty Cdf53 path: io_bridge orchestrates, gpu_pipeline owns Vulkan.

### 4.2 `tile/escalation.rs` (new)

```rust
/// Returns up to `k_max` tile indices eligible for idle-escalation, in
/// tile-idx order (row-major). Eligibility: idle_frames > 30 AND
/// codec_state ∈ {H264, Bc1, PalRle, Solid} AND !already_escalated_this_gen.
pub fn detect_escalation_candidates(
    metrics: &MetricsTracker,
    k_max: usize,
) -> Vec<u32>;
```

No I/O, no GPU. Single-threaded sweep over `metrics.iter()`. Unit-testable directly.

### 4.3 New `TileMetrics` field

```rust
pub struct TileMetrics {
    // ... existing fields ...
    pub already_escalated_this_gen: bool,
}
```

Reset to `false` by `Scheduler::bump_generation()` via the same callback mechanism that updates codec_state on bump (or, if simpler, by the io_bridge path that calls bump_generation; chosen during impl).

### 4.4 New Vulkan resources

In `GpuFrameProcessor`:

| Resource | Size | Memory | Purpose |
|---|---|---|---|
| `cdf53_escalation_list_buffer` | K × u32 = 2 KB | HOST_VISIBLE \| HOST_COHERENT | CPU writes candidate tile-idx values |
| `cdf53_escalation_count_buffer` | u32 = 4 B | HOST_VISIBLE \| HOST_COHERENT | CPU writes per-frame count |
| `cdf53_escalation_coefficients_buffer` | K × 3072 × 4 = 6 MB | DEVICE_LOCAL \| HOST_VISIBLE | Forward output; CPU reads per slot for encode_passes |
| `cdf53_forward_l{1,2,3}_escalation_descriptor_set` | — | — | Same layout as the dirty descriptor sets, bound to escalation buffers at the same binding slots |

`K = 512` (compile-time constant). Memory ceiling per session = 6 MB. Multi-tenant 10 sessions = 60 MB. Acceptable for desktop server budget.

### 4.5 New helper in `gpu_pipeline/frame.rs`

```rust
unsafe fn run_cdf53_forward_escalation_stages(
    &self,
    cmd: vk::CommandBuffer,
    count: u32,
) -> Result<(), Box<dyn std::error::Error>>;
```

Mirrors the existing `run_cdf53_forward_l{1,2,3}_stage` chain:
- Pipeline barrier (escalation_list buffer → SHADER_READ).
- Stage L1: bind escalation descriptor set, `cmd_dispatch(cmd, count, 1, 1)` (CPU-known count, no indirect).
- Pipeline barrier L1 → L2 (escalation_coefficients_buffer → SHADER_READ | SHADER_WRITE).
- Stage L2: same.
- Pipeline barrier L2 → L3.
- Stage L3: same.
- Pipeline barrier L3 → HOST_READ on escalation_coefficients_buffer.

### 4.6 io_bridge changes

After the existing Phase B Cdf53 block (`io_bridge.rs:1427+`), add:

```text
1. Skip if !cdf53_enabled || !caps.supports_cdf53.
2. candidates = escalation::detect_escalation_candidates(&self.metrics_tracker, K).
3. If candidates.is_empty(): skip.
4. Write candidates into escalation_list_buffer (host-coherent memcpy);
   write count into escalation_count_buffer.
5. Call gpu_frame_processor.run_cdf53_forward_escalation_stages(cmd, count).
6. After fence (existing fence covers all GPU work in the encoder), iterate
   candidates again. For each tile-idx at slot s in [0..count):
     a. Read coefficients from cdf53_escalation_coefficients_ptr + s * 3072.
     b. Cast i32 → i16; call cdf53::encode_passes(coeffs_i16).
     c. gen = scheduler.bump_generation(tile_x, tile_y).
     d. scheduler.enqueue_refinement(tile_x, tile_y, gen, passes).
     e. metrics_tracker.get_mut(...).codec_state = Cdf53 { passes_sent: 0, max_passes: 14 }.
     f. metrics_tracker.get_mut(...).already_escalated_this_gen = true.
7. Emit one cdf53.emit log line per pass (existing pattern), so e2e tests can verify.
```

Encode_passes CPU cost: K=512 × ~10 µs = ~5 ms/frame worst case. Rayon-parallelize if measurements show it's a bottleneck (Phase B already uses rayon for the dirty path).

### 4.7 PixelPerfect transition

New method on `Scheduler`:

```rust
/// Returns true iff all `max_passes` passes for the given (tile, gen) have been ACKed.
/// O(1) lookup against the per-(tile, gen) ACK counter the scheduler already tracks.
pub fn tile_fully_acked(&self, tile_x: u8, tile_y: u8, gen: u8, max_passes: u8) -> bool;
```

In io_bridge.process_frame_gpu, after the dirty + escalation Phase B blocks, sweep `metrics_tracker` once more for tiles whose `codec_state == Cdf53{passes_sent, max_passes}` with `passes_sent == max_passes` (or just check `scheduler.tile_fully_acked` for all current Cdf53 tiles); transition those to `CodecState::PixelPerfect`. Cost: O(active-cdf53-tiles) — typically dozens, not thousands.

### 4.8 Cancel-on-content-change

Already implemented in the scheduler:
- `Scheduler::bump_generation` supersedes pending passes for old gens (per `feedback_quic_congestion_tiles.md`).
- `Scheduler::bump_generation_collecting` returns the superseded work (already in tree at `scheduler.rs:241`) — useful for scheduler-level unit tests that assert "all old-gen pending work is returned".

No new server code expected for the cancel semantics itself. The new `e2e_refinement_cancel` exercises it end-to-end via the diagnostic snapshot API in §6.2.

### 4.9 Classifier change

In `classify_tile`:
- Add a single early-out before Rule 1: `if prev == CodecState::PixelPerfect && idle => return Skip` (semantically identical to current behavior, but makes the lifecycle explicit). Tiles that are PixelPerfect and become dirty fall through to the normal rules, which is correct: the new dirty frame's content differs from what we already sent, so the tile re-classifies.
- No other classifier changes.

## 5. Test-pattern extension: `--mode-switch-cycle SECS`

`ghostframe-test-pattern/src/mode_switch.rs` static half replaces the single-color paint with three horizontal stripes:

```
┌───────────────────────────────────────────────────────────┐
│   STRIPE 1: SOLID (top third, #204080)                   │  → Solid
├───────────────────────────────────────────────────────────┤
│   STRIPE 2: PalRle (middle third)                         │  → PalRle
│   ~8-color repeating pattern of 32px-wide vertical bars   │     (≤16 colors)
├───────────────────────────────────────────────────────────┤
│   STRIPE 3: Cdf53 (bottom third)                          │  → Cdf53
│   diagonal RGB gradient per gradient.rs formula           │     (high-color)
└───────────────────────────────────────────────────────────┘
```

Motion half: unchanged (shifting noise bands → forces H264 full-frame).

Implementation in `mode_switch.rs::run`:
- Static-paint becomes three `poly_fill_rectangle` / `put_image` calls (one per stripe).
- Existing motion-half code untouched.

## 6. New e2e tests

### 6.1 `e2e_progressive_refinement`

```text
Setup: setup_e2e_webgpu_gpu_with_env("--mode-switch-cycle 3",
                                      &[("GHOSTFRAME_ENABLE_CDF53", "1")])

Timeline (one cycle, skip cycle 0 for startup settle):
  t=0       motion phase (3 s)                       SSIM = 0.92-0.95 (H264 lossy)
  t=3 s     mode-flip → static phase begins
  t=3.0 s   sample 1: post-flip burst                SSIM = mix
  t=3.5 s   sample 2: refinement in progress
  t=4.0 s   sample 3
  t=4.5 s   sample 4
  t=5.0 s   sample 5
  t=5.5 s   sample 6
  t=6.0 s   sample 7: end of static phase            SSIM ≥ 0.999

Assertions on cycle-1 static-phase samples (3 through 7):
  - monotonic_non_decreasing(ssim, jitter_eps=0.01)
  - final_ssim >= 0.999

Diagnostics on failure: dump table of (timestamp_ms, ssim_per_stripe,
codec_emission_counts, escalation_count); eprintln failing-sample
per-tile deltas via existing image-diff helpers.
```

SSIM helper: existing `helpers::assert_ssim_against_golden`. The golden for the static phase is generated by `cdf53::forward + inverse` on the host (byte-exact reference) and checked into `ghostframe-e2e/tests/e2e/golden/`; first-run capture via the existing `GHOSTFRAME_BLESS_GOLDENS=1` env var that `assert_ssim_against_golden` already supports.

### 6.2 `e2e_refinement_cancel`

Test design relies on the cyclic structure: at the static→motion boundary inside cycle 1, escalation passes for cycle-1 static-half tiles may still be in flight. The test captures scheduler state just before the boundary, waits past it, then verifies all old-gen pending passes are gone.

```text
Setup: setup_e2e_webgpu_gpu_with_env("--mode-switch-cycle 1",  // tight cycle
                                      &[("GHOSTFRAME_ENABLE_CDF53", "1"),
                                        ("GHOSTFRAME_CDF53_DIAG", "1")])  // expose scheduler snapshot

Timeline (cycle 1):
  t=0..1 s  motion (cycle 0)
  t=1..2 s  static (cycle 0)
  t=2..3 s  motion (cycle 1)
  t=3..4 s  static (cycle 1): escalation fires, passes in flight
  t=3.6 s   snapshot_before = scheduler.pending_refinement_snapshot()
            // expect: many (tile, gen=N) entries with passes_remaining > 0
  t=4.0 s   motion starts (cycle 2): bump_generation for affected tiles
  t=4.3 s   snapshot_after = scheduler.pending_refinement_snapshot()
            // assert: for every (tile, gen=N) in snapshot_before with
            //         passes_remaining > 0, no entry with that same gen
            //         remains in snapshot_after (either drained or canceled)

New diagnostic API (cdf53-diag feature):
  Scheduler::pending_refinement_snapshot(&self)
      -> Vec<(tile_x, tile_y, gen, passes_remaining)>
```

The `cdf53-diag` feature flag already exists (added in M3.3b commit). Extending it to cover the scheduler snapshot is consistent.

### 6.3 Tightened `e2e_mode_switch`

Current assertions stay (tile_seen, frame_seen, tile_present_phase, h264_active_phases ≥ 2). Add:

1. Enable `GHOSTFRAME_ENABLE_CDF53=1` in test setup. Without this, escalation doesn't fire.
2. Compute per-phase dominance: `frame_dominant` iff `frame ≥ 5 × tile`; `tile_dominant` iff `tile ≥ 5 × frame`; else `mixed`.
3. Walk the phase sequence and count adjacent dominance flips: `Frame→Tile` (frame_dominant followed by tile_dominant), `Tile→Frame` (reverse).
4. Assert: **≥2 Frame→Tile flips AND ≥1 Tile→Frame flip**. Per `project_m33_static_refinement.md`: this replaces the indirect "at least 2 H264-active phases" inference; with refinement emitting in static halves, the flips are now directly observable.

## 7. Risks and edge cases

| Risk | Mitigation |
|---|---|
| 6 MB extra GPU memory per session | K=512 sized for typical desktop budget. Could lower K for embedded targets. Configurable as a future enhancement. |
| Mode-flip burst frame: up to K escalation candidates at once, ~5 ms serial CPU encode_passes | Rayon-parallelize encode_passes (existing pattern in dirty Phase B); 8+ cores → ~700 µs. |
| Escalation list timing: CPU must write before second-dispatch's barrier | Host-coherent writeBuffer is ordered before the next submit (same guarantee the M3.3b client integrate clear exploits). |
| `already_escalated_this_gen` lifetime: if not reset on bump_generation, escalation never re-fires after re-dirty | Reset inside `Scheduler::bump_generation()` (callback to metrics_tracker) or in io_bridge wherever bump_generation is called. Pick during impl review; explicitly checked by `e2e_progressive_refinement` (cycle 1's static phase reaches PixelPerfect, cycle 2's motion bumps gen, cycle 2's static escalates again). |
| SSIM monotonicity jitter from H.264 decoder sub-pixel rounding | Allow ±0.01 jitter per step in the monotonic check; raise to ±0.02 if flaky. |
| `e2e_refinement_cancel` timing depends on the static→motion flip landing during refinement | Use shorter cycle (1 s) for the cancel test; the 3 s cycle is for progressive_refinement. K=512 with refinement_bandwidth_fraction=0.2 means refinement of 72 tiles per stripe takes ~6 frames — comfortably inside a 1 s window. |
| Stripe-boundary tiles classify as PalRle (mixed colors) | Treated as ordinary PalRle escalation; no special handling. |
| First static-after-startup phase: H264 may not be warm yet | Skip cycle 0 in both new tests; sample cycle 1+. |

## 8. Acceptance criteria

This work is complete when:

1. `e2e_progressive_refinement` passes 3 consecutive runs.
2. `e2e_refinement_cancel` passes 3 consecutive runs.
3. `e2e_mode_switch` passes with the tightened assertions.
4. All other existing cdf53 e2e tests still pass.
5. 304-test ghostframe-lib unit suite still passes (with and without `cdf53-diag` feature).
6. New unit tests for `escalation::detect_escalation_candidates` pass.
7. New unit tests for `Scheduler::tile_fully_acked` and the cancel-on-bump_generation behavior pass.

## 9. Implementation order (high-level)

1. `tile/escalation.rs` + unit tests for the pure predicate.
2. `TileMetrics::already_escalated_this_gen` field + `Scheduler::bump_generation` reset hook + unit tests.
3. `Scheduler::tile_fully_acked` + unit tests.
4. `Scheduler::pending_refinement_snapshot` (gated behind `cdf53-diag`) + unit test.
5. GpuFrameProcessor: new escalation buffers + descriptor sets + `run_cdf53_forward_escalation_stages` helper.
6. io_bridge: sweep + escalation list write + dispatch invocation + post-fence Phase B + PixelPerfect transition sweep.
7. `mode_switch.rs` static-half three-stripe paint.
8. `e2e_progressive_refinement` test.
9. `e2e_refinement_cancel` test.
10. Tighten `e2e_mode_switch`.
11. Verification: full cdf53 e2e suite + lib unit tests (with and without `cdf53-diag`). Three consecutive runs of the two new acceptance tests.

Each step is independently mergeable; the implementation plan can sequence them across multiple commits.
